## 1. 两层存储（实测，已落地）

对手的记录形状（01 号报告 §0 + 02 号报告）：

```
profile 记录
├─ 平铺列    name / group_id / ua / canvas / webgl / timezone / fonts / webrtc / ...
└─ fingerprint_config  TEXT  ← JSON.stringify 后存，只有部分维度进这里
```

我们照做，不改成「全平铺」也不改成「全 JSON」：

| 存储方式 | 字段 | 说明 |
|---|---|---|
| 平铺标量列 | 绝大多数（UA、时区、开关、数值） | 查询/迁移友好 |
| csv 列 | `profile_tag_ids` `repeat_config` `app_ids` | 对齐对方 `join(",")` 的行为 |
| 独立 JSON 列 | `open_urls` `tabs` `language` `fonts` `blacklist` `whitelist` `browser_kernel_config` `user_proxy_config` … | URL/规则里可能含逗号，csv 会损坏数据 |
| `fingerprint_config` | `webgl_config` `client_hints` `mac_address_config` `media_devices_num` `media_devices_config` `media_devices_config_v2` | 结构化指纹对象，写入时 JSON.stringify |

**推测标注**：只有 6 个键进 `fingerprint_config` 是我们的判断。拆解只证实了「存在这一列」和「webgl_config 在里面」，
其余键「原样透传」（02 号报告 §13.3）→ 以后拿到更细证据，改 `reference/overrides.mjs` 的 `STORAGE` 再重跑
`tools/gen-schema.mjs` 即可，不用手改 DDL。

生成链：

```
adspower-reverse/8.9.23/fingerprint-fields.json   ← 拆解产物（139 条原始记录）
  + packages/profile/reference/overrides.mjs      ← 我们的判断（存储/覆盖度/默认值）
      ↓ node tools/gen-schema.mjs
  packages/profile/src/fields.generated.json      ← 138 个唯一字段，带 coverage 标注
  packages/profile/src/schema.sql                 ← DDL
```

字段数对账：原始 139 条里 `virtual_camera` 在 `browser` 和 `privacy_switches` 重复出现，去重后 **138**。
分组条数与 CEO 转述的 21/14/9/12/2/8/6/12/5/21/24 略有出入（我们数出来 22/14/9/11/2/8/6/13/5/22/26），
差异在 `identity`(+1)、`noise_quad`(−1，`webgl_config` 计为 1 个字段而不是展开子键)、`network`(+1)、
`privacy_switches`(+1)、`launch_and_cache`(+2)。不影响建表，记录在此备查。

## 2. 值域：官方文档 vs 静态拆解，冲突取并集

拆解手拿到了 AdsPower 随包的官方 skill 文档，默认值以它为准；内部实现支持更多值的地方取并集：

| 字段 | 静态拆解 | 官方文档 | 我们的做法 |
|---|---|---|---|
| `webgl` | `0｜2` | `0｜2｜3`（3=随机） | 收 `0/2/3` |
| `hardware_concurrency` | 2,3,4,6,8,10,12,16,20,24 | 2,4,6,8,16,32 | 并集 + `default` |
| `device_memory` | 2,4,6,8 | 2,4,6,8 | 两种写法都收 |
| `mac_address_config.model` | `0｜2` | `0｜1｜2`（1=match） | 收 `0/1/2` |
| `webgpu.webgpu_switch` | 只见 `"1"` | `0`(关)/`1`(WebGL 匹配)/`2`(真实) | 收 `0/1/2` |
| `do_not_track` | `true｜false` | 还有 `default` | 三个都收 |
| `allow_scan_ports` | csv 字符串 | 数组 `["4000"]` | 两种都收，内部存 csv |
| `screen_resolution` | `none｜W_H` | 还有 `random` | 三个都收 |
| `accuracy` | 默认 1000 | 10–5000 整数 | 卡 10–5000 整数 |

**默认值来源已改判**：官方文档说 `canvas`/`webgl_image`/`audio` 默认就是 `1`（加噪），`webrtc` 默认 `disabled`，
`flash` 默认 `block` —— 我 v0.2 里按静态推断写的 `0`/`local`/`allow` 是错的，已全部改掉。
`fields.generated.json` 里每个默认值带 `defaultSource: official | guessed`。

## 3. 校验器（已实现，10 条测试绿）

`packages/profile/src/validate.js`：

- **单字段值域**：枚举、数值范围、`device_scale ∈ (0,2.1)`、`accuracy ∈ [10,5000]` 整数、
  经纬度 6 位、`cookie` 必须是 JSON 数组字符串（错就 `cookie must be list string`）、时区必须是真 IANA 名。
- **一致性检查**（这是产品能不能活的核心）：
  1. UA 里的平台 token ↔ `platform`（Windows NT ↔ Win32）
  2. `client_hints.platform` ↔ `platform`
  3. UA 里 `Chrome/131` ↔ `client_hints.ua_full_version`
  4. `webgl="2"` 必须带 vendor/renderer
  5. 桌面平台报 SwiftShader → 高危
  6. `language` ↔ `timezone` 国家粗匹配（`automatic_timezone=1` 且用户没显式给时区时不报，避免噪音）
  7. 高核心数 + 低内存、24 核配 2G 这类不像真机的组合
  8. `webrtc=proxy/forward` 但没绑代理
- 显式给的值才报警告，默认值不参与冲突判断（`explicit` 集合）。

跑法（沙箱里 `node --test` 会 spawn 子进程被拒，直接跑文件）：

```
node packages/profile/test/schema.test.mjs
```

## 4. 启动与隔离（照 03 号报告）

| 决策 | 对手做法 | 我们的做法 |
|---|---|---|
| profile 目录 | agent 不下发 `--user-data-dir`，靠约定 `<cacheRoot>/<fbccId>_<inviteCode>`，由 `SunBrowser.exe` 翻译 | **目录由系统算**：`<dataRoot>/profiles/<profile_no>_<id前8位>`，**不接受用户覆盖**；用户传 `--user-data-dir` 直接丢弃 |
| 调试端口 | `--remote-debugging-port=0` + 读 `DevToolsActivePort` 回读 | 照做。固定端口在多开时会互相抢，随机端口 + 文件回读才稳 |
| 用户参数 | 白名单：`--load-extension` / `--disable-features` / `--proxy-bypass-list` / `--enable-features` / `--disable-blink-features` / `--enable-blink-features` | 同白名单；保护名单 `--user-data-dir` `--lang` `--profile` `--remote-debugging-port` 一律丢弃 |
| 指纹参数载体 | `--extended-parameters=<base64(JSON)>` | **不学**。理由见 §6 |

## 5. 字段 → 参数映射基线（不另起一套）

直接沿用 03 号报告 §3.2 的表，落到我们这边是「字段 → 我们怎么让它生效」：

| 字段 | 我们的手段 | 覆盖度 |
|---|---|---|
| `ua` / `client_hints` | `Emulation.setUserAgentOverride`（带 `userAgentMetadata`） | full |
| `timezone` | `Emulation.setTimezoneOverride` + 进程 `TZ` | full |
| `language` / `page_language` | `Emulation.setLocaleOverride` + `--lang` | full |
| `longitude`/`latitude`/`accuracy`/`location` | `Emulation.setGeolocationOverride` + `Browser.grantPermissions` | full |
| `screen_resolution` / `device_scale` | `--window-size` + `Emulation.setDeviceMetricsOverride` | full |
| `webrtc` | 启动参数 `--force-webrtc-ip-handling-policy` / `--webrtc-ip-handling-policy` | full |
| `canvas`/`audio`/`webgl_image`/`client_rects` + 各自 `_id` 种子 | `Page.addScriptToEvaluateOnNewDocument` 注入，种子由 `fp_seed` 派生 | partial |
| `webgl` / `webgl_config` | 注入 `getParameter` 覆写 | partial |
| `hardware_concurrency`/`device_memory` | 注入 `navigator` 属性 | full |
| `fonts` / `disabled_fonts` | 不动（明确标黄） | none |
| `user_proxy_config` | 启动参数 `--proxy-server` + `Fetch.authRequired` | full |
| `ban_dev_tools` | `--disable-dev-tools` 不行 → 不启 `--remote-debugging-pipe` 之外的接口 + UI 层拦 | full |

`coverage` 三档的含义写在 `docs/00-技术方案.md §2.2`，`fields.generated.json` 里逐字段标注（36 full / 36 partial / 6 none / 60 n/a）。

## 6. 我们不学的三个「可疑特征」

04 号报告 §5 列了对手自己的破绽。我们没理由继承：

1. **命令行塞 base64 指纹束**（`--extended-parameters`）。任何本机进程看命令行就能读出全部指纹，且原版 Chrome 没有这个开关。
   我们走 CDP，不放自定义命令行。
2. **profile 目录里放 `md5(...)` 无名文件**。原版 Chrome 的目录结构有固定名单，多出来的东西一眼可见。
   我们的静态配置直接进 `Local State`/`Preferences`/启动参数，不落怪文件。
3. **`SunBrowserPolicys` 这种品牌化策略名**。我们用中性命名，且不写进二进制字符串。

## 7. DynamicConfig：设计上可分三层，**当前只实现启动时生效**

对手用 `md5(fid+"_webrtc")` 文件实现「换 IP 后原地改时区/地理/WebRTC 地址，不重启」（04 号报告 §3）。
这项能力我们**没有实现**，如实记录设计意图与现状：

- 现状：`update` 在环境运行中直接拒绝（`profile is running, stop it before update`）；
  `Emulation.setTimezoneOverride` / `setGeolocationOverride` / `setLocaleOverride` 只在页面会话装配时调用，
  也就是**启动时（以及之后新开的页面）生效**，没有「运行中重配」的 API 或 UI 入口。
- 设计上（未落地）：时区 / 地理 / 语言可以按「对已连接 target 重发一遍」实现；代理出口必须重启（进程级参数）。

| 维度 | 设计上能否不重启 | 当前实现 |
|---|---|---|
| 时区 | 可以（重发 override） | 启动/新页面装配时生效；运行中改环境被拒 |
| 地理坐标 | 可以 | 同上 |
| 语言 | 可以（新页面生效，已开页面需刷新） | 同上 |
| 代理出口 / WebRTC 地址 | 不能（进程级参数） | 改代理需停止再启动 |

对我们的额外好处：CDP 改时区/地理不留文件、不改 mtime，比对手的 `DynamicConfig` 文件干净。
