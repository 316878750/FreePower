# 15 · 应用中心与扩展管理（0.4.3 ①）

对手这块的能力叫「应用中心」/「扩展管理」：从它的云端商店装扩展，再决定每个环境加载哪些。
我们没有云端商店（也不转发别人的分发），所以这一版做的是**本地的扩展库 + 环境级勾选**。

本文记四件事：怎么建模、文件怎么放、怎么真的加载到内核里、以及**哪些是和对手不一样的**。

---

## 一、结论先行：两条来自拆解的硬事实

来自 `adspower-reverse/8.9.23/27b-扩展库字段核对与更正.md`：

1. **扩展文件全局共享一份**，按扩展 id 一个目录。不是每个环境一份副本 ——
   27 号报告里那条「每环境一份副本」已被 27b 用磁盘证据推翻
   （`cache/<profile>/extensionCenter` 在 100 个 profile 里一个都没有；真实命令行里
   `--load-extension` 0 命中；扩展靠 `Secure Preferences` 的 `.extensions.settings[<id>].path`
   指向共享目录）。
2. **启用状态是环境级的**：环境对象上有 `appIds`（数组）+ `sysAppCateId`。
   对手 `sysAppCateId==="0"` 的语义是「不过滤、库内 `status=1` 全加载」，
   **我们不用这个隐式语义**，改成显式勾选：勾了才加载，界面上看得见。

所以本产品的模型是：**共享文件 + 环境级勾选**，两件事分开存。

---

## 二、数据模型

两张新表（`tools/gen-schema.mjs` 生成，别手改 `schema.sql`）：

```sql
CREATE TABLE extensions (          -- 扩展库
  id TEXT PRIMARY KEY,             -- 库内编号（数字串），也是 <数据根>/ext_env/<id> 的目录名
  unique_id TEXT,                  -- Chrome 扩展 ID（32 位 a–p）
  name TEXT NOT NULL,
  version TEXT,
  description TEXT,
  manifest_version INTEGER,
  path TEXT NOT NULL,              -- 相对数据根：ext_env/<id>
  status TEXT NOT NULL DEFAULT '1',-- '1' 启用 / '0' 停用（库级）
  source TEXT, files INTEGER, bytes INTEGER, sha256 TEXT,
  created_at TEXT NOT NULL, updated_at TEXT
);

CREATE TABLE profile_extensions (  -- 环境 ↔ 扩展（显式勾选）
  profile_id TEXT NOT NULL,
  ext_id TEXT NOT NULL,
  created_at TEXT NOT NULL,
  PRIMARY KEY (profile_id, ext_id)
);
```

- `profile_extensions` **没有建外键**，跟 `profile_tags` 一致：环境是软删除（进回收站），
  外键级联会把恢复回来的环境搞成「没勾任何扩展」的壳。
- `sha256` 是**目录内容指纹**（`<相对路径>\0<文件 sha256>` 逐行排序后再 sha256），
  用来做导入去重：同一个包导两次不占两份盘。
- 没有 `ext_env/record` 那种 JSON 索引文件。对手两边（`ext_env/record` 与 `ext/record`）
  `version` 不一致、谁是权威连拆解都定不下来（27b §5.3），我们不让库里出现第二份事实源。

## 三、文件布局

```
<数据根>/
  ext_env/
    <id>/                 ← 每个扩展一个目录，全局共享
      manifest.json
      ...
    .import-<random>/     ← 导入中的临时目录，成功后 rename 成 <id>，失败整个删掉
```

- 导入 = **复制**（源目录留着），先复制/解压到 `.import-*`，校验 manifest、算指纹，
  最后 `rename` 成 `<id>`。「要么整份，要么没有」。
- `.crx` 是 Chrome 的签名包，**不解**：报错让用户先解压成目录（解 CRX 要处理签名与
  版本化容器，为一个小众入口引一套解析不值得）。
- zip 用现成的 `src/kernel/zip.js`（带 CRC 校验、路径穿越拦截、解压总量上限），
  允许「zip 里套一层目录」—— 那是打包工具的默认行为，不剥这一层用户会一脸问号。

## 四、怎么真的加载进内核（这一段是本版最重要的改动）

### 4.1 `--load-extension` 已经没用了（实测）

2026-11-14，真内核 **Google Chrome 157.0.8103.78**，四组隔离对照（每次全新 `--user-data-dir`）：

| 组 | 参数 | 扩展装进来了吗 |
|---|---|---|
| A | `--load-extension` + `--disable-extensions-except` | ❌ |
| B | A + `--disable-features=DisableLoadExtensionCommandLineSwitch` | ❌ |
| C | 只 `--load-extension` + 关特性开关 | ❌ |
| D | B + `--enable-unsafe-extension-debugging` | ❌ |

读数：`Target.getTargets` 里没有该扩展的 service_worker，
`Default/Preferences` 的 `extensions.settings` 也没有条目。

**所以旧实现（白名单放行 + 自动补特性开关）是「静默空转」**：参数进了命令行、
`launch_args.applied` 里也写着成功，实际什么也没发生。本版把它挪进**保护名单**，
用户再写 `--load-extension` 会拿到明确拒绝，并被告知改用应用中心。

### 4.2 能用的路：CDP `Extensions.loadUnpacked`

```
Extensions.loadUnpacked { path } → { id: "ejlcoabbkkleleoeihhipbeaicabpnfa" }
```

实测结论：

- **不需要** `--enable-unsafe-extension-debugging`（带不带返回同一个 id），
  所以产品命令行一个字节都没为它改。
- **真生效**：自造 MV3 扩展 + content script，页面 `documentElement` 上读到了它写的属性。
- **一次装多个**可以（两个扩展的 service_worker 同时在线）。
- **不持久**：同一个 user-data-dir 重启后不调 `loadUnpacked` 扩展就不在。
  这正好是我们要的语义 —— **每次启动按环境勾选加载**，取消勾选下次启动自然就没了，
  不用像对手那样去改 `Secure Preferences` 的 `.extensions.settings[].path`。
- 什么时候装：**`injectAndOpen` 之前**。content script 只对「扩展加载之后创建的文档」生效；
  先开页面再装扩展，那批页面就没有扩展的注入（实测）。

### 4.3 扩展 ID 的算法（复算出来了）

Chrome 的 unpacked 扩展 ID = **加载路径字符串按 UTF-16LE 编码**做 sha256，取前 16 字节 hex，
再把 `0-9a-f` 映射成 `a-p`。两种目录实测都对上 CDP 返回的真值。

推论（很要紧）：**ID 是路径的函数**。

- `<数据根>/ext_env/<id>` 这个目录名一旦创建就不许改（改名 = 换扩展 ID）；
- 数据目录搬家（换盘、换便携路径）会让所有扩展换 ID，扩展自己的 localStorage 也跟着分家；
- 启动时会把 CDP 报回来的 ID 与导入时推算的比一次，**不一致就告警**（目录被搬过/改过名）。

## 五、本地 API

六条，都在 `/api/v2/app/*`，鉴权/限流/错误码与其它路由一致（错误码用 `100002` 参数非法、
`100001` 找不到，不用 `-1` 糊过去）：

| 路由 | 做什么 |
|---|---|
| `GET/POST /api/v2/app/list` | 库列表；每条带 `used_by`（被几个环境勾着） |
| `POST /api/v2/app/import` | `{path, name?, status?}`；`path` 是**本机路径**（目录或 zip）。回 `duplicate` 与 `warnings`（MV2 告警等） |
| `POST /api/v2/app/update` | `{id, status?, name?}` |
| `POST /api/v2/app/delete` | `{ids: []}`；回 `deleted` / `skipped` / `running_affected` |
| `GET/POST /api/v2/app/profile` | `{profile_id}` → 这个环境勾了哪些（带 `enabled`） |
| `POST /api/v2/app/profile/set` | `{profile_id, ext_ids: []}` 全量替换；回 `restart_required` |

`running_affected` / `restart_required` 是为了**不假装立刻生效**：环境正在跑的时候改扩展，
下一句就得说「重启才生效」。

启动结果（`/start`、`/active`、`local-active`）多一个 `extensions` 字段：

```json
{ "requested": 2,
  "loaded": [{ "ext_id": "1000001", "chrome_id": "gffj…", "name": "FP One" }],
  "failed": [] }
```

一个都没勾时是 `null`（不是空对象）。加载失败的会同时进 `warnings`，
**目录被删掉**的在启动一开始就进 warnings 并跳过 —— 沉默的缺口比报错难查得多。

## 六、界面

- 侧栏「常用」下新增 **应用中心**：列表（名字/版本/状态/被几个环境用/落盘目录/文件数）、
  启用停用、改名、删除、导入。
- 环境编辑页「基本信息」分栏里新增 **扩展** 勾选框（只列库级启用的），
  旁边一个「打开应用中心 →」的入口。
- 删除扩展时会明确说「有 N 个环境勾着它，删除后这些环境重启时就没有这个扩展了」，
  并二次确认。
- 导入弹窗里写清楚：**收的是本机路径，不是上传**；`.crx` 要先解压。

## 七、和对手不一样的地方（如实列，别当成漏了）

| 对手 | FreePower |
|---|---|
| 云端应用商店，登录后一键装 | 只能**本地导入**（目录 / zip）。不转发别人的分发 |
| `sysAppCateId==="0"` → 库内启用全加载 | 只认显式勾选，没有隐式全量 |
| 靠 `Secure Preferences` 的 `path` 指向共享目录 | 靠 CDP `Extensions.loadUnpacked` 每次启动装 |
| `ext_env/record` 单行 JSON 索引 | 不写索引文件，库表是唯一事实源 |
| 扩展更新（`path` 新版 / `used_path` 旧版并存） | **暂不支持更新**，要换版本就删了重导（目录名跟着 id 变，扩展存储会重置 —— 这一条在 README 里写明） |
| Chrome 商店的 MV2 老扩展还能用 | Chrome 137+ 已不支持 MV2；导入 MV2 会导入成功但**明确告警**，加载时可能被内核拒绝 |

## 八、判据

- `test/apps.test.mjs`（A 层，不起内核）：导入/去重/manifest 解析/MV2 告警、勾选全量替换、
  停用不加载、目录缺失告知、删除清关系清目录、回收站保留勾选、六条路由的形状与错误码、
  复制环境带勾选、以及两条静态约束（`--load-extension` 已进保护名单；
  加载发生在 `injectAndOpen` 之前）。
- `test/apps-kernel.test.mjs`（B 层，真内核）：勾一个 → 启动 → 页面被 content script 标记、
  SW 在线、`chrome_id` 等于导入时推算的；勾两个 → 两个都活；取消勾选 → 重启 → 标记消失；
  库级停用 → 不加载；目录被删 → 启动不崩且告警点名。
