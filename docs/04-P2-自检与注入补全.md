# P2 交付：自检页 + 注入补全

> ⚠️ 本文是 P2 阶段的记录，描述的是当时状态；当前能力以 [README](../README.md) 为准。

> 目标（CEO 定的顺序）：先让每个环境启动后能跑一次可读自检，再补 canvas / audio / webgl_image / client_rects 的确定性噪声、media devices、硬件参数。字体只做「声明存在」。PAC 明确拒绝。

---

## 一、做了什么

### 1. 自检页（每个环境启动后自动跑一次）

- 启动流程里，内核起来、注入装配完成后，开一张**环境自己的页面**跑探针（`src/selfcheck/probe.js`），页面内真实调用各 API，不在主进程模拟——只有这样才能证明 CDP 注入真的生效。
- 探针页走 `http://127.0.0.1:<临时端口>` 的**安全上下文**（`127.0.0.1` 是 secure context）：`navigator.userAgentData` 与 `navigator.mediaDevices` 只在安全上下文存在，`about:blank` 上验证不了 UA-CH / 媒体设备。
- 本地只开一个只服务探针页的 HTTP 服务，跑完即关（`src/selfcheck/origin.js`）；Chrome 的 keep-alive 会让 `server.close()` 挂住，所以用 `closeAllConnections()` + `Connection: close` + 1s 兜底。（P7 起同一服务还提供 `/fp-worker.js`、`/fp-sw.js`、`/fp-worklet.js` 三个路由，供 worker 与 AudioWorklet 探针用。）
- 报告 19 项（P2 当时 15 项；P7 增加三个 realm + AudioWorklet，见 [P7 文档](08-P7-双Realm与AudioWorklet.md)）：UA、UA-CH、platform、语言、时区、屏幕、硬件参数、WebGL、canvas、webgl_image、audio、client_rects、字体、媒体设备、WebRTC，以及专用 Worker / SharedWorker / ServiceWorker（双 Realm）与 AudioWorklet 作用域。
- 每项标 `pass` / `warn` / `fail`，覆盖度**直接取字段表的 `coverage`**（35 项 full / 37 项 partial / 6 项 none），不另造一套口径：
  - 值不匹配 → `fail`
  - 匹配 + 覆盖度 `full` → `pass`
  - 匹配 + 覆盖度 `partial` → `warn`
  - 覆盖度 `none`（字体）→ `warn`，写明「只声明不伪装」
- 只在没绑代理 / 代理允许 loopback 时能跑安全上下文；远程代理下回落到 `about:blank`，报告里如实写「UA-CH / 媒体设备本次未验证」，**不假装通过**。
- 落盘 `data/selfchecks/<profile_id>.json`，保留最近 4 份，同内核历史报告用来判断跨重启一致性。
- `browser/start` 响应带摘要（`selfcheck` 字段，超集不破坏契约），完整报告走接口：
  - `GET /api/v1/browser/selfcheck?user_id=`
  - `GET /api/v2/browser-profile/selfcheck?profile_id=&rerun=1`
  - `GET /api/v2/browser-profile/selfcheck?profile_id=&format=html`（本地渲染的深色报告页，无外链、内容全转义）
- 自检默认开启，`FREEPOWER_SELFCHECK=0` 可关，超时 `FREEPOWER_SELFCHECK_TIMEOUT_MS`（默认 25000）。失败不挡启动，只出 `soft` 告警。

### 2. 四维噪声确定性（种子入库，跨重启一致）

- `src/fingerprint/seeds.js`：从环境种子派生四个独立子种子 `canvas=1 / webgl_image=2 / audio=3 / client_rects=4`，建环境时入库；老环境启动前补缺（已有的值不动）。
- `src/kernel/inject.js` 重写：
  - **canvas**：`getImageData` / `toDataURL` / `toBlob` / OffscreenCanvas（`getImageData` + `convertToBlob`），按环境种子做确定性像素扰动。
  - **webgl_image**：`WebGL(2)RenderingContext.readPixels` 返回值扰动；`getParameter(37445/37446)` 覆盖 vendor / renderer。
  - **audio**：`AudioBuffer.getChannelData`（WeakSet 防重复加噪）+ `copyFromChannel`。
  - **client_rects**：`Element.prototype.getBoundingClientRect` 用 `elementKey`（tag|class|text|index|style）派生亚像素偏移，返回新的 `DOMRect`。
- 四个维度各自独立种子：一个维度的噪声不会因为另一维度配置变化而漂移。
- 另加 `--disable-accelerated-2d-canvas`：GPU 2D 光栅化路径在不同进程间会产生不同像素，导致 canvas 哈希跨重启漂移（实测 arc / gradient / rotLine 三项变、rects / text 不变）。固定为软件光栅化后三轮完全一致。代价是 `chrome://gpu` 显示 Software only，已进启动参数保护名单。

### 3. 其余补全

- **media devices**：`MediaDevices.prototype.enumerateDevices` 替换；数量按环境声明，deviceId 用环境种子派生（64 hex，确定性），label 用通用 Windows 设备名。非安全上下文下补一个最小 `navigator.mediaDevices`（fallback），页面可见。
- **hardwareConcurrency / deviceMemory**：接上声明值，高核数统一配 8G 内存（12 核 + 4G 会触发「软冲突」）。
- **字体**：不 patch，只 `document.fonts` 声明存在。JS 改不了 DirectWrite 的字形与宽度度量，伪造比不做更危险。

### 4. PAC：明确拒绝，绝不静默降级

- 建环境 / 改环境带 `full_pac_url` 或 `proxy_type=pac` → `100002 参数非法`，消息写明「不支持 PAC：PAC 可能含 DIRECT 回退，无法保证 fail-closed；请改用固定 HTTP / SOCKS5 代理」。
- 老数据里已有的 PAC（迁移 / 手改库）：启动时直接 `800003`，`reason=pac_unsupported`，**一个内核进程都不拉起**（纵深防御：`buildArgs` 里再拦一次）。

## 三、已知缺陷（照实说）

| # | 项 | 现状 | 影响 |
|---|---|---|---|
| 1 | 字体 | 只声明，不伪装字形与度量 | 字体枚举 / 宽度测量类检测可发现声明与实际不一致 |
| 2 | canvas | 只盖 `getImageData/toDataURL/toBlob/OffscreenCanvas` | WebGPU、`createImageBitmap`、WebGL framebuffer 回读是盲区 |
| 3 | webgl_image | 只扰动 `readPixels` | 真实光栅化结果、GPU 计时仍来自驱动 |
| 4 | audio | 只改 `AudioBuffer` 读出值 | AudioWorklet / 实时音频线程是盲区 |
| 5 | client_rects | 只改 `getBoundingClientRect` | `getClientRects`、Range、布局引擎交叉验证可绕过 |
| 6 | WebGL 参数 | vendor/renderer 对齐，扩展/精度/最大纹理尺寸仍是真实值 | `coverage=partial`，与字段表标注一致 |
| 7 | platform | JS 侧可改，但 CDP 的 `Emulation.setUserAgentOverride` 是权威 | 标 `partial` 不吹成 full |
| 8 | 远程代理下的自检 | loopback 被迫走代理时回落 `about:blank` | UA-CH / 媒体设备本次标「未验证」，不标通过 |
| 9 | 2D canvas 性能 | `--disable-accelerated-2d-canvas` 固定软件光栅化 | 大量 canvas 的页面会慢一些，`chrome://gpu` 显示 Software only |
| 10 | 双 Realm | P2 当时不做 Worker / AudioWorklet 双 Realm 注入；这两种上下文里读到原始指纹 | **P7 已解决**：三类 worker（专用 / Shared / Service）+ 嵌套 worker 都覆盖，AudioWorklet 明确 `none`，见 [P7 文档](08-P7-双Realm与AudioWorklet.md) |
| 11 | PAC | 明确不支持（报错拒绝） | 需要 PAC 的用户无法使用 |
| 12 | `https` 代理 | 不做 TLS-in-TLS | 只支持 HTTP / SOCKS5 |
| 13 | SOCKS5 账号密码 | 内核限制，不做绕过 | 需认证的 SOCKS5 不可用 |

结构性上限照旧：CDP 注入是有天花板的（`pass` 只代表「我们声明的和页面读到的一致」，不等于「不会被检测」）。

## 四、这轮踩到的三个真 bug（都已修，写下来免得再踩）

1. **新建 target 的首个 `about:blank` 文档收不到 `addScriptToEvaluateOnNewDocument`**：`Target.createTarget` 的初始文档在 attach 之前就存在。修法：对我们的内部页用 `ensureInjected()`（`window.__fpInstalled` 不为 true 才 reload）；对用户新开标签延迟 400ms 再确认还是空白页才 reload——早期版本无脑 reload 会把出口探测 / `open_urls` 的导航顶掉，实测三条环境都出现「出口探测页没有内容」。
2. **重启读到旧 `DevToolsActivePort`**：第二次 start 读到上次残留的端口，`fetch failed ECONNREFUSED`。修法：spawn 前删掉 `<user-data-dir>/DevToolsActivePort`。
3. **自检本地 HTTP 服务 close 卡死**：Chrome 保持 keep-alive，`server.close()` 永不回调，`start` 一直不返回。修法：`closeAllConnections()` + `Connection: close` + 1s 兜底。
