关键设计决定：

1. **零运行时依赖**。存储用 Node 24 内置 `node:sqlite`，API 用 `node:http`，CDP 的 WebSocket 自己写。
   理由：内核启动参数是长期演进的，依赖越少越不容易被第三方升级带崩。
2. **页面在「暂停态」注入**：`Target.setAutoAttach({waitForDebuggerOnStart:true})` + `Runtime.runIfWaitingForDebugger`。
   好处是用户运行中 Ctrl+T 开的新标签、页面自己 `window.open` 的窗口都会被同一套注入覆盖，不留裸奔窗口。
3. **指纹是整组换，不是单字段改**：`new-fingerprint` 只换种子，UA/UA-CH/WebGL/屏幕/时区一起重算。
   单改一个字段最容易造出「UA 说 Win11、WebGL 报另一台机器」的高危组合。
4. **Canvas 噪声每次取用前重置 RNG**：同页面连读两次必须一致，否则「两次读不一样」本身就是检测点。
5. **canvas 的 `toDataURL`/`toBlob` 走原始 `getImageData`**：否则噪声会叠两遍，同一个 canvas 的导出和读取对不上。

### 当前实测（受限沙箱内）

```
PASS  /status 形状对齐
PASS  无 key 被拒
PASS  建环境返回 profile_id
PASS  指纹自洽：UA 版本 == 内核大版本 — 156
FAIL  启动返回 code 0 — Chrome 未在 20000ms 内暴露 DevTools 端口
```

**原因不是代码**：DSH 的 Windows 沙箱禁止命名管道，Chrome 的 Mojo IPC 建管道被拒（`mojo\public\cpp\platform\platform_channel.cc:112 Check failed: 0x5`），
crashpad 也随之自终止（`crashpad_client_win.cc:145 crash server failed to launch, self-terminating`）。
Chrome 在进程启动阶段就退出，`DevToolsActivePort` 根本没写出来。

→ **浏览器启动这一段必须在普通终端（非沙箱）跑 `npm run smoke` 才能验证。** 其余 12 项已在沙箱内可验。

## 3. 已知缺陷（按严重度）

| # | 缺陷 | 影响 | 计划 |
|---|---|---|---|
| 1 | Canvas/Audio/WebGL/字体是 JS 注入 | 深度检测站可识别（双 Realm、toString、字体度量交叉验证） | 接受，README 已写明；是否上内核补丁待 CEO 评估 |
| 2 | 字体不伪装 | 字体列表与真实字形一致，但换不了操作系统指纹 | 不做，风险大于收益 |
| 3 | SOCKS5 认证不支持 | 需要账号密码的 SOCKS5 代理用不了 | P3 评估（可能要走本地转发代理） |
| 4 | 代理认证用 `Fetch.enable('*')` | 带账号密码的代理会给所有请求加一跳，页面变慢 | P3 改成仅对 `407` 挑战响应，或本地代理端口 |
| 5 | 内核矩阵还没接 | 只有系统 Chrome 一个版本，无法 pin 118/142/156 多版本 | P1 |
| 6 | 没有一致性校验器 | 目前靠生成器「自洽」，改字段后没有校验兜底 | P1（CEO 已提前） |
| 7 | 没有 UI | 只能走 API | P1 Electron 壳 |
| 8 | `groups` 表不校验外键 | 删分组后环境 `group_id` 悬空（列表仍能显示） | P1 |
| 9 | 内核版本漂移只写日志 | 指纹声明 156、实际内核不同时只 warn，不拦 | P1 一致性校验器里做成硬校验 |
