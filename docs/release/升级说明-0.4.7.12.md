# FreePower 0.4.7.12 升级说明

> 上一版（0.4.7.11）把「投错标签」修掉了，但用户现场仍有一类「同步看着在跑、部分页面没反应」。
> 这一版只做一件事：**把投递链上「Chrome 不报错、页面却没处理」的盲区堵上** ——
> 派发前探活、失败先唤醒、再失败重连重建，实在不行计给人话；
> 同时把同步路径上的死会话报错和受控侧第二遍指纹注入清零。

## 一、先纠正一个错误结论（事实优先）

上一版诊断时假设「Chrome 遮挡会冻结渲染器吞掉 CDP 输入」。本轮实测**推翻了它**：

- 本产品内核启动参数里本来就带 `--disable-features=...,CalculateNativeWinOcclusion,...`
  —— 原生遮挡判定是**关**的。被完全遮挡的受控页 `visibilityState` 依然是 `visible`，
  「冻结渲染器吞输入」这个机制不存在。
- 真正让「部分受控页没反应」的是**几何**：
  ① 会话恢复把页面带回了页底（scrollY 已在底部，滚轮增量无处可去）；
  ② 页面无溢出（`sh == ih`，滚了等于没滚）；
  ③ CDP 窗口 bounds 回读 1600×900，但实际视口有 744 / 780 / 900 三种并存。
- 诊断早期的「0/7 点击全失败」是**测量假红**：探针 `counts()` 只数了 `click` 没数 `trustedClick`。
  修探针后 hit(2)×7 全通。「探针死了」那条判据也修正为：
  **探针死但 href 变了 = 导航成功 = hit**；只有「探针死 AND href 没变」才算真失败。

写清楚这段是为了不再被旧结论带偏：以后排查「页面没动」，先看 `delivery_wake/retry/fail`
和页面 `headroom`（余量），不要先怀疑遮挡。

## 二、修了什么

### 1. 投递链防陈旧（核心）

每条事件派发前对目标会话做**节流探活**（`Runtime.evaluate '1'`，节流 1500ms、超时 1200ms），
失败后按顺序自救，每一步都计数：

| 步骤 | 动作 | 计数 |
| --- | --- | --- |
| 探活失败 | `Page.setWebLifecycleState active` 唤醒后重投 | `delivery_wake` |
| 仍失败 | 会话判定失效（`invalidateSession`），以 `maxAgeMs:0` 强制重连解析目标，重试一次 | `delivery_retry` |
| 仍失败 | `delivery_fail` +1，`windows[].degraded` 写人话，日志 WARN | `delivery_fail` |

`send` 抛「Session with given id not found」这类会话死错走同一条重连路径，不再裸抛。
status 的 `windows[]` 新增 `delivery_wake / delivery_retry / delivery_fail` 三个计数；
同步结束日志带聚合（`唤醒=… 重连=… 投递失败=…`）。

**唤醒计数在验收轮里是 0，这是正常的**：探活针对的是「会话陈旧/死亡」，
「JS 活着但页面在页底/无溢出」这类几何情形本来就不该触发唤醒。
通道本身有效由反向验证证明（见第四节红读数：老实现下这三个字段是 `undefined`，死会话报错 28 处）。

### 2. 死会话报错清零 + 摘掉受控侧第二遍指纹注入

同步运行期内核会对每个新 target 走一遍指纹装配。老实现下这套装配会撞上同步自己创建的
内部 target 和已销毁的会话：

```
hc 覆写失败 Session with given id not found   ← 每个环境 4 处（hc/geo）
```

受控日志里**28 处**这类报错（7 个受控环境 × 4）。本版：

- 内核管理器维护 `internalTargets` 集合，同步创建的内部目标**整套跳过指纹装配**
  （只保留代理认证闸门和 debugger 放行）—— 受控侧零注入这条既定原则现在在装配层也成立；
- 装配过程中会话被销毁时不再当异常刷栈，改记一条 INFO
  （「装配中止：目标在装配期间被销毁（新 target 出现时会重新装配）」）；
- 装配每一步都有会话死守卫，会话死了立即中止，不再往下发。
- 新代码同样跑 7 环境：**0 处**死会话报错。

### 3. diag2 正式判据（`.tmp/e2e/diag2.cjs`）

在真内核（iso2 数据目录、53391 端口、主控最大化 + 7 个受控 1600×900 级联被主控遮挡，
受控各开真站双标签、页面装探针，真实 OS 滚轮/点击打主控）上定义了 **8 条**判据：

1. 探针输入前全存活；
2. 主控捕获正常（事件有增长）；
3. 7/7 受控页 `trustedWheel ≥ 2` 且（`scrollΔ > 0` 或 `headroom < 120` 无余量时只验证送达）；
4. 无越界丢弃；
5. 7/7 受控页 `trustedClick ≥ 1` 或 href 变化（导航成功也算 hit）；
6. status 带 `delivery_wake/retry/fail` 字段；
7. 受控日志本轮 0 处死会话报错；
8. 结束日志含聚合读数。

轮次锁防互踩，任何出口都走收尾汇总。**`sent/errors/alive` 不是通过条件** ——
0.4.7.9 就是 `sent=311 / errors=0` 全绿而用户看不到反应，这条教训进了硬规则。

## 五、已知差异 / 限制（照旧写全）

- **受控视口回读三种值并存（744/780/900）**：越界判定按各自实测 viewport 走；
  CDP 窗口 bounds 回读 1600×900 与实际视口不一致是内核行为，本版未改。
- **「页面在页底 / 无溢出」不是本版修的对象**：那是几何事实（headroom=0 滚轮无处去），
  判据按「无余量只验证送达」处理，不为绿放宽。
- **诊断期间的干预实验不计分**：唤醒+直发滚轮 / `synthesizeScrollGesture` / 窗口微移
  三种干预能让输入到达 JS（tw +7）但不改变几何，只用于定位，不进判据。
- 沿用 0.4.7.11 的已知差异：受控侧 `buttons` 真值位掩码、地址栏/标签栏捕不到、
  受控最小化不停投递、跨 DPI 未处理、`/sync/arrange` 无桌面壳读不到屏幕尺寸等 —— 本版均未改动。
- 指纹、代理、UA-CH 本版未改动；本版动的只有投递链（`src/sync/session.js`）、
  目标解析（`src/sync/follow.js`）、内核装配（`src/runtime/manager.js`）。

## 六、装前动作

1. **先完全退出 FreePower**：主窗口关掉不算退出，右下角托盘图标 → 退出，
   确认任务管理器里没有 `FreePower.exe` 残留。安装器覆盖正在运行的 exe 会失败或留下半个文件。
2. **备份整个数据目录**：`%APPDATA%\FreePower\`
   （含旁文件 `freepower.db-wal` / `freepower.db-shm`，只拷 `.db` 等于没备份最新写入）。
3. 本版**不改数据库结构**（只新增运行时计数，不进库），装错版本也能直接装回，数据不用还原。

## 七、回退

装回 `FreePower-0.4.7.11-setup.exe`（回退包随本版一并放在交付目录）即可。
本版没改数据库结构，旧版本读新数据不会出问题。
