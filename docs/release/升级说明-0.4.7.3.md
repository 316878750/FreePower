# FreePower 0.4.7.3 升级说明

这一版只修**一件你实际踩到的事的两个叠加根因**：打开环境**打不开**、就算打开了也是**空白一片**。

1. **打不开** —— 不是导入坏了、也不是代理坏了，是 **Chrome 内核不支持 SOCKS5 认证**；
2. **空白** —— 就算代理修好，旧版第一张标签就是 `about:blank`（你库里 102 个环境有 101 个 `open_urls` 是空的）。

这一版把两件都修了：带账号密码的代理走**本机中继**，第一张标签换成**本地起始页**。

---

## 1. 这一版改了什么

### ① 带用户名密码的代理走本机中继（P0）

- 新增 `src/proxy/relay.js`：本机 SOCKS5 服务端，**只 bind `127.0.0.1`**，对浏览器不要求认证，
  对上游用环境的协议与账号密码握手；隧道建立后裸转发。
- 只要代理**带 username 或 password** 就自动起中继，内核拿到的只有 `socks5://127.0.0.1:<随机端口>`；
  `socks5` 与 `http/https` 带凭据都走这条路。
- **不带凭据的 socks5 仍是直连**（Chrome 自己能跑，不多绕一层）。
- 中继起不来 → 明确报错并**拒绝启动**（`800003`），绝不偷偷降级成直连。
- 代理预检仍然打**真实上游**（带凭据）—— 不会变成「探自己」的假绿灯。

### ② 新增起始页：第一张标签不再是 `about:blank`

- 新增 `GET /start?id=<环境>&sig=<签名>`：**纯 HTML，由本机服务进程出，不要 api_key**，
  签名绑这个环境、24 小时有效（只防跨站读，不是权限）。
- 页面上就一屏：**环境名、代理 `host:port`、期望出口 IP（导入时记的 ip/国家/城市）、
  实测出口 IP（服务进程探测 + 时间戳）、内核版本、UA**。
  代理不通时明确写 **「代理未连通：<原因>」** —— 不空白、不显示 Chrome 错误页。
- **页面自己不发任何外连请求**（CSP `default-src 'none'`，内联脚本只 `fetch` 同源的 `/start/data`）；
  出口探测全在**服务进程**做、结果注入页面。所以代理全挂时这张页照样打得开。
- 「重新检测」按钮 → 打本地 `/start/data`（`force=1` 跳过 15 秒缓存）。
- 触发规则：
  - `open_urls` 为空 → 第一张就是起始页（替掉 `about:blank`）；
  - `open_urls` 有值 → **行为与以前逐字节一致**，不多开；
  - 设置页新增开关「**总是打开起始页（与 AdsPower 一致）**」，**默认关**；打开后 = 起始页 + 原有启动网址。
- **代理全挂时还能打开的原因**：启动参数里 `--proxy-bypass-list=<-loopback>;start.freepower.test`
  ＋ `--host-resolver-rules=MAP start.freepower.test 127.0.0.1`。
  为什么不用 `127.0.0.1`：我们的判据钉着「连 `127.0.0.1` 也走代理」（代理不泄漏的底线），
  把 loopback 放进 bypass 会把这条底线破掉；用一个只有本机能解析的假域名绕过去，两者都保住。

### ③ 0.4.7.2 那几件仍然在

UA 跟版默认关（你存的 133 不会被改成 157）、UA-CH 逐项忠实、跨站子帧的限制如实写在下面第 7 节。

## 2. 你那 50 个环境为什么打不开（真相）

启动日志里是这两行：

```
代理预检通过 38.190.239.119 HK 8489ms
launch … --proxy-server=socks5://38.190.239.119:33066
WARN 出口探测失败 出口探测页不是预期格式：This site can't be reached
```

直接跟那台 SOCKS5 握手：客户端只报 `no-auth` 时，服务端回 **`0x02`（必须用户名密码）**。
`--proxy-server=socks5://host:port` 是内核自己发握手，**它只会发 no-auth、不带账号密码** ——
所以握手失败，所有请求 `ERR_BLOCKED_BY_CLIENT`，页面全红。

而我们的代理预检是在 FreePower 进程里**带凭据**做的，所以能通 —— 于是「预检绿、浏览器死」。
**这不是你的数据坏了，也不是代理坏了。** 升级后同一批环境直接能开，不用重新导入。

## 3. 修法与边界

```
浏览器 --socks5://127.0.0.1:<端口>--> FreePower 中继 --(你的账号密码)--> 你的代理 --> 目标
```

- 内核**看不到**你的上游地址与账号密码（命令行里只有 `127.0.0.1:<端口>`），
  启动响应、环境日志、页面里都查不到账号密码。
- 中继只监听本机回环。**边界**：本机上其它程序理论上能连这个回环端口白用这个出口
  （端口随机，但同机可扫）—— 与我们一贯的「同一台机器互不设防」是同一条边界。
- 中继起不来就拒绝启动，不会「看起来在跑、其实在用本机 IP」。
- 多级代理链仍走原来那条路（`is_multi_level_proxy` 的行为没变）。

## 4. 为什么「打开了也是空白」（第二个根因）

旧代码是这一行：

```js
const firstUrl = urls[0] || 'about:blank';
```

`open_urls` 为空就开一张 `about:blank` —— 一片白，什么都没有。你库里 **102 个环境有 101 个
`open_urls` 是 `[]`**（只有一个是配了 example.com 的），所以就算代理修好了，打开还是白屏，
你会以为根本没修。

对手的做法是每个环境第一张开 `https://start.adspower.net/?id=<env>`，并在启动参数里
把那个域名放进**绕代理名单** —— 所以它代理挂了也能显示。我们照同样的思路做，但用**本地页**：
不依赖任何外网、不泄露环境 id 给第三方。

## 5. 起始页长什么样、怎么用

一屏，从上到下：

| 字段 | 说明 |
|---|---|
| 环境名 | 标题就是环境名；下面一行是 `#编号 · id 前 8 位` |
| 状态条 | 绿「代理已连通」/ 红「代理未连通」＋原因（如 `SOCKS5 认证失败`、`ECONNREFUSED`） |
| 代理 | 协议 + `host:port`；带账号密码的只写「（带用户名密码）」，**不显示凭据** |
| 期望出口 | 导入时记下的 `ip · 国家 · 城市`（没有就显示「—」） |
| 实测出口 | 服务进程真探测到的 IP + 国家/城市 + 时间 + 延迟；「重新检测」按钮在右边 |
| 内核版本 | 这个环境实际用的内核版本 |
| User-Agent | 这个环境实际用的 UA |

- 时间显示的是**环境自己的时钟**（按环境时区），不是宿主时间 —— 与页面里 `Date` 一致。
- 探测结果按环境缓存 **15 秒**（点「重新检测」强制重探）。
- 代理不通时**不猜**出口 IP：宁可写「代理未连通：原因」，也不把宿主 IP 当环境 IP 显示。

## 6. 升级、回退与备份

### 升级

直接跑 `FreePower-0.4.7.3-setup.exe`（一键安装，装到当前用户，装完自动启动）。
不用先卸载旧版，也不用动数据目录。旧库直接能读，**不需要迁移**。

### 回退（如果这一版有问题）

跑同目录下的 `FreePower-0.4.4-setup.exe` 即可回退到 0.4.4。
**注意**：0.4.4 不认识 0.4.6/0.4.7 新增的几列（快照、缓存清理、撤销合并 cookie 等），
读旧库时会忽略它们（不报错、不删数据），但那几样功能在 0.4.4 里就没有。

### 备份（升级前建议做一次）

数据目录是 `%APPDATA%\FreePower`，**要连同 `data\logs` 一起拷**（日志是排障的唯一线索）。
只拷主库文件等于没备份：cookie、快照、环境 userdata 都在这个目录里。

## 8. 已知限制（照旧写全，没改的不省略）

1. **跨站子帧（OOPIF）里 `uaFullVersion` 仍是真实内核版本**（0.4.7.2 起如实记录，本版没动）：
   父页 `127.0.0.1`、子帧 `localhost` 这种真跨站 iframe，页面自己在补丁落地前读到的
   `uaFullVersion` 是宿主真值（如 `157.0.8103.78`），8 秒内都不会翻过来；
   从外部调试会话（CDP）读却是你配的 `133.0.6943.127`。
   **只影响跨站子帧、只影响这一项已废弃的字段**：`brands` / `fullVersionList` / `platformVersion`
   在子帧里**从首字节起就是对的**；同站子帧跟随父页，本来就是对的。修法方向（补完补丁后让子帧 reload 一次）
   会让每个跨站 iframe 多加载一次，留到 0.4.8 单独评估。
2. **起始页只在 `open_urls` 为空时自动出现**（默认）；配了启动网址的环境要多看一张，得去设置页打开那个开关。
3. **起始页靠假域名 `start.freepower.test` 绕代理**：启动参数里用 `--host-resolver-rules` 把它钉到回环。
   这是**每个内核进程内**的解析规则，不改系统 hosts、不影响别的浏览器；
   但如果你把这个域名在代理侧做成黑洞（比如代理强制拦截所有 `*.test`），起始页会被代理拦下来。
4. **起始页签名 24 小时**：一直开着的旧标签超过 24 小时再点「重新检测」会 403，重开起始页即可。
5. **字体不伪装**：只声明存在、不伪造字形与宽度度量（自检里标黄、覆盖度 `none`）。
6. **WebRTC 只做参数级**（`disable_non_proxied_udp`），不做 JS 层伪造。
7. **SOCKS5 中继只支持 CONNECT（TCP）**，UDP ASSOCIATE 不做；`https` 代理 + `https` 目标（TLS in TLS）预检仍不支持。
8. **PAC 明确不支持**（可能含 DIRECT 回退，无法保证 fail-closed），会明确报错、一个内核都不起。
9. **同步会话仍是单例**：同时只能有一个（窗口同步这一版的改动挪到 0.4.7.4）。
10. 其它未变的限制（注入面、worker 覆盖范围、代理检测边界、云端接口一律明确报不支持等）见 README 的「已知限制」。

## 11. 需要你在真实桌面复验（我这边没法替你点）

1. 双击 `FreePower-0.4.7.3-setup.exe` → 装完自动启动 → 「关于」里版本显示 **0.4.7.3**。
2. 打开你那个 socks5 带账号密码的环境 → **第一张标签就是起始页**（不再是白屏）：
   状态条是「代理已连通」，实测出口 IP 应该等于你导入时那个环境的期望出口；
   环境日志里应有一行 `代理中继 127.0.0.1:<端口> → 上游 socks5 <host>:<port>`。
3. 把那个环境的代理故意改成一个不存在的端口再打开 → 起始页**照样能开**，状态条红字
   「代理未连通：<原因>」，代理那一行写着 `socks5://<host>:<port>`。
4. 打开一个配了启动网址的环境（比如 tray-accept）→ 仍然只开那一张，没有多出起始页。
5. 设置页 → 「启动：起始页」→ 勾上「总是打开起始页（与 AdsPower 一致）」→ 再打开第 4 步那个环境 →
   应该是两张：起始页 + 那个网址；取消勾选后恢复一张。
6. 起始页上点「重新检测」→ 时间会刷新（15 秒内不点则读缓存）。
