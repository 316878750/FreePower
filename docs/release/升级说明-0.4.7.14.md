# FreePower 0.4.7.14 升级说明

> 0.4.7.13 装到用户机器上：**9 个窗口，主控操作，8 个受控窗口完全不动**。
> 本版定位到原因并修掉，同时补上了一直缺的**标签同步**（新开标签、打开链接、切换、关闭）。
> 用户 2026-11-25 用 9 窗口实测 5 项全部 OK（第四节）。

## 一、先纠正 0.4.7.13 的结论（事实优先）

0.4.7.13 把 **Win32 投递设为默认**，依据是真内核判据 16/16。**这个依据有盲区**：判据环境里，
指纹固定的页面尺寸恰好等于真实窗口尺寸，两套坐标重合，所以换算错了也测不出来。

用户机器上的诊断读数（`data/diag-win32.json`，2026-11-25 13:36）：

| 读数 | 值 |
|---|---|
| 受控页面视口（指纹 `setDeviceMetricsOverride` 固定） | 3170×1800 / 2970×1560 / 2842×1488 |
| 受控窗口实际外框（窗口排列后） | **1146×464** |
| 每个受控窗口：Win32 成功 / 越界丢弃 | **1 / 63** |
| 结束日志 | `事件=64 转发=64 投递失败=0` —— 看不出任何问题 |

Win32 helper 按「页面 CSS 坐标 × DPI」算屏幕坐标，算出的点几乎全在 1146×464 窗口外，被判越界丢弃。
而 0.4.7.13 的写法是「找到窗口就算投递了」，CDP 路径被跳过 —— 所以是**一点都不动**，不是偶尔不动。

教训已进本版：结束日志带投递路径与越界数（第二节 4），判据缺口记在第五节。

## 二、修了什么

### 1. 默认投递改回 CDP

- `deliver` 默认 `cdp`；只有显式设 `"win32"` 才启用 Win32（实验，坐标换算未修，**不要开**）。
- Win32 判越界 / 失败时，这条事件**改走 CDP**，不再吞掉（计入 `win_oob` / `win_fail`）。

### 2. 标签同步（新）

`src/sync/tab-mirror.js`。页面里的捕获脚本看不到浏览器界面（地址栏、「+」、Ctrl+T、标签栏），
所以改看主控的 CDP target 事件，在每个受控窗口里做同样的事：

| 主控操作 | 受控窗口 |
|---|---|
| 新开标签（「+」/ Ctrl+T） | 各开一张 |
| 地址栏输入回车 / 点链接跳转 / 前进后退 | 对应标签跳到同一地址 |
| 点 `target=_blank` 链接 | 点击回放已让受控开出来就**认领**那张，不再另开 |
| 切换标签 | 切到对应那张 |
| 关闭标签 | 关掉对应那张 |

- **按映射对应，不按序号**：用户 9 窗口里主控与受控的标签顺序不一致，按序号会动错页。
  只镜像「同步开始时的前台标签」和「同步期间新开的标签」；之前就开着的其它标签不动。
- 跳转前等约 1.2 秒再比地址：点击回放已让受控跳到同一页的，不再跳第二次。
- `GET /api/v2/sync/status` 新增 `tab_sync`：`opened / adopted / navigated / activated / closed / errors / last_error`。

### 3. 修 0.4.7.13 拆分遗留的 bug

`session.js` 拆模块时有 9 处 `...current.xxx` 没改成 `state.current`。
受影响：**重启同步、运行中改设置、打开网址、标签状态、关闭标签、统一标签、窗口排列的窗口解析** —— 调用即报错。
诊断里「restart 后 `deliver` 没切过去」就是它。

### 4. 结束日志更好排查

「同步结束」一行新增：

```
越界丢弃=… 投递路径=cdp×8/win32×0(ok=…,fail=…,越界=…) 标签同步={"opened":…,"navigated":…,…}
```

以后「受控不动」先看这一行，不用临时抓 status。

## 五、已知限制（照旧写全）

1. **Win32 投递坐标换算未修**：需按「渲染区实际像素 ÷ 页面视口」算比例；修好并补上「窗口比指纹尺寸小」的真内核判据前，不要开 `deliver: "win32"`。
2. **判据缺口**：`sync-deliver-kernel` 的窗口尺寸 = 指纹尺寸，测不出本版第一节的问题。待补。
3. 标签同步**不跟**：地址栏里的逐字输入、标签栏拖动排序、同步开始前就在后台的标签。
4. 页面自己 JS 跳转的站点：主控跳、受控也会自己跳；有「同地址不再跳」，但时间差可能让受控多刷新一次。
5. 组合键（Ctrl+A / Ctrl+C / Ctrl+V）、跨进程 iframe（reCAPTCHA、钱包弹窗）本轮**未实测**。
6. 浏览器界面里的其它操作（书签栏、扩展按钮、右键菜单）仍抓不到。
7. 指纹、代理、UA-CH 本版未改动；数据库结构未改动。

## 六、打包注意（本机一次性处理过，换机器可能再遇到）

本机工作区目录带 **Low 完整性标签**（README 第 23 条），打包时工具与目录级别不一致会失败：

| 现象 | 处理 |
|---|---|
| `rcedit … Unable to load file …\win-unpacked\FreePower.exe` | `icacls .\.tmp\eb-cache\winCodeSign /setintegritylevel "(OI)(CI)M" /T /C`、`icacls .\release …` 同 |
| 弹窗 `7za.exe - This application could not be started` | `icacls .\node_modules\7zip-bin /setintegritylevel "(OI)(CI)M" /T /C /Q`、`node_modules\electron` 同 |

`icacls` 在**管理员**窗口跑，打包在**普通**窗口跑。装前照旧：`icacls <setup.exe> /setintegritylevel Medium`。

## 七、装前动作

1. 托盘图标 → 退出，确认 `Get-Process FreePower` 无输出。
2. 备份 `%APPDATA%\FreePower\`（含 `-wal` / `-shm`）。
3. 本版不改数据库结构；`deliver` 缺省即 `cdp`。但 0.4.7.13 下**保存过同步默认设置**的，库里会存着 `deliver: "win32"`，升级后照用（界面没有这个开关）。**从 0.4.7.13 升上来的，开始同步后读一次 `GET /api/v2/sync/status` 的 `settings.deliver`，应为 `cdp`**；不是的话 `POST /api/v2/settings/sync-defaults` 写 `{"deliver":"cdp"}`，再重新开始同步。

## 八、回退

- 装回 `FreePower-0.4.7.13-setup.exe` 或 `0.4.7.12`。数据库结构未改，旧版读新数据无问题。
- 0.4.7.13 默认 Win32，回退到它要在同步设置里手动改 `deliver: "cdp"`，否则在窗口比指纹尺寸小时又会全不动。
