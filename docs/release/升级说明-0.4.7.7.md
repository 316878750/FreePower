# FreePower 0.4.7.7 升级说明

> 本版取代 0.4.7.6。**只有一件事**：上游代理改走本地 SOCKS5 链。

| # | 改了什么 | 为什么要改 |
|---|---|---|
| 1 | 中继拨环境代理时，**先走本机 SOCKS5 链**，在隧道里对环境代理做握手，最后 CONNECT 目标 | 页面打不开时，卡的是**我们到代理这一跳**，不是代理连目标 |

为了让读数可信，本版同时带两笔观测/口径修正（行为不变）：

| # | 改了什么 | 影响 |
|---|---|---|
| 2 | 拨号两段埋点：`dial_tcp_ms`/`dial_tcp_fail`、`dial_reply_ms`/`dial_reply_fail`、`dial_fail_stage{tcp,auth,reply}` | 纯观测，默认开，便于以后一眼看出 21s 烧在哪一段 |
| 3 | 读正文改 `textContent` 优先（`innerText` 只作兜底） | 标签页不可见时 `innerText` 返回空串，会把「渲染了」误判成「白屏」 |

---

## 1. 为什么改：卡在「本机 → 代理」这一段

2026-11-19 15:06 那轮（`206.119.169.185:37663`，带埋点）读数：

```
dial_tcp_ms=21016   dial_tcp_fail=31
dial_reply_ms=31219 dial_reply_fail=2
dial_fail_stage={tcp:31, auth:4, reply:2}
```

**48 次拨号里 31 次死在「连到代理本身」的 TCP 段，每次烧满 21 秒**；`reply` 段（代理去连目标）只失败 2 次。
同一个代理单发串行能通（第一次 26708ms、随后 2701ms）。也就是说：**丢的是我们到代理这段路，不是代理的出口能力。**

21 秒这个数字正是 TCP SYN 重传退避（1s / 3s / 7s / 15s）被我们自己掐断的痕迹。

## 2. 照谁的做：AdsPower 把这一跳放到了隧道对端

逆向实测（`adspower-reverse/8.9.23/33-AdsPower代理链路形态.md`）：

- 全机器 TCP 采样 **545 个样本 × 100ms，覆盖 IPv4+IPv6**，对 `206.119.169.175:37663` 的
  `ESTABLISHED` / `SYN_SENT` **全是 0**，本机也没有任何本地中继进程；
- 页面只连 `127.0.0.1:10808`（用户的 v2rayN / xray）；
- 但页面看到的出口 IP **仍是 `206.119.169.175`**。

结论：AdsPower 把「拨这台代理」这件事**放到了隧道对端（泰国节点）去做**，本机到代理这条丢包路径被整段绕开。

## 3. 改成什么

```
浏览器 → 我们的中继(127.0.0.1:port)
      → 本地 SOCKS5 链（默认读系统代理，如 127.0.0.1:10808）
      → 在隧道里 CONNECT 到环境代理 host:port
      → 在隧道里对环境代理做 SOCKS5（带环境自己的账号密码）
      → CONNECT 目标
```

- 最后一跳 CONNECT 目标的是**内层（环境代理）**，所以**出口 IP 仍是环境代理的 IP**，不是本地链的节点 IP。
  指纹隔离、IP 一致性、环境之间互不串 IP 的语义一律不变。
- 只有「中继拨上游」这一条路走链；本地 API、下载、CDN **一律不走链**。

## 4. 开关与兜底

| 场景 | 行为 |
|---|---|
| 系统代理是显式 SOCKS（`socks=` / `socks5=` / `socks://`） | 自动走链 |
| 系统代理是**裸 `host:port`**（本机就是这种：`ProxyServer = 127.0.0.1:10808`） | 也当 SOCKS5 候选、自动走链 |
| 系统代理是 `http=` / `https=` | 不当 SOCKS 链用，退回直连 |
| 分段格式（`http=…;https=…;socks=…`） | 从中挑出 `socks=` 那条 |
| 环境变量 `FREEPOWER_RELAY_CHAIN=socks5://host:port` | 显式指定，优先于系统代理 |
| 环境变量 `FREEPOWER_RELAY_CHAIN=0` / `off` / `false` | 关掉，走直连（与 0.4.7.6 完全一致） |
| 链连不上 / 外层握手失败 | `chain_fail` +1，**退回直连**，不拦启动、不拦连接 |
| **内层（环境代理）认证失败或被拒** | **不退回直连**，照实报错 —— 退回等于绕过用户配的代理 |

裸 `host:port` 当 SOCKS5 是有风险的（真 HTTP 代理会握手失败），所以必须依赖上面这条兜底：
外层握手不成 → `chain_fail` +1 → 退回直连。这条在判据里验过。

**前置条件**：链式依赖本机有可用的 SOCKS5（我们默认取系统代理）。
**没开代理软件的用户会自动退回直连，行为和 0.4.7.6 一样，不会更差。**

## 5. `stats` 新增字段（只记读数，不含凭据）

| 字段 | 含义 |
|---|---|
| `chain` | 当前用的链 `host:port`，直连时 `null` |
| `chain_used` | 成功经链拨出去的次数 |
| `chain_fail` | 链本身失败、退回直连的次数 |
| `chain_tcp_ms` / `chain_tcp_ms_total` | 连本地链的耗时（单次 / 累计） |
| `chain_reply_ms` | 让链 CONNECT 到环境代理的耗时（含外层握手） |

配合第 2 条的两段埋点，一眼能分出：**链没起（`chain_used=0` 且 `chain_fail` 涨）**、
**链起了但内层认证不过（`dial_fail_stage.auth`）**、**内层通了但到目标不行（`reply`）**。

## 7. 已知限制

1. **起始页「实测出口 IP」可能显示「探测源不可用」**：探测走链，`ip-api.com` 有速率限制，
   被限流时返回 `fail`。这是**软失败**，不代表代理不通 —— 同一时刻 `checkProxy` 是通的、出口 IP 正确。
   后续单独修（多探测源 + 备用源）。
2. **没开本地代理软件就没有链**：自动退回直连，等于 0.4.7.6 的行为。
3. **系统代理是 HTTP 代理时不当链用**：Windows 惯例裸值本意是 HTTP，真 HTTP 代理上做 SOCKS5 握手必然失败；
   我们靠「握手失败 → `chain_fail` +1 → 退回直连」兜住。
4. **站1（`defi.xstocks.fi/points`）是 SPA**：`readyState=complete` 时正文可能还是空的，
   不能用 readyState 当完成条件。验收脚本已改成**轮询正文非空**（500ms 一读，去掉 `style`/`script` 再计长度）。
   0.4.7.6 文档 §9.3.2 / §9.3.3 里「`body_len=0`」的旧读数按此口径理解。
