# FreePower 0.4.7.4 升级说明

这一版只修**窗口同步那一摊**，三件事：

1. **「窗口排列」点了报 100002** —— 我们错把它绑在「同步已经启动」上，而你的习惯（也是 AdsPower 的流程）是
   **勾选环境 → 窗口排列 → 启动同步**；
2. **「同步起来了但没反应」** —— 主窗口停在 Chrome 错误页时，旧版照样把会话起起来，一条事件都抓不到；
3. **出了问题看不见** —— 同步的开始/结束没有日志，只能靠猜。

0.4.7.3 那两件（带账号密码的代理走本机中继、第一张标签换成起始页）这一版原样保留。

---

## 1. 这一版改了什么

### ① 排列 / 显示 / 统一尺寸**不再要求同步已经启动**

- `arrange`（窗口排列）、`show`（显示窗口）、`show/force`（强制抬到前台）、`unify-size`（统一尺寸）
  都接受 `ids`（**运行中的环境 id 列表**）。
- 有同步会话、没给 ids → 行为与以前**完全一致**（用会话里的窗口，不重复 attach）。
- 没有会话、给了 ids → 按 ids 连上这些**已经在跑**的环境（复用现有 runtime 连接，
  **不新起内核、不 startProfile、已连的不重连**）。
- 没有会话、也没给 ids → `100002`，文案改成说人话：
  「没有可排列的窗口：先勾选正在运行的环境（同步没开始时也能排列），或者先开始同步」。
- 排列只走浏览器级命令，**一次 CDP 会话都不开**（响应里 `attached: 0`），不会和同步会话抢连接。
- 响应里 `source` 说明走的是哪条路：`ids` / `session`。

### ② 界面：「作用范围」可选，同步没开始也能用

- 「窗口同步」页与操作台的排列/显示区块多了**作用范围**：
  「**已选环境**」（默认，同步没开始时也能用）/「**当前同步会话**」。
- 窗口同步页现在**没开始同步也能勾环境**（以前只有开始同步时才选主/受控）。
- 两处是**同一份组件**（`web/sync-widgets.js`），参数跟着走，没有各写一套。

### ③ 同步前先判「主窗口有没有可同步的页面」

- 主窗口停在 `chrome-error://` / `devtools://` / 浏览器内部页 / 没注入的空白的空白页时，
  **直接报错**：「主窗口现在没有可同步的页面（…），先把页面打开再开始同步」，`100002`。
  不再起一个抓不到事件的死会话。
- 会话开始/结束各写一行**环境日志**（主/受控 id、主窗口 url、捕获脚本装没装、
  转发多少条、被开关拦下多少、binding 有没有真摘掉）。下次你说「没反应」，我能直接看日志定责。

## 2. 为什么「先排列」会报 100002（真相）

用户机器上 0.4.7.2 实测：

```
POST /api/v2/sync/arrange {"auto":true} → {"code":100002,"msg":"没有正在运行的同步会话"}
POST /api/v2/sync/show {}               → {"code":100002,"msg":"没有正在运行的同步会话"}
```

`arrangeWindows` / `showWindows` / `forceShowWindows` / `unifySize` 四个函数开头都是无条件的
`if (!current) throw`。但**排列这件事根本不需要同步会话** —— 它作用在「窗口」上，不是「会话」上。
界面里「窗口排列」区块一直摆在那儿，用户按习惯先点，就吃到 100002。

**这不是你的操作错了，是我们把两件不相干的事绑在了一起。**

---

## 3. 为什么「同步起来了却没反应」

同步引擎本身没坏（键鼠/滚轮/输入框/跨进程 iframe 的键鼠/收尾，真内核判据全绿）。
你那次是**主窗口停在 Chrome 错误页**（就是 0.4.7.3 修的那个代理问题），页面上没有可捕获的文档，
会话起来了但一条事件都抓不到，日志里也干干净净 —— 所以看起来像「同步坏了」。

这一版起：这种页面**直接告诉你**「主窗口现在没有可同步的页面，先把页面打开再开始同步」，
并且每次开始/结束都留一行日志。

**快捷键**：`Ctrl+Alt+S` 在装了 AdsPower 的机器上被它全局占着，我们注册失败（`err=1409`）是常态，
不是坏了。到**「窗口同步」页最下面的「全局快捷键」**里改一个（要带至少一个修饰键），
桌面壳会在 1–2 秒内重新注册。

## 4. 升级、回退与备份

### 升级

直接跑 `FreePower-0.4.7.4-setup.exe`（一键安装，装到当前用户，装完自动启动）。
不用先卸载旧版，也不用动数据目录。旧库直接能读，**不需要迁移**。

### 回退（如果这一版有问题）

跑同目录下的 `FreePower-0.4.4-setup.exe` 即可回退到 0.4.4。
**注意**：0.4.4 不认识 0.4.6/0.4.7 新增的几列（快照、缓存清理、撤销合并 cookie 等），
读旧库时会忽略它们（不报错、不删数据），但那几样功能在 0.4.4 里就没有。

### 备份（升级前建议做一次）

数据目录是 `%APPDATA%\FreePower`，**要连同 `data\logs` 一起拷**（日志是排障的唯一线索）。
只拷主库文件等于没备份：cookie、快照、环境 userdata 都在这个目录里。

## 5. 这一版没有动数据库结构

0.4.7.4 **没有新增列、没有改表**。回退到 0.4.4 不会因为结构不认而读不了库。

## 6. 已知限制（照旧写全，没改的不省略）

1. **跨站子帧（OOPIF）里 `uaFullVersion` 仍是真实内核版本**（0.4.7.2 起如实记录，本版没动）：
   父页 `127.0.0.1`、子帧 `localhost` 这种真跨站 iframe，页面自己在补丁落地前读到的
   `uaFullVersion` 是宿主真值（如 `157.0.8103.78`），8 秒内都不会翻过来；
   从外部调试会话（CDP）读却是你配的 `133.0.6943.127`。
   **只影响跨站子帧、只影响这一项已废弃的字段**：`brands` / `fullVersionList` / `platformVersion`
   在子帧里**从首字节起就是对的**；同站子帧跟随父页，本来就是对的。修法方向（补完补丁后让子帧 reload 一次）
   会让每个跨站 iframe 多加载一次，留到后面单独评估。
2. **窗口排列只改窗口外框**，不改视口；没有「记住每个环境上次的位置」。
3. **同步会话仍是单例**：同时只能有一个。
4. **「作用范围 = 已选环境」时只认运行中的环境**：没起来的 id 会被跳过并在响应里点名，不会替你启动。
5. **字体不伪装**：只声明存在、不伪造字形与宽度度量（自检里标黄、覆盖度 `none`）。
6. **WebRTC 只做参数级**（`disable_non_proxied_udp`），不做 JS 层伪造。
7. **SOCKS5 中继只支持 CONNECT（TCP）**，UDP ASSOCIATE 不做；`https` 代理 + `https` 目标（TLS in TLS）预检仍不支持。
8. **PAC 明确不支持**（可能含 DIRECT 回退，无法保证 fail-closed），会明确报错、一个内核都不起。
9. **起始页只在 `open_urls` 为空时自动出现**（默认）；配了启动网址的环境要多看一张，得去设置页打开「总是打开起始页」。
10. **新建环境的「内核版本」取的是目录名**：本机 Chrome 自动更新已落盘、但启动器还没换过去时
    （Windows 上要等 Chrome 完全退出），新建/导入的环境会按**新目录名**记 `kernel_version`，
    而实际启动的还是旧内核；开「UA 跟随内核版本升级」时会按新版本号写 UA，与实际内核差一个补丁号。
    启动后 `Browser.getVersion` 的真值仍会写进 `data/kernel-version.json` 并在之后复用，
    所以重启一次 Chrome 即自愈。彻底修（启动前用真值校验）记在 0.4.8。
11. 其它未变的限制（注入面、worker 覆盖范围、代理检测边界、云端接口一律明确报不支持等）见 README 的「已知限制」。

## 8. 怎么验的（本轮读数）

**红→绿（先红后绿，红测钉「没有连坐」）**

- 红：把 `src/sync/session.js` 换回 0.4.7.3 那一版再跑同一个判据 → **13/36**，
  关键几条：`① API 回 code=0` → `100002 没有正在运行的同步会话`；
  `① 走的是 ids 这条路` → `undefined`；`① 排列没开任何 CDP 会话` → `undefined`；
  `② msg 说的是「先勾选正在运行的环境」` → `没有正在运行的同步会话`；
  `③ status.size_mismatch === false` → **`true`**（宽度 `1266 / 1600` 不一致）。
  **没有连坐**：`② code=100002（不是 500）`、`③ 会话起来了（1 主 + 1 受控）`、
  `③ 没有降级窗口`、`④ 有会话时排列照旧成功（已排列 2 个窗口）`、
  四条「静态：没有起内核的调用」在红测里**仍然是绿的**。

## 9. 需要你在真实桌面复验（我这边没法替你点）

1. 双击 `FreePower-0.4.7.4-setup.exe` → 装完自动启动 → 「关于」里版本显示 **0.4.7.4**。
2. 打开 2 个环境 → 「窗口同步」页勾上这 2 个 → 作用范围选「**已选环境**」→ 点「窗口排列」→
   两个窗口应该摆好，**不再报 100002**。
3. 接着点「开始同步」→ 状态里不应出现「窗口尺寸不一致」的告警。
4. 故意让主窗口停在一个打不开的网址（错误页）→ 点「开始同步」→ 应该明确提示
   「主窗口现在没有可同步的页面…」，而不是「起来了但没反应」。
5. 「全局快捷键」那一栏如果显示「注册失败」，改一个（例如 `Ctrl+Alt+Y`）→ 1–2 秒后应变成「已生效」。
