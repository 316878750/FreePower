# FreePower 0.4.7.10 升级说明

> 本版取代 0.4.7.9。**主改动只有一件事**：窗口同步「连错标签页」——操作主控，受控窗口不跟着动。
> 没动库结构、没动内核、没动指纹、没动代理。

| # | 改了什么 | 为什么要改 |
|---|---|---|
| 1 | 同步选页改成**优先选前台可见的那张标签**（主控和受控都走这条） | 用户操作主控、受控窗口不动：同步连到了后台隐藏标签，输入全打到看不见的页上 |
| 2 | `sync/status` 的 `windows[]` 增加 `target_url` / `visible` / `confident` / `target_source` | 原来只有一串 `target_id` 哈希，日志和界面都看不出「连错页」 |
| 3 | 选页判据用页面**自己报的** `location.href`，不信 CDP 的 `targetInfo.url` | 错误页那里 targetInfo 报的是「当初想去的地址」，会把死掉的错误页当成真站选走 |
| 4 | 新增判据 `test/sync-pick.test.mjs`（20 条） | 这条链路上一次漏检就是因为没人真求值测过「选哪张页」 |

---

## 1. 出了什么问题

用户装上 0.4.7.9 后：**指纹正常、窗口排列正常、同步能启动，但操作主控时受控窗口不跟着动。**

整条链路逐段量过，**除了最后一步全是好的**：

```
采集：running=true events=105 forwarded=105 dropped=0
派发：scheduler={sent:311, errors:0, pending:0}
受控窗口吃输入：对 10054 注入 5 次 mouseWheel，scrollY 0 → 1500
```

断在**连错了标签页**。把 `status.windows[].target_id` 逐个映射回 `/json/list`：

```
master 398346c1 → defi.xstocks.fi/points    ← 可见
slave  b9cef669 → app.startale.com/sign-up  ← 后台隐藏
slave  a0bf4554 → app.startale.com/sign-up  ← 后台隐藏
slave  e1b93fa4 → app.startale.com/sign-up?_v=… ← 后台隐藏
```

三个受控窗口里**看得见**的标签都是 `defi.xstocks.fi/points`，同步却连在后面那张看不见的 startale 上。
用户看着 xstocks 操作，输入全打在后台页上，所以「怎么点都没反应」。

原因：旧 `pickPageTarget()` 取「第一张 URL 像真站的 page」，**完全不看哪张是前台可见的**。
这次每个窗口都开了 3–4 个标签，`/json/list` 里 startale 排在前面就被选中了。
（11-18 那轮能过，是因为当时每个窗口只有起始页一张。）

## 2. 改成什么样

选页优先级（主控、受控**同一套**）：

1. **前台可见 + 是真站** → 选它，`confident: true`
2. 读不到可见（窗口最小化、target 已关），或可见的那张是起始页 → 退回**第一张真站**（跳过起始页 / 空白页 / 内部页），`confident: false`
3. 连真站都没有 → `pages[0]`，`confident: false`

「跳过起始页」这条**保留**（0.4.7.3 修过的东西不许丢），只是从「首选依据」降级成「兜底时仍然遵守」。

**主控还多一道守卫**：如果前台那张是起始页、真站在后台标签里，**拒绝开始同步**并说明原因
（「主窗口停在起始页…同步它等于点了没反应」），而不是悄悄同步到后台页。
这条同时保住了 0.4.7.5 的「主窗口停在起始页就拒绝」。

另外两处顺带的正确性修正（同一件事的组成部分，不是新功能）：

- 选页判「是不是真站」改用页面**自己报的** `location.href`。CDP 的 `targetInfo.url` 在错误页上报的是
  「当初想去的地址」（`http://127.0.0.1:1/nope`），页面实际停在 `chrome-error://chromewebdata/` ——
  光看 targetInfo 会把一张死掉的错误页当成真站选去同步。
- 读可见性的实现抽成 `tabs.js` 的 `readVisibility()`，切标签用的 `visibleTabIndex()` 和同步选页
  共用一份，口径不会各写一套。

## 3. 用户可见的变化

| 场景 | 0.4.7.9 | 0.4.7.10 |
|---|---|---|
| 每个窗口开了多个标签，前台是 xstocks、后台是 startale | 连到后台 startale，**操作没反应** | 连前台 xstocks，**正常同步** |
| 主窗口前台是起始页、真站在后台 | 可能悄悄同步后台页 | **拒绝开始**并提示「主窗口停在起始页…」 |
| 窗口最小化 / 读不到可见性 | 连第一张真站 | 不变（连第一张真站），但 status 里 `confident:false` |
| 看 `sync/status` | 只有 `target_id` 哈希 | 多了 `target_url`、`visible`、`confident`、`target_source` |

`sync/status` 的新字段长这样：

```json
{"profile_id":"b9cef669…","role":"slave","target_id":"EC27CBC176",
 "target_url":"https://app.startale.com/sign-up","visible":false,
 "confident":false,"target_source":"real-fallback"}
```

**排查口诀**：同步没反应时先看 `windows[]` 里 `role:"master"` 那条的 `target_url` 是不是你正在看的那张页。
如果不是，就是这个 bug；`visible:false` 就是铁证。

## 4. 升级方式

- 直接跑 `FreePower-0.4.7.10-setup.exe` 覆盖安装即可。环境数据、代理、Cookie、指纹配置全部保留，
  不需要先卸载，也不需要备份（本版不碰库结构）。
- 装完在「关于 / 版本」里应显示 `0.4.7.10`。
- 装完**先停掉正在跑的同步再重新开始**（旧的同步会话是按旧规则连的，不会自己换页）。

## 5. 已知限制

1. **「可见」只在会话开始时判定一次**。同步跑起来之后，用户如果在主控窗口里切到另一张标签，
   同步**不会**跟着切到那张页（这条本版没做，属于「跟随活动标签」的能力，不是这次的 bug）。
   要换页就先停掉同步再重新开始。
2. **读不到可见性时只能兜底猜**：窗口最小化、或 target 刚好在关闭过程中，`document.visibilityState`
   读不到，此时退回「第一张真站」，`confident:false`。这时仍可能连错页 —— 但 status 里能看出来。
3. **判据用的是假 CDP 客户端，不是真 Chrome**：能钉住「选哪张页」的决策逻辑（含反向验证），
   钉不住「真内核里 `visibilityState` 的实际取值」。真内核那层仍靠 `npm run smoke` 里的 `sync-*`。
4. 0.4.7.7 – 0.4.7.9 的其余已知限制**照旧全部适用**，本版没有改：起始页出口 IP 可能显示
   「未验证（探测源不可用）」、没开本地代理软件就没有链、HTTP 系统代理不当链用、站1 是 SPA
   不能用 readyState 判断完、站1 有 2 个环境正文只收到 3339 字符。详见 `升级说明-0.4.7.7.md` §8。
5. **代理链只支持 http 跳**（0.4.7.9 的行为，未改）。

## 6. 回退

退回到 **0.4.7.9 包**即可，直接覆盖安装。
本版**没有动库结构、没有新增列**，旧版本读到新版数据没有任何兼容问题。
但回退会把「同步连错后台标签」这个问题一起带回来。

## 7. 判据

### 7.1 新增 `test/sync-pick.test.mjs`（20 条，已并入 `npm test`）

用**假 CDP 客户端**真求值 `pickPageTarget()` / `masterBlockReason()` / `statusOf()`，不碰真内核、不碰用户环境。

| 组 | 钉住什么 |
|---|---|
| ① | 用户这次的现场还原：startale 排前面（后台）、xstocks 可见 → **必须选 xstocks**，且 `visible/confident/source` 都对 |
| ② | **反向自证**：同一份 target 列表，可见性读不到（等价于旧实现不看可见性）→ 选中的是 startale，且与 ① **必须不同**（证明这条门有区分力） |
| ③ | 一个都读不到可见 → 兜底第一张真站、`confident:false`、`visible:null`（不瞎猜）；可见性读到异常值同样兜底；兜底时仍跳过起始页 |
| ④ | 主控同口径（可见页不是第一张时选可见的）；主控「前台是起始页、真站在后台」→ 拒绝；可见页就是真站 → 允许（不误伤）；读不到可见时仍按 0.4.7.5 原口径判；错误页仍然拒绝 |
| ⑤ | 起始页是可见标签时**跳过起始页**（0.4.7.3 那条不许丢）；只有起始页一张时只能选它（交给上层拒绝）；空白页 / `chrome://newtab` 永不当真站 |
| ⑥ | 用页面自己报的 href 判：targetInfo 说是真站、实际停在 `chrome-error` → 不当真站；起始页同理 |
| ⑦ | `status.windows[]` 必须带 `target_url` / `visible` / `confident` / `target_source`，且 `visible` 如实反映 true/false/null |

**反向验证（真做了，不是声称）**：把 `pickPageTarget` 临时换回 0.4.7.9 的旧实现（完全不看可见性），
重跑本判据 → **`11 passed, 9 failed`**，其中 ① 报的就是
`选中了 EC27CBC176 / https://app.startale.com/sign-up`；换回新实现 → **`20 passed, 0 failed`**。

### 7.2 升级一条旧判据

`test/start-page.test.mjs` 的「同步选页跳过起始页」原来是对 `session.js` **做正则**
（找 `isStartPageUrl(t.url)` 这个字面量）。这次实现一改写就假红了 —— 正则只能证明「这行存在」，
证明不了「起始页真的不会被选走」。已改成**真求值**：给 `pickPageTarget` 一个假客户端，
断言「起始页是可见标签时也不选它」。
