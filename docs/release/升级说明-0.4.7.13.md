# FreePower 0.4.7.13 升级说明

> 0.4.7.9 起「主控操作、受控窗口不动」反复出现，0.4.7.10–0.4.7.12 三版都只修到一部分。
> 这一版找到了**主因**并一起修掉两个次因：
> ① 受控窗口被遮挡/在后台时 Chrome 会节流渲染器——命令「成功」、页面不执行；
> ② iframe（登录框、钱包、验证码）里的操作抓不到；
> ③ 新增 Win32 鼠标投递：像 AdsPower 一样**投给窗口**而不是投给标签。
> 详细技术回执见 `docs/30-窗口同步修复-后台节流-iframe-Win32投递.md`。

## 一、先纠正上一版的结论（事实优先）

0.4.7.12 升级说明第一节写了「Chrome 遮挡冻结渲染器吞 CDP 输入——这个机制不存在」，依据是启动参数里已经关了
`CalculateNativeWinOcclusion`。**这个结论只对了一半**：

- `CalculateNativeWinOcclusion` 只管「原生遮挡判定」，关掉它 `visibilityState` 确实保持 `visible`；
- 但 Chrome 另有三套与遮挡判定**无关**的后台降级：渲染器后台优先级（renderer backgrounding）、
  被遮挡窗口降级（backgrounding occluded windows）、后台定时器节流（含 1 分钟级的 IntensiveWakeUpThrottling）。
  它们照样会让被遮挡的受控页「输入到了但不执行/不重绘」，而 CDP 返回成功、`errors=0`。
- 本版新判据 D1 直接量了这一点：受控窗口被主控**完全盖住**时，页面 `setInterval(100)` 1 秒跑 10 次（42→52），点击同步成功。

以后排查「受控不动」：先确认这四个启动参数在内核命令行里（见第二节 1），再看 `delivery_via / win_fail / win_last_reason`。

## 二、修了什么

### 1. 后台/被遮挡窗口不再被节流（主因）

内核启动参数新增：

```
--disable-renderer-backgrounding
--disable-backgrounding-occluded-windows
--disable-background-timer-throttling
--disable-features=…,IntensiveWakeUpThrottling
```

`CalculateNativeWinOcclusion` 仍在 `--disable-features` 里，且 `--disable-features` 只有一条（多条时后者覆盖前者，判据钉死）。

### 2. iframe 里的操作能同步了

| 场景 | 之前 | 现在 |
|---|---|---|
| 同源 iframe | 坐标按 iframe 自己算，点偏；已加载的子帧没装捕获 | 沿 `frameElement` 累加偏移；装捕获时递归覆盖已加载子帧；子帧导航补装 |
| 跨进程 iframe（OOPIF：多数登录框/钱包/reCAPTCHA） | 完全抓不到 | 主控每张标签自动挂子帧（先停住→装捕获→放行，首屏输入不丢）；坐标按子帧在页面里的位置补偏移，拿不到位置就丢弃（不点错） |

### 3. Win32 投递（Windows 默认）

- 鼠标（移动、按下、抬起、滚轮）和**不带字符的键**（退格、方向键、回车、Tab、功能键、组合键）用 PostMessage 投给受控窗口，
  由浏览器自己路由到前台标签和 iframe——不再依赖「找准受控窗口的激活标签」。**不装键鼠钩子**。
- **带字符的键、输入法文本、粘贴、随机数字、模拟人工输入仍走 CDP**。实测 PostMessage 产生不了正确字符（补 WM_CHAR 得到 `"aabb"`，不补得到 `"AB"`）。
- 首次开始同步时用系统自带 .NET Framework 4 的 `csc.exe` 编译一个小 helper 到 `%TEMP%\freepower-win-input\`，**多等几秒属正常**，之后复用。
- helper 起不来（无 csc / 编译失败）→ 自动走 CDP，服务日志一行 `WARN 同步投递端 … 退回 CDP 投递`。
- mousemove 现在带按键状态，**拖拽能同步**了。

### 4. 状态接口新增字段

`GET /api/v2/sync/status` → `windows[]`：

| 字段 | 含义 |
|---|---|
| `delivery_via` | 最近一次实际走的路径：`win32` / `cdp` |
| `win_ok` / `win_fail` | Win32 投递成功 / 失败条数 |
| `win_last_reason` | 最后失败原因：`no_window` / `window_gone` / `window_minimized` / `no_render_widget` / `timeout` / `helper_down` |

同步设置新增 `deliver`（默认 `win32`，只有 `cdp` 能切回老路径）。

### 5. 代码结构（不影响行为）

`src/sync/session.js`（约 2300 行）拆成门面 + 5 个模块：`session-state / session-cdp / session-live / session-windows / session-tabs`。
对外导出名与 0.4.7.12 完全一致。

## 五、已知限制（照旧写全）

1. 判据用 CDP 模拟主控输入，**不是真人鼠标**——请按第七节人工实测后再分发。
2. **组合键**（Ctrl+A / Ctrl+C / Enter / Tab）走 Win32，判据未覆盖；Chrome 读修饰键可能看真实键盘状态。
3. **hover 效果**：被遮挡窗口的悬停样式可能不出现（Chrome 参考真实光标位置）；点击不受影响。
4. 开**侧边栏 / 下载栏 / 页面缩放**时 Win32 坐标可能偏；iframe 带 CSS `transform` 缩放时两条路径都会偏。
5. **跨屏不同 DPI** 未实测。
6. **地址栏、标签栏**的操作仍抓不到（捕获端仍是页面 JS，不上全局钩子）。
7. **受控窗口最小化**：Win32 不投递，`win_last_reason=window_minimized` 并降级提示（与 AdsPower 实测一致）。
8. 指纹、代理、UA-CH 本版未改动。

## 六、装前动作

1. **先完全退出 FreePower**：托盘图标 → 退出，确认任务管理器里没有 `FreePower.exe` 残留。
2. **备份整个数据目录** `%APPDATA%\FreePower\`（含 `freepower.db-wal` / `freepower.db-shm`）。
3. 本版**不改数据库结构**（`deliver` 是同步设置字段，缺省即 `win32`），装错版本可直接装回，数据不用还原。

## 七、装后实测清单（出包前必做）

1. 开 3 个以上环境，主控窗口**盖住**受控窗口，在常用站点点击、滚动、打字、拖拽。
2. 在 iframe 里操作：带 reCAPTCHA 的登录页、钱包弹窗。
3. 组合键：Ctrl+A、Ctrl+C / Ctrl+V、Enter、Tab、方向键。
4. 有问题时读 `GET /api/v2/sync/status` 的 `windows[]`：`delivery_via`、`win_fail`、`win_last_reason`、`dropped_out_of_view`。
5. 想排除 Win32 投递的影响：同步设置改 `deliver: "cdp"` 重开同步对比（第 1、2 项修复仍生效）。

## 八、回退

- 只回退投递方式：同步设置 `deliver: "cdp"`。
- 整版回退：装回 `FreePower-0.4.7.12-setup.exe`。本版没改数据库结构，旧版本读新数据不会出问题。
