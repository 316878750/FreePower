# FreePower 0.4.7.9 升级说明

> 本版取代 0.4.7.8（0.4.7.8 没有对外发布，它和本版合并成一次交付，用户只需要装这一次）。
> **主改动两件事**：① 修好「窗口同步」页打不开的线上故障；② 修好「代理链某一跳要求认证却照样启动」的洞。
> 没动库结构、没动内核、没动指纹。

| # | 改了什么 | 为什么要改 |
|---|---|---|
| 1 | `web/pages/sync.js`：5 个派生函数挪到第一个 `await` 之前 | 点开「窗口同步」直接显示 `出错。页面加载失败：Cannot access 'isRunning' before initialization`，整页不可用 |
| 2 | 代理链：**任何一跳**认证失败（407）一律拒绝启动，并写明是第几跳 | 原来系统代理要求认证、而本机没存凭据时会**照样启动**——用户以为在走链，实际链没通，出口可能根本不是他要的那个 |
| 3 | `web/api.js`：网络失败的 `console.warn` 只打 `name`/`message` 两个字段 | 原来把整个 Error 丢进 console，devtools 一展开就是满屏英文堆栈 |
| 4 | 新增判据 `test/sync-page-import.test.mjs`（12 条） | 以前窗口同步页的判据**全是正则扫源码**，页面从没被真正求值过一遍，所以执行顺序的错一路漏到用户手上 |
| 5 | 判据 `test/proxy-chain.test.mjs` 从 30 条扩到 42 条 | 补上「链上第一跳 407 / 第二跳 407 都必须拒绝启动」；修掉一条会被**别人的浏览器进程**干扰的假红 |

---

## 1. 出了什么问题

### 1.1 窗口同步打不开（0.4.7.7 起）

装上 0.4.7.7 之后点开「窗口同步」，页面不是同步面板，而是：

```
出错。
页面加载失败：Cannot access 'isRunning' before initialization
```

**影响面**：只有「窗口同步」这一页。环境列表、打开环境、代理、API&MCP 都不受影响。
**数据**：不受影响，没有丢任何东西，也不需要重装环境或清缓存。

原因：`renderSync` 是 `async` 函数。修前第 88 行 `await reload(true)` 一挂起，函数体后半段
（包括第 152 行的 `const isRunning`）**还没执行**；但第 89 行的 `paintAll()` 已经在跑了，
它经 `paintTop` / `paintTable` / `paintStatus` 读到 `isRunning` —— 这一刻它还在 TDZ（暂时性死区），
于是抛 `Cannot access 'isRunning' before initialization`。
一句话：**`await` 之后的方法先跑，用到了下面才声明的 `const`。**

修法：把这 5 个派生函数（`running` / `nameOf` / `groupNameOf` / `selectedIds` / `isRunning`）
整体上移到第一个 `await` 之前，并加注释写明规则。它们只读 `state`、是纯函数，
**挪动不影响任何可观测行为**，窗口同步的行为与设计完全一致。

### 1.2 代理链某一跳要求认证，却照样启动（0.4.7.5 起就有的洞）

**场景**：环境勾了「多级代理」（hop0 = 本机系统代理，hop1 = 环境自己的代理），
而本机系统代理要求用户名密码、Windows 注册表里又没有存凭据。

**原来的结果**：系统代理回 407，我们的本地中继把它翻成 502 交给预检；
预检看到「拿到了 HTTP 响应」，就归成「探测源不可用（不是代理不通）」这一类**软失败**，
于是按「未验证」**放行启动**。

**为什么这是错的**：用户以为在走链，实际上链从头就没通，出口很可能是本机 IP。
这和我们早就定过的「内层（环境代理）认证失败不退回——那等于绕过用户配的代理」是同一条道理：
**链上任何一跳认证失败都不能放行。**

**现在的行为**：

- 链上**任何一跳**回 407 → 拒绝启动，报 `code=800003`、`reason=proxy_chain_hop_failed`，
  并带上 `failed_hop`（0 = 系统代理那一跳，1 = 环境代理那一跳）。
  错误文案会写成「代理链第 N 跳认证失败：…」。
- **502 不变**：代理接受了我们的 CONNECT、只是没能到目标，这类仍然按软失败放行
  （这是 0.4.7.5 修过的「探测源一挂就打不开」，这次**故意没有**把它改回硬失败）。

## 2. 用户可见的变化

| 场景 | 0.4.7.7 | 0.4.7.9 |
|---|---|---|
| 点开「窗口同步」 | 整页报错 | 正常显示面板（没开环境时显示「暂无已打开的浏览器环境」） |
| 多级代理 + 系统代理要求认证、没存凭据 | 照样启动（链没通） | **拒绝启动**，提示「代理链第 1 跳认证失败」 |
| 多级代理 + 环境代理认证失败 | 拒绝启动 | 拒绝启动（文案带「第 2 跳」） |
| 多级代理 + 代理回 502（目标到不了） | 按未验证启动 | **不变**，按未验证启动 |
| devtools 里看网络失败 | 一坨英文堆栈 | 一行 `[fp] 请求失败 /api/… { name: 'Error', message: '…' }` |

## 3. 升级方式

- 直接跑 `FreePower-0.4.7.9-setup.exe` 覆盖安装即可。**环境数据、代理、Cookie、指纹配置全部保留**，
  不需要先卸载，也不需要备份（本版不碰库结构）。
- 装完在「关于 / 版本」里应显示 `0.4.7.9`。
- 装完第一次点开「窗口同步」应该直接看到同步面板，不再出现上面那句报错。
- **如果你用的是多级代理**：升级后如果某个环境启动被拒、提示「代理链第 N 跳认证失败」，
  那是**本版修出来的正确行为**——说明这条链本来就没通。请去
  「设置 → 系统代理」确认系统代理是否需要账号密码，或者在环境里补上环境代理的账密。
  这类环境在 0.4.7.7 上是「能启动但出口不对」，比现在更危险。

## 4. 已知限制

1. **「页面能不能真加载出来」的门目前只给窗口同步页加了**，其它页面（环境列表、API&MCP 等）
   仍然只有静态检查。它们这一版没出过问题，但同一类「`await` 之后用到下面才声明的 `const`」
   的隐患，下次改动仍可能在别处出现。
2. **窗口同步真机行为本版没有重新验收全量**：本版只改了声明顺序，同步的点击、窗口映射、标签跟随
   逻辑一行没改；但「真开两个环境、真的同步点一次」这一步本轮只跑了真内核套件，没有重跑全量真站。
3. **判据里的「真加载」是 Node 的真 ESM 求值，不是真 Chrome**：能抓到 TDZ / import 解析 / 渲染抛错，
   抓不到「DOM 桩和真浏览器行为不一致」。真内核那套（`npm run smoke` 里的 `sync-*`）仍然要跑。
4. **代理链只支持 http 跳**：两跳里任何一跳是 socks5/https 会直接拒绝启动（这是原有行为，本版没改）。
5. 0.4.7.7 / 0.4.7.8 的其余已知限制**照旧全部适用**：起始页出口 IP 可能显示「未验证（探测源不可用）」、
   没开本地代理软件就没有链（自动退回直连）、HTTP 系统代理不当链用、站1 是 SPA 不能用 readyState 判断完、
   站1 有 2 个环境正文只收到 3339 字符。详见 `升级说明-0.4.7.7.md` §8。

## 5. 回退

退回到 **0.4.7.7 包**即可（`FreePower-0.4.7.7-setup.exe`），直接覆盖安装。
本版**没有动库结构、没有新增列**，旧版本读到新版数据没有任何兼容问题；反过来也一样。

**注意**：回退到 0.4.7.7 会把「窗口同步打不开」和「代理链认证失败照样启动」两个问题一起带回来。
如果只是想避开某个环境的代理链问题，**不需要回退**：在那个环境里把「多级代理」关掉，
或者补上系统代理的账密即可。

## 6. 判据

### 6.1 窗口同步（新增 `test/sync-page-import.test.mjs`）

用**真 ESM**（`data:` URL + 相对 specifier 改写成 `file://`，Node 原生求值，不是自研打包器 ——
自研打包器自己在 TDZ / 循环依赖 / export 分类上出过 bug，会「假绿」，正是这次漏掉的根因）
把 `web/pages/sync.js` 的整张依赖图加载起来，挂最小 DOM 桩，真跑 `renderSync()` 两次。

| 条目 | 钉住什么 |
|---|---|
| ① | 先自证「真 ESM 能抓 TDZ」（探针是确定会抛的形状，不用 await 版） |
| ②③ | 整张依赖图能加载、导出 `renderSync` |
| ④⑤ | `renderSync()` 跑完不抛、不是 TDZ 错 |
| ⑥⑦ | 页面真画出来（标题 +「暂无已打开的浏览器环境」），重复进入同样正常 |
| ⑧ | 页面发出的 console 全部干净 |
| ⑨-a / ⑨-b / ⑨-c | 日志门：子进程真读终端、长 base64 串 0 处；并自证「这双眼睛看得见」 |
| ⑩ | 网络失败的 `console.warn` 形状：不挂 Error、不带堆栈 |

**修前**：`3 passed, 4 failed`（④⑤⑦ 抛的就是用户看到的那句原文，⑥ 页面为空）。
**修后**：`12 passed, 0 failed`。
**⑩ 反向验证**：把 `api.js` 临时改回 `console.warn(..., e)` → ⑩ 变红（堆栈 60 行、长串 20 处）。

### 6.2 代理链（`test/proxy-chain.test.mjs`，30 条 → 42 条）

| 条目 | 钉住什么 |
|---|---|
| A | 两跳都真被走过、上一跳→下一跳对得上、凭据不串层、argv 里没有上游 host/port/账密 |
| B | 系统代理未启用 → 塌成单跳，不吃错 |
| C | hop0 回 502（代理是通的、只是没到目标）→ **放行启动** + 一条 `proxy_probe_unavailable` 软警告 + 不降级直连 |
| C2 | 链上**第一跳**（系统代理）407 → 拒绝启动，`failed_hop=0` |
| C3 | 链上**第二跳**（环境代理）407 → 拒绝启动，`failed_hop=1` |
| D | 起来之后关掉 hop0 → 请求失败、目标命中不增加（不回落直连） |
| E | 单跳 + 代理认证 → 走本地中继，内核只看到 127.0.0.1 |

**反向验证**：把认证失败的硬失败判定临时关掉 → C2 红 2 条、C3 红 2 条；恢复后 42/0。

另外修掉一条**假红**：「零内核进程」原来用「profile id 前 8 位做子串匹配」去数 chrome 进程，
用户本机开着 FreePower 时会把别人的浏览器进程也算进来（实测报 11 个，其实是用户 10053/10055 的环境）。
现在改成按 `--user-data-dir` **是否落在本用例自己的临时数据目录里**精确归类，
并且对「停止后进程回收」做轮询等待（回收是异步的，立刻数会数到正在退的进程）。

- `npm test`：末行 `57 passed, 0 failed`，`EXIT=0`。
- `npm run smoke`（真内核）：见下方读数。
