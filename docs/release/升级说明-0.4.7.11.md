# FreePower 0.4.7.11 升级说明

> 这一版只做一件事：**窗口同步在运行中跟着用户走**。
> 上一版（0.4.7.10）修的是「启动时选错了标签」，但那只对了一瞬间 ——
> 会话绑死在启动时那张 target 上，用户中途切标签 / 关标签 / 开新标签之后，同步就打在旧页上，
> 或者那张页已经没了、事件一条都进不来，而界面还显示「同步中」。
>
> 这一版的实现口径按逆向实测重写：见 `adspower-reverse/8.9.23/34-窗口同步真实行为.md`
> 与 `docs/29-窗口同步规格-按实测行为对齐.md`（R1–R8）。
>
> **第二轮（2026-11-21 晚）**：CEO 用真 `SendInput` + `PrintWindow` 逐像素验收，
> `--no-arrange`（两个窗口叠着，真实用法）下 S2/S3 红：受控窗口标题已经是 `B2`，
> 投递却一直打在 `B1`；两张标签同时报 `vis=visible focus=true`。
> 根因不在选标签逻辑，而在 **R7 的焦点模拟把可见性信号一起覆盖了**（见第二节「激活标签」）。

## 一、为什么这次能修对（先看事实）

AdsPower 的投递对象是**窗口句柄**（`Dll2.dll` 低级钩子 + `PostMessage`），**没有 target 概念**，
所以切标签 / 关标签 / 开新标签它全都即时跟上，不存在「绑错页」这回事。

我们走 CDP，天然是 target 语义，于是把「target 语义」换成「窗口语义」：

- **主窗口的每一张 page target 都装捕获**（不是只装可见那张）。真实用户输入本来就只会落在
  前台那张页上 —— 全装天然等价于「跟随激活标签」，不需要判断谁可见。
- **受控窗口每条事件派发前重新解析「当前激活 target」**（≤500ms 缓存，任何 target 生命周期
  事件立刻失效），而不是绑死启动时那张。

现场读数（CEO 在用户机器上实测，2026-11-21）：

```
/api/v2/sync/status
  running=true  events=21  forwarded=21  scheduler={sent:147, errors:0}
  master target_id=DB4B3123AD  url=https://app.startale.com/sign-up
        visible=true  confident=true  source=visible

主控窗口现在的标签（/json/list）
  1CEE7A58D2  https://defi.xstocks.fi/points
  55743DA1F8  http://start.freepower.test:53380/start?id=398346c1…
  → DB4B3123AD 已经不在窗口里了（那张标签被关掉/换掉了）
```

往主控**当前可见**的 xstocks 页注入 5 个事件，计数 delta=0（21→21）：
捕获脚本根本不在用户看的那张页上。

### 激活标签：改成「页面自己上报」（第二轮修的）

原来受控窗口「谁是当前激活标签」是主进程每 450ms 轮询 `document.visibilityState` 读出来的。
第二轮现场两张标签**同时**报 `visible`，轮询只能退回列表顺序第一张 —— 一直投 B1。

实测根因（`.tmp/e2e/vis2.cjs`，真内核 157.0.8103.78）：

```
后台页 未开焦点模拟: {"vis":"hidden","focus":false}
后台页 开了焦点模拟: {"vis":"visible","focus":true}   ← R7 一开就翻成 visible
后台页 关掉焦点模拟: {"vis":"hidden","focus":false}
```

`Emulation.setFocusEmulationEnabled(true)` 不只手抖 `hasFocus`，它把 `visibilityState` 也一起覆盖。
所以「给新开的标签也补开焦点模拟」= 每张页都报可见 = 轮询彻底失效。

改成事件驱动：

- 每张受控页装一段**上报脚本**（`buildActivationScript()`），监听 `visibilitychange` / `focus` /
  `blur` / `pageshow`，一变就通过 CDP binding 上报 `{v, f}`；
- 主进程**只认 `v === 'visible'`**：谁最后变成可见，谁就是当前激活标签
  （切走时不动作，避免「旧的先报 hidden 把目标清空」的空窗）；
- `choosePage()` 的优先级里，事件上报的那张排在**最前面**，轮询降级为兜底
  （`signal: 'event'` / `'poll'` 在 status 里能分清）；
- 焦点模拟跟着投递目标走：换目标时**先给新页开、再关旧页**，旧页立刻恢复 `hidden`，
  不会在下一轮轮询里被重新选回去。

上报脚本与捕获脚本同一套纪律：抓完 binding 引用立刻 `delete`，页面 own names 里不留名字；
脚本第二次跑时 `window[名字]` 已是 undefined，直接 return —— 天然幂等，不需要任何标记位。

`alive` **是读页面里的探针得到的**，不是看进程在不在：
捕获脚本在文档里放一个 `{at, off}` 对象，`at` 每次上送刷新；主进程读得到 = 脚本真的在这个文档里跑过。

### 与规格的一处刻意偏离（必须说清）

规格写的是页面里留 `window.__fpSyncProbe`。**我们没有用固定名，也没有用字符串名**，
用的是 **Symbol 键 + 不可枚举**（`Object.defineProperty(window, Symbol(), {enumerable:false})`）。
主进程按「枚举 own symbols 找一个 `{at: number, off: function}` 形状的对象」读它，不需要名字。

理由：

- 固定名（`__fpSyncProbe`）本身就是检测面：这个属性会在整个会话期间留在用户每一个主控标签上，
  站点一句 `if (window.__fpSyncProbe)` 就能认出「这是被自动化接管的浏览器」；
- 第一版我用了「每会话随机的 `_s<8hex>` 字符串名」，**被仓库里现有的 P0 判据当场抓出来**：
  `Object.getOwnPropertyNames(window)` 里多一条 `_s<8hex>` 且整个会话期间都在，
  比 binding 名（抓完就 delete）还糟。已改成 Symbol 键，判据回到 50/50 全绿。

语义等价：读得到 = 脚本在这个文档里活着；会话结束时 `off()` + `delete` 一并摘掉。
残留暴露面如实写：`Object.getOwnPropertySymbols(window)` 能看到一个无名 Symbol，其值带 `off()`。
真实站点几乎不枚举 window 的 symbol —— 这比「固定字符串名」严格更安全。

## 三、状态接口

### 会话级（`GET /api/v2/sync/status`）

| 字段 | 含义 |
| --- | --- |
| `alive` | 主控当前投递页里的探针读到了没有（**读 marker**，不是看进程） |
| `targets_attached` | 装过捕获的主控标签数 |
| `last_capture_target_url` | 探针所在那张页的真实地址 |
| `events_from_current_target` | 当前主控 target 贡献了多少条事件 |
| `last_event_at` / `stale_ms` | 最后一条事件时间 / 距现在多久（没在跑时为 0） |
| `skipped_no_target` | R2 解析不到受控目标而跳过的事件数 |
| `dropped_out_of_view` | R3 坐标落在受控视口外被丢弃的事件数（正常现象，但要能看见） |
| `capture_reinstalled` | R6 看门狗重装捕获的次数（>0 说明前面有东西在丢） |
| `probe` | 探针形状（恒为 `"symbol"`：Symbol 键 + 不可枚举，没有字符串名可暴露） |
| `master_pages` / `master_page_state` / `master_visible_target_id` / `master_visible_url` | 主窗口有几张标签、当前可见的是哪张 |
| `hint` | 给人看的一句话（没问题时是 `null`） |
| `end_reason` / `end_message` / `last_end` | 会话为什么结束 |

`gated` / `gate_reasons` 保留形状但**恒为 0**：R1 明确不要「只转发可见页」的闸门
（后台页不会有人按键，加闸门只会多一个「读不到就全丢」的失败模式）。

### 窗口级（`windows[]`）

| 字段 | 含义 |
| --- | --- |
| `alive` | 这个 target 现在还在不在 |
| `events_from_this_target` | 这张页贡献了多少条事件 |
| `pages` | **逐张明细**：`[{target_id, url, visible, alive, active, is_current}]`（第二轮从「一个数字」改成数组 —— 只给张数等于让人去 `/json/list` 人肉映射 target_id，那正是「投错标签」查不出来的原因） |
| `pages_count` | 张数（老读数的等价字段） |
| `target_signal` / `activation` | 「当前激活标签」靠什么定的：`event` = 页面自己上报，`poll` = 主进程轮询兜底 |
| `delivery_target_url` / `delivery_ok` | 受控窗口**实际投到哪张页** / 投递成功过没有 |
| `skipped_no_target` / `dropped_out_of_view` / `no_viewport` | 这个窗口的三类「没投出去」计数 |
| `degraded` | 这个窗口为什么不可用（人话；受控窗口 0 张页时**可推导**，不依赖回调） |

### 新增 `POST /api/v2/sync/selftest`

逐窗口、逐 page target 读一次事实，**只读、不改状态**：

```json
{ "running": true, "probe_name": "_s9bce0a1a",
  "windows": [
    { "profile_id": "…", "role": "master", "target_id": "…",
      "target_url": "https://…", "visibility_state": "visible",
      "capture_installed": true, "is_delivery_target": true,
      "viewport": { "vw": 1500, "vh": 780 } } ] }
```

`capture_installed` 只有主控有意义（受控窗口按设计零注入，值是 `null`，不是 `false`）。
用户报「没反应」时，先看这个接口，不用再靠映射 target_id 猜。

## 五、已知差异 / 限制（照旧写全，不假装对齐）

- **受控侧 `buttons` 恒为 1**：AdsPower 实测如此，我们没有复刻这个「假值」，
  按主控真实 `buttons` 位掩码投递。
- **chrome 区域（地址栏 / 标签栏）捕不到**：我们用页面级事件，AdsPower 是窗口级钩子。
  在地址栏里打字不会同步 —— 与「同步的是网页内容」这个产品语义一致。
- **受控窗口最小化时不停投递**：只记 `window_minimized` 语义（读不到视口时丢鼠标事件）。
  AdsPower 实测是完全不投递，我们没强制停（停了会导致恢复窗口后要等下一轮才继续）。
- **跨 DPI 未处理**：两个窗口在不同缩放比的显示器上时，1:1 坐标会偏。
- **轮询间隔 450ms**：只在「页面还没上报过激活」时兜底用；上报到了就是即时的。
  最坏情况下（上报脚本装不上）切完标签立刻敲的第一个字符可能丢（最多半秒）。
- **受控页上多一个 CDP binding**：与捕获那个名字不同，抓完引用立刻 `delete`，
  页面 own names 里只存活同一任务内几微秒。这是「事件驱动定激活标签」的必要通道，
  也是本版新增的**唯一**页面暴露面（`visibilitychange` 上报要用它）。
- **`/sync/arrange` 在「没有桌面壳」的进程里读不到屏幕尺寸**：`displays.json` 是桌面壳写的，
  纯服务进程（`node src/main.js`）读不到，`autoFit` 会退到系统最小窗口（516×200）。
  产品侧正式使用有桌面壳，不受影响；开发侧给 `.tmp/e2e/iso/data/displays.json` 补一份
  3440×1392 的 work area 之后，arrange 排出 1720×1392。
- **验收脚本不靠人记得补屏幕尺寸**：`.tmp/e2e/run.cjs` 自带三道自证 ——
  ① 滚轮点按窗口**实际尺寸**算（`y = min(320, 窗口高-80)`），不再写死坐标；
  ② 每次滚轮前用 `WindowFromPoint` 确认该点**真的落在主控窗口上**，落错窗口直接报错中止；
  ③ 每次滚轮后必须看到主控捕获的 `events` 增长，`events +0` 直接判失败。
  这样「受控页滚了」不会再是 OS 滚轮直接打在受控窗口上冒充同步生效。
- **同一次同步里新增的受控窗口不会自动加入**（窗口集仍是启动时定的），
  但**同一个窗口里换标签会自动跟随**。
- **主控规则保持「勾选顺序第一个为主控」**（与 AdsPower 一致），界面上有标注。
- 主窗口停在起始页时**不会自动切回业务页**：起会话前拒绝 + 运行中在 `hint` 里说人话。
- 指纹、代理、UA-CH 等本版未改动。

## 六、装前动作

1. **先完全退出 FreePower**：主窗口关掉不算退出，右下角托盘图标 → 退出，确认任务管理器里没有 `FreePower.exe` 残留。
   安装器覆盖正在运行的 exe 会失败或留下半个文件。
2. **备份整个数据目录**：`%APPDATA%\FreePower\`（含旁文件 `freepower.db-wal` / `freepower.db-shm`，只拷 `.db` 会丢最新写入）。
3. 本版**不改数据库结构**，所以装错版本也能直接装回旧的，数据不用还原。

## 七、回退

装回 `FreePower-0.4.7.10-setup.exe`（或更早的 0.4.7.9）即可。
本版**没有改数据库结构**（只新增运行时字段，不进库），旧版本读新数据不会出问题。
