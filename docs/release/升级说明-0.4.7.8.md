# FreePower 0.4.7.8 升级说明

> 本版取代 0.4.7.7。**主改动只有一件事**：修好「窗口同步」页打不开的线上故障。
> 没动任何数据、没动库结构、没动内核、没动代理链路。

| # | 改了什么 | 为什么要改 |
|---|---|---|
| 1 | `web/pages/sync.js`：5 个派生函数挪到第一个 `await` 之前 | 点开「窗口同步」直接显示 `出错。页面加载失败：Cannot access 'isRunning' before initialization`，整页不可用 |
| 2 | `web/api.js`：网络失败的 `console.warn` 只打 `name`/`message` 两个字段 | 原来把整个 Error 丢进 console，devtools 一展开就是满屏英文堆栈，排障反而更难找 |
| 3 | 新增判据 `test/sync-page-import.test.mjs`（12 条） | 以前窗口同步页的判据**全是正则扫源码**，页面从没被真正求值过一遍，所以这次执行顺序的错一路漏到用户手上 |

---

## 1. 出了什么问题

装上 0.4.7.7 之后点开「窗口同步」，页面不是同步面板，而是：

```
出错。
页面加载失败：Cannot access 'isRunning' before initialization
```

**影响面**：只有「窗口同步」这一页。环境列表、打开环境、代理、API&MCP 都不受影响。
**数据**：不受影响，没有丢任何东西，也不需要重装环境或清缓存。

## 2. 为什么会这样

`renderSync` 是个 `async` 函数，修前长这样（行号为修前）：

```js
async function renderSync(host) {
  mount(host);
  …
  await reload(true);   // 88 行
  paintAll();           // 89 行 ← 从这里一路调到下面的 isRunning
  …
  const isRunning = …;  // 152 行
}
```

`await reload(true)` 一挂起，函数体后半段（包括第 152 行的 `const isRunning`）**还没执行**；
但 88 行之后的 `paintAll()` 已经在跑了，它经 `paintTop` / `paintTable` / `paintStatus`
读到 `isRunning` —— 这一刻它还处在 TDZ（暂时性死区，声明了但没初始化），于是抛
`Cannot access 'isRunning' before initialization`。

一句话：**`await` 之后的方法先跑，用到了下面才声明的 `const`。**
`running` / `nameOf` / `groupNameOf` / `selectedIds` 也是同一个坑。

## 3. 改成什么样

把这 5 个派生函数整体上移到第一个 `await` 之前（紧跟 `mount(...)` 之后），并加注释写明规则：

> 凡是 `paintAll` / `paintTop` / `tick` 用到的派生函数，都必须定义在第一个 `await` 之前；
> 不要写成「先 await 再 paint」。

它们只读 `state`、是纯函数，**挪动不影响任何可观测行为**，所以本版窗口同步的行为与设计完全一致。

## 4. 顺带：`web/api.js` 的日志形状

```js
// 修前
console.warn('[fp] 请求失败', path, e);
// 修后
console.warn('[fp] 请求失败', path, { name: e?.name, message: String(e?.message || e) });
```

**用户可见的差别**：打开 devtools 时，网络失败只留一行 `[fp] 请求失败 /api/… { name: 'Error', message: '…' }`，
不再跟一坨 40 行调用栈。**界面上显示的中文提示完全不变**（这条 warn 从来只进 console，不进界面）。
只改了这一个参数，别处没动。

## 5. 升级方式

- 直接跑 `FreePower-0.4.7.8-setup.exe` 覆盖安装即可。**环境数据、代理、Cookie、指纹配置全部保留**，
  不需要先卸载，也不需要备份（本版不碰库结构）。
- 装完在「关于 / 版本」里应显示 `0.4.7.8`。
- 装完第一次点开「窗口同步」应该直接看到同步面板（没开环境时显示「暂无已打开的浏览器环境」），
  不再出现上面那句报错。

## 6. 已知限制

1. **本版只修了窗口同步这一页**。「页面能不能真加载出来」的门目前只给窗口同步页加了，
   其它页面（环境列表、API&MCP 等）仍然只有静态检查。它们这一版没出过问题，但同一类
   「`await` 之后用到下面才声明的 `const`」的隐患，下次改动仍可能在别处出现。
2. **窗口同步真机行为本版没重新验收**：本版只改了声明顺序，同步的点击、窗口映射、标签跟随
   走的是同一套代码，逻辑一行没改；但「真开两个环境、真的同步点一次」这一步本轮没有重跑全量真站。
3. **判据里的「真加载」是用 Node 的真 ESM 求值，不是真 Chrome**：能抓到 TDZ / import 解析 / 渲染抛错，
   抓不到「DOM 桩和真浏览器行为不一致」这一类问题。真内核那套（`npm run smoke` 里的 `sync-*`）仍然要跑。
4. 0.4.7.7 的其余已知限制**照旧全部适用**，本版没有改：起始页出口 IP 可能显示「未验证（探测源不可用）」、
   没开本地代理软件就没有链（自动退回直连）、HTTP 系统代理不当链用、站1 是 SPA 不能用 readyState 判断完、
   站1 有 2 个环境正文只收到 3339 字符。详见 `升级说明-0.4.7.7.md` §8。

## 7. 回退

退回到 **0.4.7.7 包**即可，直接覆盖安装。
本版**没有动库结构、没有新增列**，所以旧版本读到新版数据没有任何兼容问题；
反过来也一样，回退后再升上来也不会有数据问题。回退不需要备份、不需要清数据。

如果只是想绕过窗口同步这一页，**不需要回退**：其它功能本来就没受影响。

## 8. 判据（本版新增 / 重跑）

新增 `test/sync-page-import.test.mjs`，已并入 `npm test`。用**真 ESM**（`data:` URL + 相对
specifier 改写成 `file://`，Node 原生求值，不是自研打包器 —— 自研打包器自己在 TDZ / 循环依赖 /
export 分类上出过 bug，会「假绿」，正是这次漏掉的根因）把 `web/pages/sync.js` 的整张依赖图加载起来，
挂最小 DOM 桩，真跑 `renderSync()` 两次。

| 条目 | 钉住什么 |
|---|---|
| ① | 先自证「真 ESM 能抓 TDZ」（探针是确定会抛的形状，不用 await 版） |
| ②③ | 整张依赖图能加载、导出 `renderSync` |
| ④⑤ | `renderSync()` 跑完不抛、不是 TDZ 错 |
| ⑥⑦ | 页面真画出来（标题 +「暂无已打开的浏览器环境」），重复进入同样正常 |
| ⑧ | 页面发出的 console 全部干净 |
| ⑨-a / ⑨-b / ⑨-c | 日志门：子进程真读终端、长 base64 串 0 处；并自证「这双眼睛看得见」（接收计数 > 0、注入长串数得回、真漏一段能抓到） |
| ⑩ | 网络失败的 `console.warn` 形状：不挂 Error、不带堆栈 |

**修前**：`3 passed, 4 failed`，④⑤⑦ 抛的就是用户看到的那句原文，⑥ 页面为空。
**修后**：`12 passed, 0 failed`，`EXIT=0`。
**⑩ 反向验证**：把 `api.js` 临时改回 `console.warn(..., e)` → ⑩ 变红（堆栈 60 行、长串 20 处）；
改回白名单 → 转绿。

`npm test` 末行 `57 passed, 0 failed`，`EXIT=0`；输出里长 base64 串 0 处。
