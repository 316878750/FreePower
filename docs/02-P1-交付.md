## 1. 这版做了什么

### 1.1 存储换血：schema 事实源 = `packages/profile/`

- `src/store/db.js` 改为从 `packages/profile` 取 DDL 建表，profile 记录是**平铺列 + 一个 `fingerprint_config` JSON 列**。
- `profiles.payload` 整包 JSON 模型作废，但**没删**：启动时自动迁移，旧表留作 `profiles_legacy_v0`，迁移结果写进 `migration_meta`。
- 迁移实测（造了一个老库跑通）：字段逐项映射，`ua / timezone / webgl vendor / 种子 / 屏幕 / 内核版本 / 代理` 全部保留，核心数从 `"12.0"` 还原成 `12`（TEXT 列存的数值型枚举，读取时统一 coerce）。
- 老分类 `groups(group_id, group_name)` → 新 `groups(id, name)`，同样自动搬。

### 1.2 指纹生成器改成平铺字段模型

`src/fingerprint/generate.js` 现在直接输出字段表里的键（`ua / client_hints / timezone / screen_resolution / webgl_config / canvas_id …`），
注入层需要的嵌套视图由 `src/fingerprint/view.js` 从平铺字段派生 —— 一份数据两个视图，不重复造状态。

### 1.3 一致性校验接进启动前

`checkProfile()` 在 `startProfile` 第一步跑，**一致性告警一律升级为错误**（一条对不上就不让起）。
实测：把 `platform` 改成 MacIntel、UA 留着 Windows，start 返回 `800005` 并列出三条冲突：

```
platform: UA 声明 /Windows NT/i 但 platform=MacIntel
client_hints.platform: platform=MacIntel 期望 UA-CH platform=macOS，实际 Windows
client_hints.ua_full_version: UA 报 Chrome/131 但 ua_full_version=157.0.8103.40
```

### 1.4 启动/关闭/回收 + 幂等

- `--user-data-dir` **由系统算**（`data/profiles/<profile_no>_<id前8>/userdata`），不接受用户覆盖。
- `--remote-debugging-port=0` + 读 `DevToolsActivePort` 回读真实端口。
- 启动时 Chrome 自带的空白页在 `setAutoAttach` 之前就存在、脚本已跑过一轮 → 现在会对这类「已有页面」先装配再重载一次，堵住「首帧原始指纹」漏点。
- 关闭：先 `Browser.close` 让 cookie 落盘，再 `taskkill /T /F` 兜底，最后校验主进程退出 + 扫残留。
- 幂等：同一环境重复 start 直接返回现成 `ws`，不新开进程（实测 `already_running: true` 且 pid 不变）。

## 2. 契约对齐（拆解手已实测的部分）

| 项 | 实现 |
|---|---|
| start 响应 | `{ ws: { puppeteer, selenium }, debug_port, webdriver }` |
| `ws.selenium` | 只放 `host:port`，不带协议 |
| `debug_port` | **字符串** |
| 幂等 | 已启动返回现成 ws，不开第二个 |
| `launch_args` | 内部统一数组；v1 出站 `JSON.stringify`，v2 出站数组 |
| `password_filling` | 内部只留一个布尔 `disable_password_filling`，边界翻转，出站两个字段都给 |
| 字段类型 | `DisabledFonts` 存字符串；`AudioFp`/`ClientRectFp` 用有符号 32 位整数；`allow_scan_ports=""` = 一个端口都不许 |

错误码（前四个已实测存在，含义按实测报文反推，标【推测】）：

| code | 含义 | 场景 |
|---|---|---|
| -1 | 通用失败 | 参数/内部错误 |
| 100001 | profile 不存在 | detail/update/start 传了不存在的 id |
| 100002 | 参数非法 | 缺 `user_id` / body 不是 JSON |
| 800002 | 环境未运行 | stop 一个没启动的环境 |
| 800003 | 启动失败 | 内核缺失、端口超时、进程起不来 |
| 800005 | 一致性校验不通过 | 启动前冲突 |

## 4. 已知缺陷（下一阶段处理，不藏）

1. **一致性告警全部当错误**，会误挡一些「其实可接受」的组合（比如语言↔时区软规则）。P2 要分级：硬冲突阻断、软冲突只警告 + 允许强制启动开关。
2. **注入只覆盖 page target**（P1 当时状态）。Worker / AudioWorklet / SharedWorker 当时没接（双 Realm 检测会看到两套实现），这是 CDP 路线已知盲区，文档标黄。
   → **P7 已解决**：三类 worker + 嵌套 worker 都能在脚本首行之前注入；AudioWorklet 明确 `none`（音频指纹本体在主帧，不受影响）。见 [P7 文档](08-P7-双Realm与AudioWorklet.md)。
3. **用户 `launch_args` 只存不生效**：没有做白名单 merge，也没进命令行。P2 补白名单（`--load-extension` 等 6 个）与保护名单（`--user-data-dir`/`--lang`/`--profile` 一律丢弃）。
4. **字体仍是 `["all"]`**：不伪装，自检页到时候标黄。
5. **代理只有 `--proxy-server` 与 CDP 认证**，没有启动前出口探测、没有 fail-closed（代理挂了会直连）。P3 必做，属高危项。
6. **`stop` 偶发慢**：Windows 下 Chrome 子进程退出有延迟，已加 1.5s 等待 + 残留扫描，但不是硬保证。
7. **迁移后旧表未删**（`profiles_legacy_v0` 留着做回滚），确认 P2 稳定后再删。
8. `tags` / `proxies` / `kernels` / `launches` 表已建但还没接业务。
