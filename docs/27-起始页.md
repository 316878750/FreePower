# 起始页（0.4.7.3 任务 B）

> 一句话：**`open_urls` 为空时第一张不再是 `about:blank`，而是本机服务进程出的起始页**；
> 它在**代理全挂**时也能打开，因为探测全在服务进程做、页面自己一个外连都不发。

## 1. 根因（为什么「打开指纹显示的是空白」）

`src/runtime/manager.js` 老代码只有这一行：

```js
const firstUrl = urls[0] || 'about:blank';
```

用户库里 **102 个环境有 101 个 `open_urls` 是 `[]`**（只有一个是配了 example.com 的）。
所以就算代理修好了（见 [docs/26](26-带凭据代理本地中继.md)），打开还是白屏 —— 用户会以为没修。

对手的做法（逆向 08/09 已核）：第一张是 `https://start.adspower.net/?id=<env>&host=localhost:20725`，
且启动参数里 `--proxy-bypass-list` **明确放行该域名**，所以代理挂了那张页照样能开。

## 2. 我们的做法

| 关注点 | 做法 |
|---|---|
| 页面从哪来 | `GET /start?id=<profile_id>&sig=<签名>`，**本机服务进程出纯 HTML**，不要 `api_key` |
| 防跨站读 | HMAC-SHA256 签名绑环境 id，24h 有效；密钥 `data/start.secret`（32 字节、0600） |
| 页面内容 | 环境名、代理 `host:port`、**期望出口**（`profile.ip`/`ip_country`/`ip_city`）、**实测出口**（服务进程探测 + 时间 + 延迟）、内核版本、UA |
| 代理不通 | 状态条红字「代理未连通：<原因>」+ 代理那一行照常显示 —— 不空白、不是 Chrome 错误页 |
| 页面外连 | **零**。CSP `default-src 'none'`，内联脚本只 `fetch('/start/data')`（同源） |
| 重新检测 | 按钮 → `GET /start/data?id=&sig=&force=1`；不点则读 15 秒缓存 |
| 凭据 | 不显示。只写「（带用户名密码）」；页面/JSON 里都查不到账号密码 |

### 怎么在「代理全挂」时还能打开（关键，别改回去）

实测三组（真内核 157.0.8103.78，代理指向死端口 `http://127.0.0.1:9`）：

| bypass 写法 | 结果 |
|---|---|
| `<-loopback>` | `chrome-error://chromewebdata/`，`ERR_PROXY_CONNECTION_FAILED` —— **起始页打不开** |
| `<-loopback>;127.0.0.1` | 能开，但 **loopback 的 fail-closed 丢了** |
| `<-loopback>;start.freepower.test` + `--host-resolver-rules=MAP start.freepower.test 127.0.0.1` | 能开，**且 127.0.0.1 仍走代理** ← 采用 |

采用第三条的理由：`test/smoke.mjs` 钉着「连 `127.0.0.1` 也走代理（没有 loopback bypass）」，
那是代理不泄漏的底线，不能为了起始页破掉。假域名 `.test` 是保留域、公网解析不到，
只在**我们的内核进程内**被钉到回环（不改系统 hosts、不影响别的浏览器）。

## 3. 触发规则（CEO 拍板，别自己改）

- `open_urls` 为空 → 第一张是起始页；
- `open_urls` 有值 → **行为与以前逐字节一致**，不多开；
- 设置页开关「总是打开起始页（与 AdsPower 一致）」**默认关**；打开后 = 起始页 + 原有启动网址（起始页在第一张）。

`manager.injectAndOpen` 里的落点：

```js
const wantStartPage = urls.length === 0 || alwaysStart;
const tabs = startUrl ? [startUrl, ...urls] : urls.slice();
const firstUrl = tabs[0] || 'about:blank';
```

- **A 层**（`npm run test:start-page`，不起内核）**57/57**：签名 5、内容 7、静态零外连 7、

  与窗口同步的相互作用 7。
- **B 层**（`npm run test:start-page-kernel`，真内核）**36/36**：
  - 红① 代理不通 + `open_urls` 空 → 第一张是起始页（不是 `about:blank`、不是 `chrome-error`），
    页面有「代理未连通」+ `socks5://127.0.0.1:9` + 原因；
  - 红④ 同一场景下起始页**照样打得开**（bypass 生效，真内核）；
  - 红② 带账号密码的 socks5（走中继）+ `open_urls` 空 → 起始页显示实测出口 `203.0.113.66`，
    与 `profile.ip` 一致；上游确实收到了环境账密；
  - 红③ `open_urls` 有值 + 开关关 → 只有那一张，**没有**起始页；
  - 开关开 → 两张（起始页第一张 + 启动网址）。
- **启动标签**：`npm run test:startup-tabs` **12/12** 没被改坏。

## 5. 起始页与窗口同步的相互作用（0.4.7.3 实测踩到的坑，别改回去）

起始页是**我们自己的 UI**，不是用户的业务页。它现在是每个环境的第一张标签，
所以凡是「挑一张真页面」的启发式都必须跳过它：

- `src/sync/session.js` 的 `pickPageTarget`：不跳过 → 同步目标被选成起始页，
  用户的点击/按键全落在起始页上，**表现就是「同步起来点哪都没反应」**。
  0.4.7.3 第一轮 `npm run smoke` 实测 7 条红（`受控窗口 hits=[]`、`受控=""`、`move=0`、`scrollTop=0`），
  修完 `test:sync-kernel` 39/39。
- `src/sync/batch-show.js` 的 `pageTargetOf`：同上。
- `src/sync/tabs.js` 的 `planUnify`：两边各自一张起始页（id/签名/端口都不同）时**不互相导航** ——
  照字面比一定不相等，硬导航过去只会让受控窗口显示一张 403 的起始页。
  业务页那几条序号照旧。

判定统一用 `src/start/host.js` 的 `isStartPageUrl()`（只认 `http://start.freepower.test[:port]/...`，
不误伤用户自己的同名路径）。

## 6. 已知边界

1. 起始页只在 `open_urls` 为空时自动出现（默认）；要看「总是打开」得去设置页开。
2. 签名 24h：一直开着的旧标签超过 24h 点「重新检测」会 403，重开即可。
3. 探测 15 秒缓存；代理不通时**不猜**出口 IP（不会把宿主 IP 当环境 IP 显示）。
4. 页面上的时间是**环境自己的时钟**（按环境时区），不是宿主时间。
5. 如果代理侧把 `*.test` 整个拦掉，起始页会被代理拦下来（只影响这种极端配置）。
