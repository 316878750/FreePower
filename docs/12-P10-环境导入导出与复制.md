# P10：环境导入 / 导出 / 复制 + cookie 导入 / 导出

> 这一版补的是三个「拿 AdsPower 一比就能看出来的完成度缺口」：环境导入/导出、cookie 导入/导出、环境复制。
> 契约形状**没改**（`imported` 在顶层、`seeds_regenerated`、`code:800002` 报「没在跑」等都是照验收门写的）。
> 契约之外补了 AdsPower `.txt` 互操作（第七节），并修了三类真缺陷：代理字符串被静默丢、cookie 对象数组被写成 `[object Object]`、`sameSite` 被补成 Lax / 分区键丢失。

## 一、这一版做了什么

| 缺口 | 以前 | 现在 |
|---|---|---|
| 环境导入/导出 | 无。只能一个个手填，或直接改 SQLite | JSON 三种 body 形状都认；`export` 带我方字段 + AdsPower 兼容键；往返逐字段 0 差异。另有 AdsPower `.txt` 块格式双向互操作 |
| cookie 导入/导出 | 只有一个 `/cookies` 读登录 cookie **文本** | 真内核 CDP 读/写、两条路由、json + netscape 两种格式、写入后回读校验；`sameSite` 四值、分区键双向 |
| 环境复制 | 无（只能新建一个再手抄 11 组分栏） | 指纹配置原样、`fp_seed` 与**四个**噪声种子整组重生 |

三个操作的语义必须分清，混淆会出事：

- **导出/导入 = 搬运**：`fp_seed` 和四个种子一个都不动。同一个「人设」换台机器继续用，噪点哈希必须一模一样。
- **复制 = 克隆配置、换掉指纹种子**：配置（UA / 时区 / 屏幕 / 核数 / 字体 / 代理…）原样，**噪声源头全换**。复制出来的是「同一个配置下的另一个人」。
- **cookie 不是环境数据**：它在内核里，随环境跑起来才有。

## 二、导入：三种 body 形状、未知字段只告警

`POST /api/v1|v2/browser-profile/import`（别名 `/api/v1/user/import`）

认这三种（`src/api/routes.js: extractImportList`）：

```jsonc
{ "list": [ {...}, {...} ] }
{ "data": { "list": [ {...} ] } }
[ {...}, {...} ]                      // 裸数组
```

规则：

- 单次最多 1000 条，超了 `100002`（不半途写一半再抛）。
- **一条失败不影响其余**：`imported` / `failed` 各自计数，`failed` 里带 `index` 与原因；整体 `code` 仍是 0（部分失败不算接口失败 —— 这一点是门的要求，也是「批量导入」的常识）。
- **未知字段只进 `warnings`**，不报错。实测文案：`第 1 项：未知字段 unknown_field_xyz（已忽略）`。这是为了让 AdsPower 导出的文件（字段比我们多）能直接喂进来。
- 导入会给**新的** `profile_id` / `profile_no` / 创建时间；其余字段（含 `fp_seed`、`canvas_id`、`webgl_image_id`、`audio_id`、`client_rects_id`、`login_cookie`）原样落库。

代理字段两种位置都认：顶层 `proxy_host/proxy_port/proxy_user/proxy_password`，或 `fingerprint_config` / `user_proxy_config` 里那一份。归一化成我们的 `proxy_config`：

```json
{"proxy_soft":"other","proxy_type":"http","host":"127.0.0.1","port":18080,"username":"pu","password":"pp","proxy_id":""}
```

`proxy_soft` 缺省 `other`，`proxy_type` 缺省 `http`，`proxy_id` 用「host:port:username」算稳定 id（同一代理重复导入不会产生一堆重复记录）。

## 三、导出：一份记录里放两份键

`GET|POST /api/v1|v2/browser-profile/export`（别名 `/api/v1/user/export`）

- POST `{"profile_id": ["id1","id2"]}`；GET `?profile_id=a&profile_id=b`，逗号串 `?profile_id=a,b` 也认。
- 返回 `{list, count, missing}`。不存在的 id 进 `missing`，不抛错（批量导出时一条脏 id 不该毁掉整批）。

每条记录 = `present(p,'v2')` + 在**顶层**和 `fingerprint_config` 里**各放一份** AdsPower 兼容键：

```
proxy_type / proxy_host / proxy_port / proxy_user / proxy_password   // 密码明文
```

为什么不放一份：AdsPower 的文件两个位置都出现过，逆向样例还没定稿；导入侧两种位置都收，导出侧两种位置都给，先把「能互通」这条做实。

`screen_resolution` 保留在 API 边界（v1 形状），同时 `fingerprint_config` 里也有 `screen` 对象 —— 验收门 E2 判的是 `screen_resolution`。

**安全提醒（也写进 README 第 33 条）**：导出文件里含代理密码明文。本地 API 强制 `api_key`、只绑 `127.0.0.1`、校验 Origin，但导出文件本身**不是可以随便分享的东西**。

## 四、复制：为什么必须换四个种子

`POST /api/v1|v2/browser-profile/copy`（别名 `/api/v1/user/copy`）

返回新 `profile_id` + `seeds_regenerated: true` + `cookies_copied`。

`fp_seed` 换成 `newSeed()`，再由它**派生**出 `canvas_id / webgl_image_id / audio_id / client_rects_id` 四个种子（`deriveNoiseSeeds`）。四个种子是同一份 seed 派生出来的，只换 canvas 会让副本在 WebGL 图像噪声、音频噪声、元素矩形噪声上仍然与源同源 —— 等于主动告诉风控「这两个账号是同一台机器」。

**这条要求写进设计依据**：只重生 canvas 是个假动作。「造一整套假设备」不如「给真实设备改名」隐蔽；而「复制了配置却留着同一份噪声种子」比两者都糟，因为它看起来像两个账号、实际是同一台机器。

真机实测（同一台机器、同一个内核，`npm run test:fileio`；每次跑都是新建环境、新种子，哈希值本身会变，判据是「往返/重启 源=源、副本≠源」）：

| 维度 | 源 | 副本 |
|---|---|---|
| canvas | `16dff5fe` | `165ca0b2` |
| webgl_image | `544ec14b` | `699b242f` |
| audio | `037562a4` | `1926e97e` |
| client_rects | `8fec1f87` | `5ecee3b7` |
| UA | Chrome 157 同串 | **相同** |
| 时区 / 屏幕 / 核数 | `Europe/Berlin` / `1920_1080` / `8` | **相同** |

四个哈希全不同、配置项全相同 —— 这就是「克隆配置、换噪声源头」的定义。种子层面对账：`seed [-1249206965 → 1690360056]`、`canvas [902213743 → 1892071956]`、`webgl [96237705 → -1472874214]`、`audio [-64281013 → 1897330552]`、`rects [1130547193 → -1378544766]`。

`copy_cookies`：

- **默认关**。打开时必须**源环境在运行**，否则直接 `800002`（先判、再建副本，避免留一个半成品环境）。
- 读到的 cookie 以「登录 cookie 文本」回写到新环境的 `login_cookie`（`/api/v2/browser-profile/cookies` 可读），**不是**把内核 SQLite 复制过去（那份数据既加锁又不完整）。
- 需要副本启动后原样带登录态，就在副本启动后用 `cookie/import` 再导一次 —— 这是唯一诚实可行的路径。

## 五、cookie：只走运行中内核，不读 SQLite、不偷偷起内核

`src/kernel/cookies.js`（`readCookies` / `writeCookies` / `parseNetscape` / `formatNetscape` / `missingAfterWrite`）全部基于 CDP `Storage.getCookies` / `Storage.setCookies`。

真内核验证过两条命令都可用（探针 `.tmp/p10-cookie-probe.mjs`：`Storage.getCookies ok`、`Storage.setCookies ok {}`，网络兜底 `Network.setCookie` 也可用）。

- `GET /api/v1|v2/browser-profile/cookie/export?profile_id=…&format=json|netscape`
- `POST /api/v1|v2/browser-profile/cookie/import`，body 是 `{cookies:[...]}` 或 `{format:"netscape", content:"..."}`

**环境没在跑 → `800002`**，文案：`环境未在运行：cookie 存在内核里，请先启动该环境再导出（不会为了导出偷偷起内核）`。

为什么不做「悄悄起一个内核读完再关」：起内核要改环境自己的 user-data-dir 状态、会触发首屏加载与代理拨号，副作用（自检时间戳、代理记录、cookie 排序）比它省下的那一步操作贵得多；而且「导出」这个动作在用户心智里不该有启动成本。

字段口径（**等逆向的 AdsPower 真实样例到了再补映射，不自己发明**）：

| 字段 | json | netscape | 备注 |
|---|---|---|---|
| `expires` | unix **秒**；session 为 `-1` | unix **秒**；session 为 `0` | 导入兼容毫秒（`>1e12` 视为毫秒自动除 1000） |
| `sameSite` | `Strict/Lax/None`，扩展写法 `no_restriction/unspecified` 也认 | 不写 | 导出统一归一成三种标准值 |
| `httpOnly` | 布尔 | 行首 `#HttpOnly_` 前缀 | 解析时识别该前缀 |
| `secure` | 布尔 | 第 4 列 | |
| 分隔 | — | **tab**，首行 `# Netscape HTTP Cookie File` | 实测首行与 `p10a\tv1` 命中 |

写入后**立刻回读校验**：缺的条目进 `warnings`（文案带前 5 条 `name@domain`），并在响应里给 `verified`。不假装成功 —— 内核按策略丢弃 cookie（比如同站限制）是真实存在的。

实测：导入 2 条 → `imported:2, verified:2`；json 导出 3 条（`NID,p10a,p10b`，NID 是内核自己写的）；netscape 导出首行 `# Netscape HTTP Cookie File`；停掉后导出 `800002`；netscape 导入另一个环境 `imported:3, verified:3`，跨环境名字/值一致。

## 六、控制台入口

- **环境列表**：工具条「导入」（选 JSON 或 AdsPower `.txt`，按扩展名/首字符自动识别，导入完刷新列表并显示 `imported/failed/warnings`）、「导出 txt」（当前勾选或筛选结果 → AdsPower 块格式）；每行「导出」（下载 JSON 保真备份）、「复制」（复制后直接刷新，提示「四个指纹种子已重生」）。

## 七、AdsPower `.txt` 互操作（逆向实测后补的第六件事）

对方的环境导出**不是 JSON**：单文件 `profiles_YYYY_MM_DD_HH_mm_ss.txt`，每个环境一块 `key=value`，块尾 18 个 `*`，共 18 字段、没有版本号、没有 `fingerprint_config`。字段顺序（实测）：

```
acc_id, id, group, name, remark, platform, username, password, fakey, cookie,
proxytype, ipchecker, proxy, proxyurl, proxyid, ip, countrycode, ua
```

基线数字（用户那份真导出）：950 行 = 50 块 × 19 行；空值行 350 = 7 字段 × 50（`group/remark/username/password/fakey/proxyurl/proxyid`）；含多个 `=` 的行只有 `cookie`（JSON/base64 里的 `=`）；`CR` 0 个。所以**空值是常态、`=` 只切第一个**。

### 线上形状（定死）

```jsonc
// 导出
POST /api/v1|v2/browser-profile/export  { "profile_id": ["id1"], "format": "txt" }
→ { "code":0, "msg":"success", "data": { "format":"txt", "count":1,
     "filename":"profiles_2026_11_11_20_50_00.txt", "content":"<整份文件文本>", "warnings":[] } }
// txt 的响应里不放 list：保真备份（JSON）与互操作（txt）不混着给

// 导入
POST /api/v1|v2/browser-profile/import  { "format":"txt", "content":"<整份文件文本>" }
→ { "code":0, "data": { "list":[...], "imported":N, "failed":[{index,reason}], "warnings":[...] } }
```

### 解析：三条容错，缺一不可

1. `=` **只切第一个**，右边整段是值（`cookie` 行里有几十上百个 `=`）；
2. `key=` 是合法值（空串），不丢字段、不当缺字段；
3. 不依赖字段顺序，按名字取；**键集合不全不许整批失败** —— 缺什么在该条 `warnings` 里点名（缺 `ua` → 用默认 UA 并告警；整块连 `name` 都没有才进 `failed`）。

映射：`platform` 是**站点域名** → 我们的 `domain_name`（不是 `navigator.platform`）；`ua` → `ua`；`username/password/fakey` → 同名账号字段；`countrycode` → `ip_country`；`proxyid` → `proxy_id`；`group` 是分组**名**，纯数字才认，否则进默认分组并告警。`proxytype / ipchecker / ip` 同名直落；`acc_id / proxyurl` 我们没有对应字段，静默忽略（它们是对方的正式字段，**不报「未知字段」**）。

`proxy` 是**一个字符串** `host:port:user:pass`（无认证 `host:port`；密码可含 `:`，按「前 3 段定宽、其余全归密码」切）。切不出来（比如 `not-a-proxy`）→ 进 `warnings` 并写明「**该环境的代理为空**」，环境仍然建 —— 但绝不静默丢：静默丢代理 = 用户以为在走代理、实际裸奔。

`cookie` 是**对象数组**（只有它需要 `JSON.parse`）。落库时**原样保留对象**：`cookieToStorage` 以前对数组元素做 `String()`，会把整条变成 `"[object Object]"`，导入成功、cookie 全毁、无告警 —— 这是本轮修掉的数据毁灭 bug（现在对象数组存进去、`JSON.parse` 读回来仍是对象）。

### 写出：换行必须处理，写完立刻自校验

块是「一行一字段」：`name` / `remark` 里只要有一个 `\n`，写出去就多出几行假字段，这份文件从此解析不回来（而且看起来像「格式变了」而不是「数据脏了」）。所以：

- 非 `cookie` 字段的值把 `\r\n` / `\n` / `\r` 统一替成**一个空格**，并在 `data.warnings` 里报数（`N 个字段的换行已替换为空格（该格式一行一字段）`）；
- `cookie` 不走替换：它本来就是 `JSON.stringify` 出来的**单行**（换行已被转义成 `\n` 两个字符），先把数组序列化成单行再写行，**不 pretty-print**；
- 写出后**立刻用同一套解析器读回**：块数 = 导出条数、每块 18 键、cookie 能 `JSON.parse`、`proxy` 与原值逐字相等。任何一条不成立 → 路由返回非 0，**不输出半坏的文件**。

### cookie 语义：sameSite 四值、expires 秒、分区键

- `sameSite` 用对方词汇：`None → no_restriction`、`Lax → lax`、`Strict → strict`、**内核没给（未声明）→ `unspecified`**。绝不把未声明补成 `lax` —— 那会把「未声明」改成「明确的 Lax」，跨站场景「发」变「不发」。
- `expires` 仍是 unix **秒**（session 在 json 里 `-1`）；对方导出里 `session` **恒为 true 而 `expires` 有值**，所以 `session` 不可信，判会话只看 `expires <= 0`。
- 分区 cookie（CHIPS）双向：导出带 CDP 形状 `partitionKey{topLevelSite,hasCrossSiteAncestor}` + 兼容键 `CookiePartitionKey:"https://<host>"`；导入两种都认。丢了分区 = 分区 cookie 变成全局 cookie，能把两个环境串起来。

**必须记住的口径**：`.txt` 是「账号 + 代理 + cookie + UA」的**搬运单，不是环境全量备份**。指纹配置（四个种子、字体、媒体、时区、屏幕、`open_urls`…）一个都不在里面；要备份请用 JSON。

实测：`node --no-warnings .tmp/p10-txt-accept.mjs` → **9/9**（T1–T7）；主门追加的 T8/T9 也过（18 字段块导入后代理四段逐字相等、cookie 落库后仍是对象数组且 `name` 还在）。

## 八、K2a：验收门的前提写错了（已在门里加一次 stop）

门 `.tmp/p10-accept.mjs` 第一次跑到 **17 passed / 1 failed**，唯一失败：

```
FAIL  K2a 环境没在跑时导出明确报错（不许偷偷起内核）  — {"code":0,"msg":"success"}
```

原因在门自己：`C2` 用 `startAndHash(srcId)` 真起了 `srcId` 的环境，**起完从不 stop**；K2a 紧接着拿同一个 `srcId` 测「没在跑」，拿到 `code:0` 是正确行为。我用真正停掉的环境单独验过同一条：`{"code":800002,"msg":"环境未在运行：…"}`，且 `local-active` 不含该 id。

门里在 K2a 之前加一行 `stop(srcId)`（K1 会再起，cookie 测试不受影响），并追加 T8/T9 两条断言（AdsPower 18 字段块：代理四段、cookie 对象数组），现在 **20/20**。

## 九、顺带修的测量坑：audio 哈希只取前 128 个采样

复制验收第一次跑，副本的 audio 哈希与源**撞了**。查下来不是种子没换，是 `src/selfcheck/probe.js` 的测量口径：

```js
// 旧：只取前 128 个采样进哈希
for (let i = 0; i < Math.min(ch.length, 2048); i++) { ... if (i < 128) parts.push(...) }
```

而噪声是**每 1000 个采样才落一次**的 —— 两个不同种子的「前 128 个采样窗口」完全可能相同（大概率相同）。真实检测库哈希的是整段 buffer / 全样本和。

现在整段 buffer 全进哈希，并带 `|sum:` 后缀：

```js
for (let i = 0; i < ch.length; i++) { sum += Math.abs(ch[i]); parts.push(ch[i].toFixed(8)); }
hash = hashStr(parts.join(',') + '|sum:' + sum.toFixed(10))
```

修完四个哈希全不同（见第四节表格）。这条记在这里是为了说明：**「两个哈希一样」先怀疑测量口径，再怀疑注入**。同一个坑在 P9 的 `native()` 上出现过一次（那是真泄漏），这次是假阳性 —— 两种都要有判据区分。

## 十、已知限制（本轮新增，README 第 33/34/35 条）

33. 导出含代理密码明文；导入是搬运、复制是克隆换种子；我们的 JSON 是保真备份，AdsPower `.txt` 只是「账号+代理+cookie+UA」的搬运单（不含指纹配置）。
34. cookie 只走运行中内核；`copy_cookies` 以登录 cookie 文本回写，不是复制 SQLite；副本要原样带登录态需启动后再 `cookie/import`。
35. `Function.prototype.toString.call(fn)` 能读到注入函数真源码（逆向 P9-C 复验发现，9 个入口）—— JS 注入路线相对内核/DLL 替换的结构性差距，未修；**不要把「`native()` 已伪装」当成「检测方看不见」**。

## 十一、怎么验

```powershell
npm run test          # 不需要 Chrome：schema 10 + unit 64 + api 95 + ui 29 + desktop 54
npm run test:fileio   # 需要真 Chrome，约 90 秒，19 项
node --no-warnings .tmp/p10-accept.mjs       # 主门：20/20（18 条 + T8/T9）
node --no-warnings .tmp/p10-txt-accept.mjs   # txt 门：9/9（T1–T7）
```
