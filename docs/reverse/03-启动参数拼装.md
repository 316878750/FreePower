## 3. 参数从哪来（逐项）

### 3.1 固定/受保护参数（用户不可覆盖）

```
--protected-disable-safe-open     ← 仅 no_args/cover_args 分支；实测正常启动没有（见 §0）
--remote-debugging-port=0         ← 恒有（随机端口，靠 DevToolsActivePort 回读）
```
`no_args="1"` 时：**只留这两个**，其余全丢。**【实测】**
`cover_args` 非空时：`args = [上面两个] + cover_args`。**【实测】**
正常路径（`no_args` 空、`cover_args` 空）：`merge(puppeteer defaultArgs, buildLaunchOptions())`，**不含** `--protected-disable-safe-open`。**【实测，09 §2】**

### 3.3 用户自定义参数


## 4. `--user-data-dir` 与 profile 隔离

**结论（已按实测改写）：agent 侧**确实**下发了 `--user-data-dir`，值为绝对路径 `C:\.ADSPOWER_GLOBAL\cache\<fbccId>_<inviteCode>`。** 来源不是参数表，而是 puppeteer 选项：`optionPuppeteer.userDataDir = path.resolve(cacheFloder)`（偏移 702411），再由 puppeteer-core `defaultArgs` 展开成命令行参数。全包内 7 处 `user-data-dir` 字符串里，有 1 处是这条赋值，其余是 puppeteer 默认临时目录实现（`puppeteer_dev_chrome_profile-*`）——所以静态扫描时被误判成"全是默认实现"。**【实测，09 §2】**

真实隔离靠**工作目录约定**：

```
profileDir = <cacheRoot>/<fbccId>_<inviteCode>          # chrome
           = <cacheRoot>/<fbccId>_<inviteCode>_flower   # firefox
cacheRoot  = <BASE_DIR>/source/cache                     # 默认
           = <USER_DATA>/<fbccId>_<inviteCode>           # win32 若存在"旧缓存目录"则回退
BASE_DIR   = cwd_global/（agent 包所在目录的上一级）
```

`SunBrowser.exe` 二进制里含 `user-data-dir`、`UserDataDir` 字样。**实测结论：命令行里确实有 `--user-data-dir=<绝对路径>`，但它是 agent 通过 puppeteer 传的，不是启动器自己算的。**（原【推测】"由启动器翻译"不成立，已作废。）**【实测，09 §2】**

实测的 profile 目录根是 `C:\.ADSPOWER_GLOBAL\cache\`，**不是** `<BASE_DIR>/source/cache`——`cacheRoot` 默认值本文写错，实际取的是数据目录根下的 `cache`（Global 版即 `C:\.ADSPOWER_GLOBAL\cache`）。**【实测，09 §2】**

同名 md5 派生文件（都在 `profileDir` 下）：

```
<profileDir>/md5(fbccId + "_static")   → base64(JSON) 静态指纹配置
<profileDir>/md5(fbccId + "_webrtc")   → base64(JSON) 动态配置（时区/地理/WebRTC 地址）
<profileDir>/md5(fbccId + "_cookies")  → JSON cookie 列表
```

路径通过 `sunBrowserParams.StaticConfig` / `DynamicConfig` / `CookiesFile` 传进去。**【实测】**

## 7. 与 puppeteer 的关系

```js
browserOptions.ignoreDefaultArgs = mergeBrowserArgs(默认args, ...)  // 把不想要的默认参数整体屏蔽
```
即 AdsPower 借 puppeteer 的默认参数集打底，用 `ignoreDefaultArgs` 删掉个别项（实测 `--enable-automation` 被抑制），再 merge 自己的参数。**实测命令行里能看到 puppeteer 的默认参数残留**：`--force-color-profile=srgb`、`--metrics-recording-only`、`--no-first-run`、`--password-store=basic`、`--use-mock-keychain`、`--export-tagged-pdf`——这些都是 puppeteer `defaultArgs` 原样带出来的。**【实测，09 §2】**

> 原结论"AdsPower 不用 puppeteer 默认参数集、完全自己接管命令行"**不准确**：它只是选择性屏蔽，不是完全接管。
