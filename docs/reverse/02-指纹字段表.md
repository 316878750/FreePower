## 0. 两层数据模型（关键）

一个「环境」在存储上是**平铺的一张大表**（字段直接挂在 profile 记录上），但通过 API 提交时，**部分维度被打包进 `fingerprint_config` 这个 JSON 列**。

```
profile 记录
├─ 平铺列：name / group_id / ua / canvas / webgl / timezone / fonts / webrtc / ...
└─ fingerprint_config (JSON 文本列)：{ webgl_config:{...}, ... }
```

写入时：`fingerprint_config` 会被 `JSON.stringify()` 后存（模块 64350）。读取/启动时按平铺列逐项消费。

> 注意：`/api/v1/user/create`（v1）与 `/api/v2/browser-profile/create`（v2）走同一个 handler，只是参数映射不同（v1 `group_id`→v2 `batch_id`，`open_urls`→`openfb_urls`，`platform`→`domain_name`，`category_id`→`sys_app_cate_id`，`profile_tag_ids`→`fbcc_user_tag_ids`，`random_fingerprint`→`switch_random_finger`）。**【实测】**

## 5. 字体

| 字段 | 类型 | 取值 | 映射 |
|---|---|---|---|
| `fonts` | array\<string\> | `["all"]` 或具体字体名数组 | → `staticConfig.DisabledFonts`（**落盘为逗号分隔字符串**） |
