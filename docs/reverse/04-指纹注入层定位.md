# AdsPower 8.9.23 · 指纹注入层定位（内核级，非 CDP/扩展）

> ⚠️ **基线**：本文的 `chrome.dll` 偏移来自内核 **152.0.7977.54**（内核独立下发，不受 agent 热更新影响）；文中涉及 agent（`main.min.js`）的偏移基于 **v2.8.9.2**，线上已升至 **v2.9.0.1**（+53952 字节），**引用 agent 偏移前必须按 `agent-versions/README.md` 重核**。

> 结论先行：**ADS 的指纹注入发生在定制 Chromium 内核内部**，通过 Chromium 自带的 **policy（策略）加载器**吃进一个叫 `SunBrowserPolicys` 的自定义策略束，不是 CDP 覆写、不是浏览器扩展、不是外部 DLL 注入。
> 证据：`chrome.dll` 字节级字符串扫描（306 MB）+ 路径字符串。标注：【实测】/【推测】。

## 1. 证据：`--extended-parameters` 是一个 policy 源

在 `chrome_152\152.0.7977.54\chrome.dll`（306 MB）偏移 `0x10959d38` 附近的连续字符串：

```
0x10959cb8  ..\..\components\policy\core\common\policy_bundle.cc
0x10959cf0  ..\..\components\policy\core\common\policy_loader_command_line.cc
0x10959d38  extended-parameters                ← 命令行开关名
0x10959d50  SunBrowserPolicys                  ← 自定义策略束名
0x10959d68  DevtoolsPreferences                ← 一并注入的偏好
0x10959d80  extended-parameters policy is not a dictionary
0x10959db0  extended-parameters policy error: dict empty
```

解读【实测】：
- 参数名落在 `policy_loader_command_line.cc` 的字符串区 → 这是**新增的一条"从命令行加载策略"的分支**，和 Chromium 的 `--policy-data` 同类。
- 报错文案是「不是字典 / 字典为空」→ 内核把它当 **JSON 字典**解析。
- 与 agent 侧 `D.encodeBase64(JSON.stringify(sunBrowserParams))` 对得上 → **自定义字母表 base64 → JSON → 策略字典**。（注意：`encodeBase64` 不是标准 base64，见 §0 勘误与 09 §3。）

## 3. 三通道对照

| 通道 | 载体 | 内容 | 可变性 |
|---|---|---|---|
| A. `--extended-parameters` | 命令行 | **自定义base64**(JSON)：噪点种子、时区、语言、屏幕、硬件、WebRTC 地址、WebGPU 开关、StaticConfig 路径 | 启动时固定（28 个键，实测） |
| B. `StaticConfig` 文件 | `<profileDir>/md5(fid+"_static")`，**自定义base64**(JSON) | 字体重映射、媒体设备、TTS、MAC、设备名、UA-CH、NetFilters、DevTools 偏好 | 启动时读一次（47 个键，实测） |
| C. `DynamicConfig` 文件 | `<profileDir>/md5(fid+"_webrtc")`，**自定义base64**(JSON) | `TimeZone` / `Geoposition` / `WebRTCAddress` / `BlockList` / `StrongBlockList` | **代码确认可运行时改写，未实测**；内容不变不重写 |

C 通道设计意图：**换代理不必重启浏览器**，内核会重读这个文件。三个运行时写入点已定位（`UPDATE_IP_$$_` 消息 → 偏移 445489；城市/国家变化 → 463785；经纬度变化 → 465178，后两者需 `IS_REALTIME_TZ_GEO=true`）。

**⚠️ 消息通道的真实形态（2026-11-11 新发现）**：所谓 `UPDATE_IP_$$_` 消息不是 IPC，而是 **`page.on("console")`** —— 主进程在页面里 `console.log("UPDATE_IP_$$_<ip>")`，agent 从 console 事件文本里 `indexOf` 匹配后改写文件。同理还有 `UPDATE_GEO_$$_<lon>_$$_<lat>`、`UPDATE_TIMEZONE_$$_...`、`disconnect`。
**安全后果**：任何页面只要输出这段字符串且条件满足（`webrtc ∈ {proxy,forward}` 且 `IS_SUNFLOWER_BROWSER_CANVAS=true`），就能改写该环境的 WebRTC 出口 IP 并删掉 `DisableWebRTC`。这是一条注入面，也是复刻时要谨慎对待的设计。详见 `09-动态验证.md` §5.3。**【码，实测未复现】**

⚠️ **但"运行时可变"要降级**：实测空闲 45 秒、stop→start 重启一次，三个配置文件 **mtime 与内容全不变**——写文件前有 md5 比对，内容一致就跳过写入（偏移 431289）。所以"用 mtime 变化判断是否换过 IP"这个检测思路**方向仍成立，但触发条件很窄**（必须真的换 IP/换时区且 `IS_REALTIME_TZ_GEO` 开启）。**【实测，09 §5】**

## 4. 注入生效的开关（32 个环境变量）

指纹并非全都默认生效，agent 用一组 `IS_*` 环境变量控制：

```
IS_SUNFLOWER_BROWSER             总开关（旧通道 --UserId）
IS_SUNFLOWER_BROWSER_BASE64      新通道（--extended-parameters）
IS_SUNFLOWER_BROWSER_WEBGL       Canvas/WebGL 噪点
IS_SUNFLOWER_BROWSER_GEO         Flash/Geolocation/端口扫描
IS_SUNFLOWER_BROWSER_LANG        语言/字体/屏幕/WebRTC/DNT/硬件
IS_SUNFLOWER_BROWSER_MOBILE      移动端相关（TouchPoints/媒体设备/TTS）
IS_SUNFLOWER_BROWSER_CANVAS      字体黑名单/WebRTC 前置
IS_SUNFLOWER_BROWSER_DONOTTACK   DNT/硬件并发/内存
IS_SUNFLOWER_BROWSER_DEBUGGER    调试（DisCanvasUrl、禁 JS 调试器）
IS_CLIENT_HINTS / IS_CLIENT_RECT / IS_MAC_ADDRESS / IS_BROWSER_DEVICE_NAME
IS_CHECK_PROXY_BEFORE / IS_REALTIME_TZ_GEO   启动顺序与时区实时化
...
```

⚠️ **同一版本号客户端，实际生效的维度可能不同**（灰度）。做指纹检测时要按变量实际值判定，不能假设全开。

## 5. 对"可检测破绽"的初步判断

| 观察点 | 为什么可疑 | 置信度 |
|---|---|---|
| `--extended-parameters` 出现在 cmdline | 原版 Chrome 没有这个开关 | 高 |
| 该参数是**自定义字母表 base64**（标准 base64 解不开） | 双重特征：既有非标开关，又有非标编码 | 高 |
| 解码后是明文 JSON 且含 `CanvasMark*`/`WebGLMark*` | 一眼是噪点种子 | 高 |
| profile 目录下 `md5(fid+"_static")` 等无扩展名文件 | 原版 Chrome 只有 `DevToolsActivePort`、`Local State` 等固定名 | 高 |
| profile 目录名 `<32位hex>_<6位hex>` + 位于 `C:\.ADSPOWER_GLOBAL\cache` | 盘符根目录 + 非 Chrome 默认布局 | 高 |
| `--user-agent` 大版本与内核不匹配（实测 133 vs 内核 142） | 页面侧 `navigator.userAgent` 与 `userAgentData` 互相矛盾 | 高 |
| `WebGLFP` 指向的 json 里 GPU 是古董型号（Intel B43 / WDDM 1.1），却配 4 核 / 8G | 硬件组合不合理 | 高 |
| `WebRTCLocalAddress` 暴露真实内网 IP 段 | 页面侧 WebRTC 可读 | 高 |
| `--no-sandbox` + 自定义 launcher（SunBrowser.exe 非 chrome.exe） | 进程树/签名差异 | 中 |
| `DynamicConfig` 文件 mtime 变化 | 换 IP/时区的信号，但触发条件窄（见 §3） | 中 |
| `--enable-automation` **被抑制**（puppeteer 默认有、它没有） | 说明做过反检测处理 | 中 |

页面内 JS 侧的检测点（`navigator.webdriver`、`WebGLRenderingContext.getParameter` 返回值、`document.fonts` 一致性）需要动态验证，不在静态证据范围内。
