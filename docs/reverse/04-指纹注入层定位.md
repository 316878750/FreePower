# AdsPower 8.9.23 · 指纹注入层定位（内核级，非 CDP/扩展）

> 结论先行：**ADS 的指纹注入发生在定制 Chromium 内核内部**，通过 Chromium 自带的 **policy（策略）加载器**吃进一个叫 `SunBrowserPolicys` 的自定义策略束，不是 CDP 覆写、不是浏览器扩展、不是外部 DLL 注入。
> 证据：`chrome.dll` 字节级字符串扫描（306 MB）+ 路径字符串。标注：【实测】/【推测】。

---

## 1. 证据：`--extended-parameters` 是一个 policy 源

在 `chrome_152\152.0.7977.54\chrome.dll`（306 MB）偏移 `0x10959d38` 附近的连续字符串：

```
0x10959cb8  ..\..\components\policy\core\common\policy_bundle.cc
0x10959cf0  ..\..\components\policy\core\common\policy_loader_command_line.cc
0x10959d38  extended-parameters                ← 命令行开关名
0x10959d50  SunBrowserPolicys                  ← 自定义策略束名
0x10959d68  DevtoolsPreferences                ← 一并注入的偏好
0x10959d80  extended-parameters policy is not a dictionary
0x10959db0  extended-parameters policy error: dict empty
```

解读【实测】：
- 参数名落在 `policy_loader_command_line.cc` 的字符串区 → 这是**新增的一条"从命令行加载策略"的分支**，和 Chromium 的 `--policy-data` 同类。
- 报错文案是「不是字典 / 字典为空」→ 内核把它当 **JSON 字典**解析。
- 与 agent 侧 `D.encodeBase64(JSON.stringify(sunBrowserParams))` 对得上 → **base64 → JSON → 策略字典**。

## 2. 证据：内核里存在这些字段名

同一 `chrome.dll` 内的字符串（ASCII）：

| 字符串 | 偏移 | 对应 agent 字段 |
|---|---|---|
| `CanvasMarkEx` | 0x11ed0b80 | `canvas` + `canvas_id` |
| `WebGLMarkEx` | 0x11ed0b90 | `webgl_image` + `webgl_image_id` |
| `Fakefonts` | 0x11f9cb18 | 字体伪造（platform 不匹配时） |
| `DisabledFonts` | 0x11fa6080 | `fonts` / `disabled_fonts` |
| `TTSEngines` | 0x10bd1530 | `speech_voices` |
| `Geoposition` | 0x108f6137 (8 处) | `latitude`/`longitude`/`accuracy` |
| `AllowScanPorts` | 0x11e0e88e | `allow_scan_ports` |
| `HardwareConcurrency` | 0x108c8ba2 | `hardware_concurrency` |
| `DeviceMemory` | 0x1070513c (19 处) | `device_memory` |
| `WebRTCAddress` | 0x12533138 | `webrtc=proxy/forward` 时的出口 IP |
| `DynamicConfig` | 0x113f6580 (2 处) | 动态配置文件路径 |
| `adspower` | 0x10ede7f8 (2 处) | 品牌标识 |

→ 这些键名**同时出现在 agent 与内核**，说明是同一份约定，内核侧按策略字典取键、在 Blink 层改写返回值【实测 + 推断】。

## 3. 三通道对照

| 通道 | 载体 | 内容 | 可变性 |
|---|---|---|---|
| A. `--extended-parameters` | 命令行 | base64(JSON)：噪点种子、时区、语言、屏幕、硬件、WebRTC 地址、WebGPU 开关、StaticConfig 路径 | 启动时固定 |
| B. `StaticConfig` 文件 | `<profileDir>/md5(fid+"_static")`，base64(JSON) | 字体重映射、媒体设备、TTS、MAC、设备名、UA-CH、NetFilters、DevTools 偏好 | 启动时读一次 |
| C. `DynamicConfig` 文件 | `<profileDir>/md5(fid+"_webrtc")`，base64(JSON) | `TimeZone` / `Geoposition` / `WebRTCAddress` | **运行时可变**（换 IP 后原地改） |

C 通道是关键设计：**换代理不必重启浏览器**，内核会重读这个文件。做检测的话这是个可疑行为特征。

## 4. 注入生效的开关（32 个环境变量）

指纹并非全都默认生效，agent 用一组 `IS_*` 环境变量控制：

```
IS_SUNFLOWER_BROWSER             总开关（旧通道 --UserId）
IS_SUNFLOWER_BROWSER_BASE64      新通道（--extended-parameters）
IS_SUNFLOWER_BROWSER_WEBGL       Canvas/WebGL 噪点
IS_SUNFLOWER_BROWSER_GEO         Flash/Geolocation/端口扫描
IS_SUNFLOWER_BROWSER_LANG        语言/字体/屏幕/WebRTC/DNT/硬件
IS_SUNFLOWER_BROWSER_MOBILE      移动端相关（TouchPoints/媒体设备/TTS）
IS_SUNFLOWER_BROWSER_CANVAS      字体黑名单/WebRTC 前置
IS_SUNFLOWER_BROWSER_DONOTTACK   DNT/硬件并发/内存
IS_SUNFLOWER_BROWSER_DEBUGGER    调试（DisCanvasUrl、禁 JS 调试器）
IS_CLIENT_HINTS / IS_CLIENT_RECT / IS_MAC_ADDRESS / IS_BROWSER_DEVICE_NAME
IS_CHECK_PROXY_BEFORE / IS_REALTIME_TZ_GEO   启动顺序与时区实时化
...
```

⚠️ **同一版本号客户端，实际生效的维度可能不同**（灰度）。做指纹检测时要按变量实际值判定，不能假设全开。

## 5. 对"可检测破绽"的初步判断

| 观察点 | 为什么可疑 | 置信度 |
|---|---|---|
| `--extended-parameters` 出现在 cmdline | 原版 Chrome 没有这个开关 | 高 |
| 该参数是 base64(JSON) 且含 `CanvasMark*`/`WebGLMark*` | 一眼是噪点种子 | 高 |
| profile 目录下 `md5(fid+"_static")` 等无扩展名文件 | 原版 Chrome 只有 `DevToolsActivePort`、`Local State` 等固定名 | 高 |
| `md5(...)` 文件名与 profile 目录里的 `puppeteer_dev_chrome_profile-*` 混存 | 临时目录残留 | 中 |
| `--protected-disable-safe-open` | 非标准开关 | 高 |
| `--no-sandbox` + 自定义 launcher（SunBrowser.exe 非 chrome.exe） | 进程树/签名差异 | 中 |
| `DynamicConfig` 文件在运行时被改写 | 换 IP 后用 mtime 可发现 | 中 |

页面内 JS 侧的检测点（`navigator.webdriver`、`WebGLRenderingContext.getParameter` 返回值、`document.fonts` 一致性）需要动态验证，不在静态证据范围内。
