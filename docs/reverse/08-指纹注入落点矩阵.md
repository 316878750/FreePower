# AdsPower Global 8.9.23 · 指纹注入落点矩阵（139 字段逐项归位）

> 采集：2026-11-09。只读分析。
> 证据两级：**【实】** 真实落盘/实测（`C:\.ADSPOWER_GLOBAL\cache\p5demo2_a1b2c3\` 与 Local API 往返）；**【码】** `%APPDATA%\adspower_global\cwd_global\lib\main.min.js` 代码路径（8.85 MB，仅 minify，@数字=字符偏移）；**【推】** 推测。
> 字段全集来自 `fingerprint-fields.json`（139 字段 / 11 组），通道来自 `04-指纹注入层定位.md`。

---

## 0. 结论先行

**AdsPower 没有一条指纹是走 CDP 注入的。** 139 个字段的落点只有四类：

1. **内核配置文件**（`StaticConfig` / `DynamicConfig`，自定义 base64 换表编码）——主力，42 个字段
2. **命令行参数**（`--user-agent` / `--lang` / `--proxy-server` / `--window-*` 等）——26 个
3. **进程环境变量**（`TZ` / `LANGUAGE` / `ISOLATE_DEFAULT_LOCALE`）——2 个
4. **不进内核，只入本地库/调度**——39 个

CDP 落点计数 = **0**。AdsPower 只在「拿调试端口」这一件事上用到 CDP 协议（`--remote-debugging-port=0` + `DevToolsActivePort`），指纹一个都不从那走。
推论：AdsPower 的页面里看不到 `Page.addScriptToEvaluateOnNewDocument` 注入的痕迹，也看不到被改写的 `Function.prototype.toString` —— 这是它相比 CDP 方案最大的隐蔽性优势，也是 FreePower 无法 1:1 复刻的根本原因。

## 2. `SB` 和 `SC` 是同一批数据的两条腿（复刻的关键）

【码】@408：

```js
for (key in sunBrowserParams)
  if (key NOT IN ["CustomIcon","WebGLFP","StaticConfig","CookiesFile","DynamicConfig","Geoposition","TimeZone"])
      staticConfig[key] = sunBrowserParams[key];
```

→ `sunBrowserParams` 里除这 7 个例外，**全部复制进 StaticConfig 一起落盘**。所以 `CanvasMark`、`AudioFp`、`HardwareConcurrency` 这些同时出现在「命令行 base64」和「落盘文件」两处，是**同一份值的两个入口**，不是两条独立的注入路径。

对复刻的意义：内核只有一套读取逻辑，命令行那份是启动即用的快照，落盘那份是可复用/可运行时改的持久副本（`DynamicConfig` 是唯一真能在运行中改的）。

## 4. 一个字段多处落地的 6 个例子（复刻按这个优先级）

| 字段 | 落的通道 | 复刻要点 |
|---|---|---|
| `webrtc` | `ARG` + `SB` + `DC` | 命令行只管 UDP 策略，地址在 DC 里；三者要一致，否则自相矛盾 |
| `timezone` | `ENV TZ` + `DC` | `TZ` 管进程/渲染层，DC 管内核覆写；只改一个会对不上 |
| `ip` | `SC.WebRTCAddress` + `DC.WebRTCAddress` | 同一个出口 IP 写两处，DC 那份运行时可变 |
| `user_proxy_config` | `ARG --proxy-server` 或 `SC.ProxyChain` | 单跳走命令行，多跳走 SC，二者互斥 |
| `screen_resolution` | `ARG --window-size` + `SB.MobileModeFixedResolution` | 桌面模拟走窗口尺寸，移动模拟才落 SC |
| `fonts` | `SC.DisabledFonts` + `SC.Fakefonts` | 先把系统字体列出来登记（`DisabledFonts` 是字符串），再做重映射 |

**顺序**：命令行（启动即定）→ StaticConfig（内核启动读一次）→ DynamicConfig（运行时可改）。

## 5. 门控层：GATE 字段 + 32 个 `IS_*` 环境变量

给了值不等于生效。除了上面 15 个 `GATE` 字段，agent 还有一层 `IS_*` 进程环境变量决定**要不要把这一段写进策略**（全表见 `04-指纹注入层定位.md` §4）：

```
IS_SUNFLOWER_BROWSER / _BASE64     总开关（旧 --UserId 通道 / 新 --extended-parameters 通道）
IS_SUNFLOWER_BROWSER_WEBGL         Canvas / WebGL 噪声
IS_SUNFLOWER_BROWSER_GEO           Flash / Geolocation / 端口扫描
IS_SUNFLOWER_BROWSER_LANG          语言 / 字体 / 屏幕 / WebRTC / DNT / 硬件
IS_SUNFLOWER_BROWSER_MOBILE        TouchPoints / 媒体设备 / TTS
IS_SUNFLOWER_BROWSER_CANVAS        字体黑名单 / WebRTC 前置
IS_SUNFLOWER_BROWSER_DONOTTACK     DNT / 硬件并发 / 内存
IS_CLIENT_HINTS / IS_CLIENT_RECT / IS_MAC_ADDRESS / IS_BROWSER_DEVICE_NAME
IS_REALTIME_TZ_GEO                 时区/地理是否实时改 DynamicConfig
```

⚠️ **同一版本号客户端，实际生效的维度可能不同**（远端灰度）。做检测/复刻都不能假设全开。

## 6. 11 个未定位字段（诚实标注）

`browser_compatibility_mode`、`gpu`、`gpu_switch`、`cdp_mask`、`ban_dev_tools`、`renderer_accessibility`、`network_information_type`、`disable_video`、`image_size`、`translate_webpages`、`domain_https`

它们既不在真实 StaticConfig 的 47 个键里，也不在命令行/环境变量里。两种可能：
1. 在 `chrome.dll` 的 `SunBrowserPolicys` 策略处理分支里（要 IDA/Ghidra 才能确认，本机没有）——**推测**
2. 走云端策略下发，客户端只传个开关——**推测**

对 FreePower 的结论：这 11 个不要声称已复刻，写进「已知差距」。

## 7. 对 FreePower 的替代映射（CDP 方案能补到哪一步）

| AdsPower 落点 | FreePower 可用做法 | 可检测性 |
|---|---|---|
| `ARG --user-agent=` / `--lang=` | 同样用命令行 | **1:1，最优** |
| `ENV TZ` / `LANGUAGE` | 同样用环境变量 | **1:1，最优** |
| `DC.TimeZone` | CDP `Emulation.setTimezoneOverride` | 低风险（原生能力，无 JS 痕迹） |
| `DC.Geoposition` | CDP `Emulation.setGeolocationOverride` | 低风险（原生能力） |
| `SC.UserAgentMetadata` | CDP `Emulation.setUserAgentOverride` 的 `userAgentMetadata` | 低风险（原生能力） |
| `SC.HardwareConcurrency` / `DeviceMemory` | `Object.defineProperty(navigator,...)` 注入 | 中：属性描述符 getter 非原生，`Object.getOwnPropertyDescriptor` 可识别 |
| `SC.CanvasMarkEx` | 改写 `getImageData`/`toDataURL` | **高**：函数 `toString()` 不像原生，调用栈可查 |
| `SC.AudioFp` | 改写 `AudioBuffer.getChannelData` / `OfflineAudioContext` | **高**：同上 |
| `SC.WebGLMarkEx` | 改写 `WebGLRenderingContext.getParameter` | **高**：同上 |
| `SC.DisabledFonts` / `Fakefonts` | 只能改 `document.fonts` / `measureText` | **很高**：字体度量测得出 |
| `SC.MacAddress` / `DeviceName` / `ProductType` | CDP 无对应 API，只能伪造 UA-CH 或页面 API | 高 |
| `SC.ProxyChain`（内核原生多级代理） | **做不到**，只能链式本地代理 | 能力差距（已定：MVP 不做） |
| `DC.WebRTCAddress` / `ARG --webrtc-ip-handling-policy` | 命令行策略 1:1；地址伪造靠代理 | 中 |

**给 README 的一句话**：能在 CDP 层 1:1 复刻的只有 UA/语言/时区/地理/UA-CH 五项；canvas/audio/webgl/字体只能靠 JS 注入，**必然比 AdsPower 的内核方案更容易被检测**，这是架构差距，不是实现问题。
