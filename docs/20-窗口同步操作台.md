# 20 · 窗口同步操作台（桌面小组件，0.4.5，2026-11-15）

出处：用户提「我们没有 AdsPower 的窗口同步操作台」。CEO 核过后确认缺口比表面更大 ——
`web/` 里「操作台 / 小组件 / widget / console」**零命中**，只有一个 `#/sync-panel` 独立小窗、
**只能从托盘菜单打开**，没有收起/展开、没有自动收起、没有「正在同步操作」的紧凑态、没有位置记忆，
而且因为没有 preload，网页侧**根本无法通知桌面壳**做任何事。

本文记三件事：对手证据 → 我们怎么落 → 哪些**验不了**。

## 二、落成什么

### 2.1 不新增第二个浮窗

现有 `#/sync-panel` 直接改造成操作台，两种形态：

| 形态 | 尺寸（**我们选的**） | 内容 |
|---|---|---|
| 展开 | **430×620**（最小 380×420，可拉大） | 完整面板：操作台设置 / 选窗口 / 状态 / 窗口排列 / 显示窗口 / 快捷键 |
| 收起 | **360×56**（最小可见 64×24，不可拉大） | **只有五项**：状态词、主控环境名、受控 N 个、停止、展开 |

**收起态是真改窗口尺寸**（`setBounds`），不是在一个 430×620 的窗里换个布局 ——
后者照样挡住主控窗口，那就等于没做。判据直接把这条钉住：收起态高度必须真的小于展开态（见 §四）。

两个实现上的坑（都在 `desktop/main.js` 的 `applyConsoleMode` 里）：

1. `setBounds` 受最小尺寸约束：收起态 360×56 会被展开态的 `minWidth 380 / minHeight 420` 挡住。
   所以**先把最小尺寸降下来再 setBounds**，展开时再抬回去。
2. 收起态 `setResizable(false)`：不锁的话用户一拉就拉成一个奇怪的大窗。

改完**回读**（CEO 硬约束：改窗口必回读验证），日志里记
`want=…x…@x,y got=…x…@x,y ok|MISMATCH`。

### 2.2 自动收起（`automaticShrink`）默认**开**

理由不是抄谁，是使用场景：展开态 430×620 且始终置顶，用户点「开始同步」的下一秒就要在主控窗口里操作，
那块面板正好压在他要点的位置。

对手的默认值**没有证据**（`dyn-staticconfig.json` 里没有这个键），所以这是**我们的选择**，
README 与升级说明都标了。设置项落在 `data/sync-console.state.json` 的 `prefs.auto_shrink`。

生效时机是**状态跳变那一下**：同步从没跑变成在跑 → 收起；同步结束且是我们自动收的 → 恢复展开。
只在跳变时动手，用户手动展开后不会被下一轮轮询又收回去。

### 2.3 位置记忆与「不许留在屏幕外」

- 位置**按形态分开记**（`rects.expanded` / `rects.collapsed`）：共用一个会让「收起 → 展开」每次跳位置；
- 拖动/拉大 → 400ms 防抖后写盘（拖的过程不写）；
- 「操作台复位到默认位置」→ 清空保存值，回主屏居中；
- **每次应用形态前都按当前 `screen.getAllDisplays()` 校验**（纯函数 `pickConsoleRect`）：
  保存值与某块屏的可用区交集不足 **64×24**（我们选的「能看见一角、能拖回来」的门槛）就回主屏居中。

为什么要校验而不是只信保存值：用户会拔副屏、改缩放、把任务栏挪走 ——
这时原坐标落在屏幕外，窗口就「打开看不见、还抢着置顶」，用户只能去任务管理器杀进程。
判据里三种场景（副屏消失 / 负坐标副屏 / 缩放变化）都钉住了。

### 2.4 preload：只开一个口子

以前 `desktop/main.js` 明确写「sandbox 开、不挂 preload」，所以网页侧没有任何办法通知桌面壳。
0.4.5 新增 `desktop/preload.js`，边界钉死：

| 项 | 值 |
|---|---|
| 挂在哪 | **只挂主窗口**（`createWindow` 的 `webPreferences.preload`）；操作台小窗**不挂** |
| 暴露什么 | `isDesktop: true`、`openSyncPanel()` 两个，`exposeInMainWorld` 只调用一次 |
| 不暴露什么 | `ipcRenderer` 本身、任何通用 `invoke`、`require` |
| 唯一通道 | `fp:open-sync-panel`；主进程侧还校验 `event.sender === win.webContents` |
| `sandbox` / `contextIsolation` | 仍然 `true` / `true`，`nodeIntegration` 仍然 `false` |

操作台小窗改形态**不走 IPC**，走 Local API + 请求文件（与快捷键同一套姿势，见 `src/sync/hotkey.js`）。

### 2.5 状态词如实映射（不硬造）

对手有 `syncOperateSyncException`（同步异常）。**我们没有对应状态**：引擎在个别窗口断连时
照样继续跑（`degraded` 只是那个窗口的连接没了）。所以：

- 同步中 → 「正在同步操作」；
- 有窗口断连 → 标题仍是「正在同步操作」，`tone` 变 `warn`，另给一行 detail「有 N 个窗口连接断了」；
- 没在跑 → 「同步已停止」，受控 0 个，只有「展开」。

不抄一个对不上的词。判据里有一条专门断言**收起条内容里不出现「同步异常」**。

### 2.6 纯网页时如实禁用

没有桌面壳（`npm start` 跑服务）时 `readConsoleState().managed === false`：

- `requestConsole` **不写请求文件**（写了没人读 = 说了但没做），返回 `managed:false` + 原因；
- `POST /api/v2/sync/console` 回 `code 0` + `{requested:false, managed:false, reason:'no_desktop_shell'}`；
- 界面据此把「收起 / 复位」禁用并写明「桌面版才有操作台」，「打开操作台」按钮禁用 + `title` 说明。

## 四、判据

### A 层：`test/sync-console.test.mjs`（59 条，已进 `npm test`）

| 组 | 钉住什么 |
|---|---|
| 1. 两种形态 | 收起态高度**真的**小于展开态（差 ≥400px）、宽度也更小；形态归一；尺寸返回副本 |
| 2. 设置 | `auto_shrink` 默认 `true`；字符串/数字写法都认；不认识的键丢掉 |
| 3. 位置校验 | 保存值在屏上就用；**副屏拔掉 → 回主屏居中**；**缩放变小 → 回主屏**；负坐标副屏照样认；只露一条缝算看不见；刚好 64×24 算看得见；垃圾值 → `bad_saved`；一块屏都没有 → 稳定值 |
| 4. 收起条 | **只有五项**；degraded 不改标题只给 detail；**不出现「同步异常」** |
| 5. 文件交接 | 无桌面壳不写请求文件；状态 30 秒没心跳当没人管；位置按形态分开记 |
| 6. preload 边界 | `exposeInMainWorld` 只一次且只有两个键；**不透传 `ipcRenderer`**；只打一条通道；主窗口挂、小窗不挂；`sandbox`/`contextIsolation` 没被改；主进程校验调用者；退出清理 |
| 7. 页面与路由 | 两条 console 路由都在（GET 一次 / POST 一次）；排列/显示**打的就是既有两条路由**；页面不许自己拼请求；纯网页如实禁用 |

### 先红后绿（两处，都实测过）

| 改动 | 读数 |
|---|---|
| ① 收起态改成「只换布局不改尺寸」（`CONSOLE_COLLAPSED` 改成 430×620） | `51/59`，**8 条红**：尺寸两条、`consoleSizeOf` 两条、三处回主屏居中、尺寸返回副本 |
| ② 位置校验改成「有保存值就用」（`pickConsoleRect` 里直接 `return saved`） | `56/59`，**3 条红**：副屏拔掉、缩放变小、只露一条缝 |
| 恢复 | `59/59`（含后来把 preload 后缀改成 `.cjs` 加的那一条 → `60/60`） |

### 既有判据的收紧

- `test/desktop.test.mjs`：原来那条 `check('不挂 preload', !has(/preload\s*:/))` 必然红 ——
  改成**按窗口分别扫**：「preload 只挂主窗口」+「操作台小窗不挂 preload」，比原来更严。
- `test/sync-arrange.test.mjs` / `test/sync-show.test.mjs`：排列与显示搬进共用组件
  `web/sync-widgets.js` 后，断言改为扫组件 + 额外钉住「两个页面 import 的是同一份」，同样更严。

**preload 后缀是 `.cjs` 而不是 `.js`**：`package.json` 有 `"type": "module"`，`.js` 可能被当 ESM 解析，
而 sandboxed preload 只能是 CommonJS。用 `.cjs` 把这件事钉死，不依赖 Electron 版本对
「`.js` + `type: module`」的处理；判据里另有一条断言 `desktop/preload.js` **不许存在**。

## 五、**我验不了**的（不许写成已验证）

本机 agent shell 里 Electron 起不来（`0x80000003`），下面三条**只写了自检条目，没有跑出读数**：

1. 收起/展开真的改窗口尺寸（`desktop:selftest` 里 `console.collapsed_shorter` / `collapsed_matches` / `expanded_matches`，本机报 skip）；
2. 拖动后位置记忆、重启后恢复；
3. 拔掉副屏 / 改缩放后窗口回主屏（`console.off_screen_recovered`，本机报 skip）。

`desktop:selftest` 的 `steps.console` 结构：能建出窗口就跑，跑不了写
`{skipped:true, reason:'no_panel'}`；跑完会把形态**恢复到进来时的样子**，不改用户设置。

README 与升级说明里另有一张「需要在你桌面上复验」的清单（3–4 条），用户照着点一遍就知道对不对。
