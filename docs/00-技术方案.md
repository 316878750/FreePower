> 独立实现的指纹浏览器（AdsPower 同类产品）。不搬运 AdsPower 私有代码/二进制/资源/商标。
> 内核用开源 Chromium 系，指纹自己实现。

## 1. 内核选型

**选定：Electron 主程序（UI/调度/存储/API） + 官方 Chrome for Testing 内核（独立进程） + CDP 注入。**

候选对比：

| 方案 | 指纹真实度 | 开发速度 | 代价 | 结论 |
|---|---|---|---|---|
| A. Electron 当浏览器（BrowserWindow 开网页） | 差（`process.versions.electron`、UA 带 Electron、`chrome.runtime` 差异） | 最快 | 擦不干净 | ❌ |
| B. 主程序 Electron + CfT 内核 + CDP 注入 | 中（引擎真实，注入层有痕） | 快（天级） | 注入面随 Chrome 版本膨胀 | ✅ 第一版 |
| C. 自编译 Chromium 打补丁（对手路线） | 高 | 慢（月级） | 编译链 + 100G + 每轮 6~10h | ⏸ 留作 P5 |

为什么 B 比 A 好：页面跑在**真 Chrome 构建**里，UA/UA-CH、引擎特性、渲染路径天然一致，
只需对少数维度做注入，而不是在一个非 Chrome 环境里到处补洞。
CfT 是 Google 官方构建，`Browser.getVersion` 与 JS 特性探测能对上同一个版本号。

## 2. 与对手的能力边界（核心：CDP 注入做不干净的地方）

对手的指纹逻辑在 `chrome.dll` 内部（Blink 层），我们是 CDP 注入（JS 层 + 少量启动参数）。
差别不是「能不能做到」，而是**留下的证据在不在可检测面上**。逐条摊开：

### 2.1 CDP 能做得干净的（和内核级几乎没差）

| 维度 | 手段 | 备注 |
|---|---|---|
| UA + UA-CH | `Emulation.setUserAgentOverride`（带 `userAgentMetadata`） | brands / fullVersion / platformVersion / architecture / bitness 一起改，不会只改一半 |
| 时区 | `Emulation.setTimezoneOverride` | Intl、Date 一起走 |
| 语言 | `Emulation.setLocaleOverride` + `--lang` | |
| 经纬度 | `Emulation.setGeolocationOverride` | 与代理 IP 地理对齐 |
| 屏幕 / DPR / 触屏 | `Emulation.setDeviceMetricsOverride` | screen.*、devicePixelRatio、innerWidth 一起 |
| WebRTC 泄漏 | 启动参数 `--force-webrtc-ip-handling-policy=disable_non_proxied_udp` 等 | **参数级，浏览器真实行为**，不是 JS 假造 |
| 内核版本矩阵 | 按 major 下载 CfT 118→最新，环境 pin 内核 | 直接对齐对手的「20 套内核」故事，且不用编译 |

### 2.2 CDP 做不干净、必须承认的（可检测性关键）

1. **字体（最硬的墙）**。真实字体列表来自系统 + DirectWrite 渲染。JS 只能改「读出来的列表」和
   `measureText` 结果，改不了真实字形栅格化。检测方用 canvas 量几十个字符串的
   `actualBoundingBoxAscent`/`width` + `document.fonts.check()` 交叉验证，我们的伪造表必须和度量数据
   自洽 —— 要做得像 macOS 字体栈，等于手工建一套几十种字体的字宽度量表。**MVP 不做完整字体伪装。**
2. **Canvas / WebGL 的真实像素**。JS 层 noise 只改返回值，底层 rasterizer 和 GPU 输出不变。
   漏点：`getImageData`/`toDataURL` 之外的 `OffscreenCanvas.convertToBlob`、`drawImage` 往返、
   `WebGL.readPixels`、`WebGPU`、每次 Chrome 大版本新增的画布 API。**JS patch 是枚举式补漏，永远漏一个。**
3. **WebGL 驱动行为一致性**。改掉 `UNMASKED_VENDOR/RENDERER` 很容易，但
   `getSupportedExtensions`、`getShaderPrecisionFormat`、最大纹理尺寸、实际渲染输出、GPU 计时特征
   仍然来自真实驱动。「报 NVIDIA 但行为像 SwiftShader」是最经典的高危组合。
4. **Worker / AudioWorklet / ServiceWorker 注入**。`Page.addScriptToEvaluateOnNewDocument` 覆盖主帧和
   iframe 很稳，但 worker 类 realm 需要 `Target.setAutoAttach` + 启动即注入，AudioWorklet 更麻烦。
   检测方在 worker 里再取一遍原生函数做比对（双 Realm 检测），就会看到两套实现。
5. **性能与痕迹**。patch 过的 getter 更慢（`performance.now()` 打点可测），
   `Function.prototype.toString` 能伪装成 native，但属性描述符形状、错误栈帧、Proxy 痕迹仍在。
   内核级是 C++ 里一行返回值，JS 级是一次函数调用。
6. **自动化痕迹**。`navigator.webdriver`、`--enable-automation`、`DevToolsActivePort`、CDP 端口
   这些必须逐条处理（关掉 enable-automation、不导 webdriver、端口随机 + 只绑 127.0.0.1）。

### 2.3 结论：MVP 的定位

**MVP = 「多环境隔离 + 代理 + 指纹一致 + 本地 API」可用，而不是「过顶级检测站」。**
对标：电商/社媒多账号运营（同机多开、cookie 隔离、IP 归属一致、UA 与屏幕不打架）—— CDP 路线完全够。
过 Pixelscan / creepjs 深度项需要内核，那是 P5，不是第一版承诺。
**对外话术必须先说清楚这一点，别让用户以为第一天就能过所有检测。**

## 3. 架构

```
freepower/
  apps/desktop        Electron 主进程 + 渲染层 UI（管理界面）
  apps/kernel         CfT 内核矩阵：下载/校验/pin 版本/启动/进程树回收
  packages/cdp        CDP 客户端 + 注入脚本（所有 patch 集中在此，单一事实源）
  packages/profile    profile 模型、存储、指纹生成器、一致性校验器
  packages/proxy      代理模型、认证（HTTP/SOCKS5）、出口探测、地理推导
  packages/api        本地 HTTP API（127.0.0.1 + 自带 API Key，离线可验）
```

存储：SQLite（better-sqlite3），单文件 `freepower.db`。启动参数、内核版本、指纹种子全部进库。

### 3.1 与 AdsPower Local API 的兼容策略（协议面对齐，代码自己写）

对手 51 条路由、`/api/v2/*` 为主、默认限流 1/s、`x-adspower-client: mcp` 提到 30/s、
API Key 走**远端**校验（离线不可用）、CORS 白名单 + Origin 403。

我们的做法：

- 路由形状对齐 `/api/v2/browser-profile/*`、`/api/v2/proxy-list/*`、`/api/v2/browser-tags/*`、
  `/api/v2/category/list`，字段用 `profile_id` / `profile_no` —— 让基于 AdsPower 写的脚本能低成本迁移。
- **API Key 本地校验**（这是差异点：对手离线不可用，我们离线可用）。
- 限流同档位（默认 1/s，特定 client 头上调），但配成可调。
- 端口不硬编 50325（避免和用户装的 AdsPower 冲突），首次启动随机端口 + 写 `local_api` 文件供发现。

## 4. MVP 范围（第一版必须能跑起来）

做：
1. 环境 CRUD（新建/编辑/复制/删除/分组/标签），`profile_id` + 指纹种子持久化。
2. 启动/关闭：独立 `--user-data-dir`、独立进程、随机 CDP 端口、进程树彻底回收、崩溃后清理孤儿。
3. 指纹注入 v1（保守但不打架）：UA + UA-CH、语言、时区、经纬度、屏幕/DPR、
   WebGL vendor/renderer（自洽：renderer 与 UA 平台、屏幕尺寸不矛盾）、Canvas 确定性噪声（种子化）、
   Audio noise、hardwareConcurrency、deviceMemory、platform、WebRTC 策略。**字体只做最小处理并明确标注风险。**
4. 代理：HTTP/HTTPS/SOCKS5 + 账号密码认证、启动前出口探测、**fail-closed（代理挂了拒绝启动，绝不直连）**、
   地理 → 时区/语言/经纬度自动对齐。
5. 本地 API：v2 形状的子集（start/stop/list/create/update/delete/new-fingerprint/status/cookies/ua）。
6. 内置自检页：把配置值与页面实际取值逐项对照，一键出差异表；同时跑 creepjs 存基线。

不做（明确砍）：自编译内核、完整字体伪装、WebGPU、AudioWorklet 深度一致、团队同步/云、RPA 市场、
批量导出 cookie 到外部格式（先做 API 拿 cookies，不做格式化导出）。

## 5. 阶段拆分

| 阶段 | 交付 | 能跑出什么 | 验收 |
|---|---|---|---|
| P0 骨架 | pnpm workspace、Electron 空壳、SQLite schema、API 空壳、`/status` | 启动出界面，`/status` 返回 `{"code":0,"msg":"success"}` | `pnpm dev` 起得来 |
| P1 环境与内核 | profile 模型 + CRUD、CfT 下载与版本矩阵、启动/回收、user-data-dir 隔离 | 新建环境 → 点启动 → 弹出真 Chrome → 关闭进程干净 | 并发 3 环境，cookie 互不可见 |
| P2 指纹 v1 + 自检 | `packages/cdp` 全套注入 + 一致性校验器 + 自检页 | 自检页逐项对照全绿（字体项明确标黄） | creepjs 与基线对比出差异表 |
| P3 代理与地理 | 认证代理、出口探测、地理推导、fail-closed | 绑代理启动，自检页显示代理出口 IP，时区语言随之切 | WebRTC 不泄漏真实 IP |
| P4 API + 批量 | v2 形状 REST、API Key、批量启停、导入导出 | 脚本 curl 批量起 10 个 | 压测 + 错误码对齐 |

## 6. 风险点（按「会翻车概率 × 影响」排）

1. **单点造假、成组不一致。** UA 说 Windows、WebGL 报 SwiftShader、deviceMemory=8 但
   hardwareConcurrency=2、时区 UTC 但语言 en-US —— 一条对不上整组作废。
   → 一致性校验器做成核心模块，启动前跑规则集，不通过就不让启动（或显式告警）。
2. **字体与 canvas 度量对不上。** 这是 CDP 路线的结构性弱点（见 2.2-1）。MVP 不硬刚，
   改为「不伪装系统字体，只保证声明的字体族确实存在」，把风险写进产品文案。
3. **Canvas 噪声不确定。** 同环境每次启动必须同值（种子入 profile），否则用户会被判「换设备」。
   覆盖 `toDataURL`/`toBlob`/`getImageData`/`OffscreenCanvas`，漏一个就穿。
4. **Worker / iframe 二次取证。** 注入必须覆盖每个 frame；worker 覆盖不到要明确知道（不假装覆盖了）。
5. **内核版本漂移。** UA 版本必须等于内核真实版本；升级核 → 指纹模板跟着升。模板配置化，不硬编码。
6. **主程序与页面同进程 = 必死。** 页面必须独立进程（这条也是选 CfT 而不是 Electron 当浏览器的原因）。
7. **代理回退直连 = 灾难。** fail-closed。
8. **WebRTC 漏一个 STUN 就暴露内网 IP。** 参数级禁用 + 自检页显式验证。
9. **本地 API 是后门。** 只绑 127.0.0.1、强制 Key、校验 Origin，端口不硬编避免和 AdsPower 抢 50325。
