# 24 · 分阶段路线图（0.4.6 起）

- 用户 2026-11-15 拍板：**先修假字段，再补功能，按轻重缓急分步逐一补齐。**
- 依据：`22-全量对比-AdsPower有而我们没有.md`（A 类 66 假字段 / B 类约 40 缺项 / D 类 112 项不做）。
- 本文是执行计划，每阶段都写清「做什么 / 为什么排这里 / 怎么算做完」。阶段之间可以调序，但**不许跳过验收**。

## 排期原则

1. **先修「界面在说谎」，再补「功能不够」**。假字段让用户配了以为生效，这比缺功能更坏。
2. **不可逆操作优先于效率工具**。合错了 Cookie、删掉了数据、清空了环境，这三类无法靠"再做一次"弥补。
3. **每个阶段必须带判据**，不接受"做完了"当验收。判据要么是先红后绿，要么是真内核实测读数。
4. **每个阶段出包、用户装、用户验**。不攒大版本，但也不为一件小事出一版。

## 阶段 0 · 假字段清理（0.4.6，进行中）

**做什么**

- 新增静态不变式判据：138 字段 × 可见性三分桶 × 消费路径，**可见可配但无消费者 → 红**。
- 48 个可见可配字段：能接的接（必须有证据），接不了的禁用并在控件旁写明原因。
- 14 个 `CLOUD_ONLY`：原因从 tooltip 挪到页面上可见。
- 4 个 API 可写不可见：`ip_city`/`ip_region`/`ip_country` 接成只读展示，`ext_obj` 评估。

**为什么排第一**：这是用户「每次等我在使用中发现问题」的根因。不修，后面补多少功能都会被意外撞到。

**怎么算做完**

- 不变式判据在旧 HEAD 上先红并打印 48 个字段名；修完后绿。
- 判据不允许用通配白名单换绿；要豁免必须逐条列名 + 理由。
- 抽查：随便删掉一个已接字段的消费路径 → 判据必须红并点名它。

**风险**：禁用控件会让用户看到"我原来能填的格子变灰了"。升级说明必须单独列一节「哪些开关变灰了、为什么」，不能让用户以为是坏了。

## 阶段 1 · 不可逆与丢数据兜底（0.4.7）

**做什么**

| 项 | 为什么在这里 |
|---|---|
| 合并 Cookie 可撤销 | 合并是破坏性操作，合错目前无法退回 |
| 本地备份快照 5 个 + 从备份恢复 | 丢数据的最后一道防线，比任何功能都值钱 |
| 关闭环境时自动备份（可关） | 同上，但必须默认关——不能替用户决定占磁盘 |
| 按天数删缓存（删 N 天未开环境的缓存） | 环境多了 `data\profiles` 是磁盘黑洞，且清缓存也不可逆 |

**为什么排第二**：这四项都是「做错了没法重来」。效率工具晚一版没关系，数据没了没法补。

**怎么算做完**

- Cookie 撤销：合并 → 撤销 → 逐条比对回到合并前（**不是"看起来回去了"**，要比 cookie 值本身）。
- 备份：造 5 个快照后造第 6 个，验证最旧的被挤掉；从快照恢复后环境能**真启动**（B 层真内核）。
- 按天数删缓存：删之前列出将删哪些、删之后验证只删了那些；**未开环境的天数判定要有真时间戳证据**，不能靠 `mtime` 猜。

## 阶段 2 · 高频操作效率（0.4.8）

**做什么**

| 项 | 说明 |
|---|---|
| 代理 `.xlsx` 批量更新（≤1000，按代理 ID 匹配） | 换代理是高频，手填 1000 条不现实 |
| 代理校验重复项 | 粘贴导入必然重复 |
| 代理随机方式：随机全部 / 优先未使用 | 对手有，且影响批量建环境 |
| 代理导出 + 关联环境数 | 改之前得知道谁在用 |
| 批量改启动参数 / 批量改指纹项 / 批量改应用 | 对手 11 项批量里我们缺的三项 |
| 批量改标签页 / 书签批量改 | 同上 |
| 多条件筛选器组合 | 我们现在只有单条件，环境一多就找不着 |

**为什么排第三**：这些不改会天天难受，但都不至于造成损失。

**怎么算做完**

- xlsx 解析要有真实文件测试（含空行、缺列、代理 ID 不存在、超 1000 条四种边界），且**部分失败要逐条报**，不能整批回滚或整批静默成功。
- 重复校验要能说清「和哪一条重复」，不是只回一句"有重复"。
- 筛选器组合要有真 HTTP 判据，证明多条件是真 AND，不是只有第一个生效。

## 阶段 3 · 功能补齐（0.4.9）

**做什么**

| 项 | 说明 |
|---|---|
| Chrome 商店 URL 装扩展 | 用户第一反应就是贴商店链接；需网络，失败要分类提示 |
| AI Agent 定时任务（日/周/月/一次 + 执行记录） | 自动化真正省时间的入口 |
| 同步：主控窗口颜色 | 多窗口时辨识主控 |
| 同步：子窗口用标签页打开（Chrome 127+） | 对手有 |
| 环境占用 / 多开模式提示 | 同环境被占用时的提示 |
| 关闭操作台开关项 | 对手有独立开关，我们只有 × |

**为什么排第四**：都是"有了更好"，没有也能用。

**怎么算做完**

- 商店 URL：网络不通 / 扩展不存在 / 已下架 / 非商店域名，四类分别有明确提示，不许都报"失败"。
- 定时任务：到点真触发（用短周期实测，比如 1 分钟后），执行记录能查到；**错过的时间点怎么补**要写清（我们的选择，不是对手行为）。

## 阶段 4 · 收尾与低优先（0.5.0）

**做什么**

- 每环境自定义图标 6 种（默认 / 环境ID后4位 / 编号后4位 / 名称前3 / 备注前3 / 不显示）
- 列锁定、自定义序号、序号批量生成（递增/递减/固定/随机）
- 标签批量追加超 30 截断、代理标签截断
- Cookie/密码的文件级导入导出（换机迁移）
- 按域名关 canvas 噪声（`DisCanvasUrl`）
- 移动档触摸点数、Passkey
- `win_x`/`win_y` 窗口位置（改行为，等用户真提）

**为什么排最后**：纯体验细节，或需要用户明确需求才做。

## 不做（不在任何阶段）

按用户已拍板或本机做不到，共 112 项，见 `22-` §4：

- 要云/需账号：费用中心与计费、团队管理与权限、环境与分组分享、动态代理生态、云端缓存同步、登录注册账号体系、AI 点数计费。
- 明确超范围：RPA / RPA Plus、云手机 / 云号码。
- 需自编译内核：字体白名单等 12 项。
