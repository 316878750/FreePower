分段是有语义的：第一段只改配置（可逆、不改变列表归属），第二段改变列表归属，第三段动运行时或登录态。

**九条路由是我们自己加的**（对手是云端 webui 内部接口，没有可抄的本地 REST），
所以形状自己定，但四条纪律写死：

1. **归档 ≠ 删除**：归档只写 `archived_at`，不碰 `deleted_at`、不碰 user-data；
2. **参数缺失就报错**：`profile_ids` 一个都没有 → `100002` 且 `data.field='profile_ids'`，
   绝不把「字段名拼错」当成「一条都没选」然后回 `code=0`（0.4.3 ① 已经在 `app/profile/set` 栽过一次）；
3. **一条失败不中断整批**：逐条结果分开报，`failed` / `skipped` 里点名到 `profile_id`；
4. **超时要说具体秒数**，不许只说「超时」。

## 三、归档 ≠ 删除（和回收站彻底分开）

这是本块最容易做混的地方，所以两套语义**在数据层就分开**：

| | 归档 | 回收站（软删除） |
|---|---|---|
| 写入字段 | `archived_at` | `deleted_at` |
| user-data 目录 | 原样不动 | 原样不动 |
| 能启动 | **能** | 不能（列表里看不到） |
| 能编辑 | **能** | 不能 |
| 主列表默认可见 | 否（要选「只看已归档」） | 否 |
| 恢复方式 | `batch/unarchive` | `recycle-bin/restore`（必须选分组） |
| 彻底删 | 不能（先删进回收站，再 purge） | `recycle-bin/purge` |

**`/recycle-bin/*` 一次都没复用**，判据里有一条静态断言钉住（批量路由里不许出现 `recycle` 字样）。

三条边界：

- **回收站里的不能被归档** → `skipped: in_recycle_bin`。把两套语义混在一起，
  用户会看到一条「既归档又在回收站」的环境，谁也不知道该从哪恢复。
- **重复归档** → `already_archived`；**恢复没归档的** → `not_archived`。都不是错误，但必须点名。
- **归档 → 删除 → 恢复后 `archived_at` 必须清空**：否则环境会「隐身」在主列表外，
  用户点了恢复却在列表里找不到（`repo.deleteProfile` 顺带把 `archived_at` 置 NULL）。

`listProfiles` 加了 `archived` 参数：`exclude`（默认，主列表）/ `only`（只看已归档）/ `include`（全部）。

## 四、检查代理：并发 + 三态 + 具体秒数

三条硬要求，逐条落到实现：

- **一条失败不中断整批**：`checkMany` 是固定 N 个 worker 抢队头，不是分批 `sleep`；
- **成功 / 失败 / 超时分开**：`outcome` 是 `ok|fail|timeout|direct` 四态；
- **不许把失败显示成成功**：`ok` 只在探测真的拿到出口 IP 时为 true。

**直连环境不算通过**：`outcome:'direct'` + `ok:false` + `error_label:'这个环境没绑代理（直连），没有代理可查'`。
检查的是「代理」，直连没有代理可查 —— 给它编一个「检查通过」才是骗人。

超时三处都带秒数：`timeout_ms`、`timeout_seconds`、`elapsed_ms`。

并发与超时都可传，且**夹在安全区间**：`concurrency` ∈ [1,10]，`timeout_ms` ∈ [1000,60000]。

用的是与启动前同一套探测（`src/proxy/health.js`，零依赖、fail-closed），所以结果与「启动时会不会被拦」可比。

## 五、改 UA / 内核：身份必须自洽

UA 里的 `Chrome/<大版本>` 必须等于内核大版本，否则造出一个自相矛盾的指纹。所以：

- 只给 `kernel_version` → UA 按这个内核重写；
- 只给 `ua` → **从本机已装内核里挑同大版本的那一个**（见第十节缺陷 2）；
- 两个都给但对不上 → `100002 field=ua`，**不静默改其中一个**。

内核版本必须是本机装了的（`listKernels({type:'chrome'})`），否则报「本机没有安装内核 X」。

## 六、改备注 / 更新环境信息 / 改代理

**改备注四档**：`replace`（默认）/ `append` / `prefix` / `suffix`，分隔符默认一个空格。
为什么给四档：覆盖会**删掉用户原来写的东西**，所以 mode 显式，界面必须提示会覆盖。

**更新环境信息白名单**：`name / remark / group_id / domain_name / open_urls / username / password /
fakey / platform_account / profile_tag_ids`。非白名单字段进 `ignored_fields` 原样回报（不静默吞掉）。
白名单收窄是故意的：批量入口一个手滑就把一批环境的指纹改掉，代价太大；UA/内核有专门的路由，
**指纹种子根本不给批量改的口子**。

> **口径声明（重要）：这条的语义是我们自己的解释，不是抄来的。**
> 逆向 `28-` 号文里，对手在批量清单里只留下一个名字 `updateUserInfo` ——
> **没有字段清单，也没有行为证据**（既不知道它改哪些字段，也不知道是覆盖还是追加）。
> 所以「哪 10 个字段、整条覆盖、白名单 + `ignored_fields`」全是 FreePower 的定义。
> 界面因此把这 10 个字段**全列出来**（勾了才发、空着不改）：不能让人「勾完不知道改了啥」，
> 也不能让人以为没列出来的字段也能在这里改。
> 以后写文档或对外的对照表时，**别把它列进「对齐对手」那一栏**。

界面的字段表（10 行，每行「改不改 / 新值 / 接口字段名」）：

| 界面字段 | 接口字段 | 类型 |
|---|---|---|
| 环境名称 | `name` | 文本（可清空） |
| 备注 | `remark` | 文本（可清空） |
| 分组 | `group_id` | 下拉 |
| 域名 | `domain_name` | 文本 |
| 启动时打开的网址 | `open_urls` | 多行，每行一个 |
| 内置账号 | `username` | 文本 |
| 内置密码 | `password` | 密码框 |
| 2FA 密钥 | `fakey` | 文本 |
| 平台账号 | `platform_account` | 多行 JSON |
| 标签 id | `profile_tag_ids` | 逗号分隔 |

勾了但没填值 → 直接拦下并点名（不会发出一个「改了但值没变」的请求）；
要提交时先弹确认，把「会改哪几个字段」列出来。

**改代理三种写法**：`proxy_config`（写死一条）/ `proxy_id`（绑代理列表里的）/ `clear:true`（改成直连）。
走 `updateProfile` 同一条路径，所以 PAC 拒绝、字段校验、`user_proxy_config` 形状全部一致。
写死一条时会回 `shared_egress:true` —— 界面必须提醒「这些环境会共用同一个出口 IP」。
在跑的环境回 `restart_required:true`（代理是启动参数，改完必须重启才生效，**不偷偷重启**）。

## 七、还原 vs 合并 Cookie（最容易做错的地方）

两种语义**必须分开**：

| | 还原 `restore` | 合并 `merge` |
|---|---|---|
| 语义 | **覆盖**：写完以文件为准 | **并集**：只补文件里有、环境里没有的 |
| 文件里没有、环境里有的 | **删掉** | 保留（`will_keep`） |
| 同名但值不同 | 用文件的 | **以环境现有为准**，不动登录态 |

两个都支持 `preview`，**默认 true**（只算不写），回「会加几条 / 改几条 / 删几条 / 留几条 / 无效几条」。
界面必须先调 preview、把数字摆给用户看、用户点确认之后才 `preview:false` 真写。
**不许一键静默改掉用户登录态。**

三条实现细节：

1. **预览里不带 cookie 的 value** —— 那是登录凭据，不该出现在界面上，更不该进日志。
   `planCookieWrite` 返回的 `sample` 按 `add / update / delete` 三组分开，每类最多 20 条，
   每条只有 `name / domain / path`（`update` 额外带 `value_changed: true/false`，也是布尔不是值）。
2. **先删再写**：`applyCookiePlan` 先发 `Network.deleteCookies` 再 `Network.setCookie`，
   顺序反了在 restore 模式下会把刚写的又删掉。
3. **写后回读**：`verified` 是「写完能读回来的条数」，不是「发出去的条数」；
   读不回来的进 `warnings` 并点名，不假装全成。restore 模式下还额外检查「应当被覆盖删掉的是否还在」。

**依赖**：cookie 在内核里，所以环境必须在跑（与 `/cookie/import` 同一条口径，
**不为了改 cookie 偷偷起内核**）。没跑的那条进 `skipped: not_running`，不影响其它条。

## 八、显示窗口（批量版）

对**任意勾选的环境**用，不要求开同步会话 —— 直接对每个环境的浏览器级 CDP 做。
判定**复用** `src/sync/show.js` 的 `planShow` / `verifyShown` / `summarizeShow` / `planForce` /
`verifyForced` / `summarizeForce`，只新写两个读取器（`pageTargetOf` / `rectOf`），
所以面板文案与同步面板保持同一口径：

- `restored` = 真到 OS 前台（最小化的那批走 restore）；
- `page_only` = 只做了页面级激活，**不许说成「已置前」**，面板明说「可能仍被其它窗口盖住」；
- `force:true` = 一次性显式动作（minimize→restore，会闪任务栏、每窗约 1 秒），
  **不写设置、不做开关、默认 false**；
- 没在跑的环境进 `skipped: not_running`，不偷偷起内核。

## 九、视图密度

三档：紧凑 / 标准 / 超高，行高 **30 / 44 / 64 px**。

**这三个数字是我们选的**：28- 号文只给了三个名字（`fbcc2` / `standard` / `broad`），没给行高数字。
所以 README 与界面都不许把它写成「对手原值」或「系统下限」。

**只写 localStorage**（一个键 `fp.view_density`），不写库、不同步到别的机器。
理由：这是「这台机器上这个用户看着舒服」的显示偏好，不是环境数据；写进库就意味着一份配置跟着库走
（换机器 / 恢复备份时被别人的习惯覆盖），还会因为「两个窗口不同密度」打架。

认不出的脏值一律回「标准」—— 不因为 localStorage 里存了个坏值把列表画坏。

## 十、抓出并修掉的两个真缺陷

### 1. `proxy_config: null` 被吞（报告与行为相反）

「批量改成直连」回 `code=0`，但环境的 host/port 原样留着：

```
改之前 {"host":"127.0.0.1","port":58467,"proxy_id":"px_7547b730c2f89983"}
发 {clear:true} → code=0
读回   {"host":"127.0.0.1","port":58467,"proxy_id":"px_7547b730c2f89983"}   ← 一个字节没变
```

根因：`updateProfile` 里 `null` 被当成「这个字段没给」合并掉了。
修法两处：store 层 `proxy_config === null` 走**显式清空**分支；repo 层加
`NULLABLE_COLS = ['user_proxy_config','proxy_id','cookie','archived_at']`，`updateProfile` 里显式 null 照写。

判据：`batch/proxy` 的 `clear:true` 之后读回 `proxy_config === null` 且 `proxy_id === null`。

### 2. 只给 UA 时内核版本取错

老写法拿 UA 里的 `157.0.0.0` 当内核版本 → 报「本机没有安装内核 157.0.0.0」。
真实内核是 `157.0.8103.78`，UA 那四段的后三段本来就是打码值（`.0.0.0`），拿去当内核版本必然匹配不上。

修法：从**已装内核**里挑同大版本的那一个（同大版本有多个取最高），一个都没有才报错。

## 十二、已知限制

1. **密度三档的行高是我们选的**（30/44/64），28- 号文只给了名字。
2. **归档不进回收站、也不会自动清理**：归档只改变「在主列表里看不看得见」，
   磁盘一个字节都不动；要腾磁盘得先删除进回收站，再「彻底删除」。
3. **批量 Cookie 要求环境在跑**：cookie 在内核里，不为改 cookie 偷偷起内核；没跑的进 `skipped`。
4. **还原模式下「应当删掉却还在」只告警不重试**：内核按策略丢弃某些 cookie（比如被标记为
   partitioned 的第三方 cookie）时，删了也可能被写回来。我们如实进 `warnings` 并点名，不循环重试。
5. **批量改代理写死一条 = 这些环境共用同一个出口 IP**：响应里有 `shared_egress`，
   界面必须提醒；这是平台最容易识别的信号之一，不该默默发生。
6. **改 UA / 内核、改代理、勾选扩展都要重启环境才生效**：响应回 `restart_required`，不偷偷重启。
7. **一次最多 500 个环境**：超过报 `100002`。批量动作是同步执行的 HTTP 请求，
   上千个环境会撞上请求超时，分两批比等一个超时好。
8. **「更新环境信息」的字段与语义没有对手证据**（见第六节那段口径声明）：
   名字来自 `28-` 号文，内容是我们定的。别拿它当「对齐对手」的证据。
   白名单之外的字段（指纹、UA、代理、扩展）**永远不从批量入口改**。
