## 二、三条硬要求怎么落的

### 1. 网络诊断只读

「只读」写在三个地方，不是只写在文档里：

- **代码里没有任何写操作**：`src/api/diagnose.js` 只 `stat`、只读内存里的表、只调纯探测
  （`checkProxy`）。判据把注释剥掉后扫 `setMeta(` / `updateProfile(` / `startProfile(` /
  `stopProfile(` / `writeFileSync` / `rmSync` / `rememberProxyCheck(` —— **一个都不许出现**。
- **行为验**：连读两次快照，环境 / 代理 / 设置逐字节比对**完全不变**。
- **探测不落盘**：`/api/v2/diagnose/proxy` 与代理管理页那条**不是同一条路**。
  后者会 `rememberProxyCheck` 写 `last_ip` / `checked_at`，前者响应里明写
  `readonly: true` + `persisted: false`，判据比对探测前后 `checked_at` 没变。

还有一条容易忘的：**不为了出一份报告去起内核**。快照里 `kernels.running` 只报「现在在跑的」，
没跑就是空数组 —— 判据断言「没有 CDP 端口条目」。诊断页也不会因为想看内核就帮用户启动环境。

### 2. 设置页的项都要真生效

这一页只摆**真的有行为在用**的偏好：

| 项 | 存哪 | 谁在用 | 怎么验 |
|---|---|---|---|
| 窗口同步默认设置（14 个开关/数值） | 库 `meta.sync_defaults` | `/api/v2/sync/start` 读它；`/sync/status` 没在跑时显示它 | `mergeSyncSettings()` 直接验合并结果 + 静态断言 start 路由用的是它 |
| 全局快捷键 | 交接文件（桌面壳注册） | 桌面壳轮询重新注册 | 已有能力，页面只接上（`managed:false` = 没桌面壳，如实说） |
| 外观（视图密度） | localStorage `fp.view_density` | 列表页工具条 + 本页，同一个键 | 静态断言「没自己写新的 localStorage 键」 |
| 本地 API 摘要 | 只读显示 | —— | 只给「去 API & MCP 页」的链接，不重复摆开关 |

**顺手修掉一处「说了但没做」**：同步页在「没在跑」时改开关，原来弹的是
「已记住，开始同步后生效」，实际**什么都没存** —— 刷新页面就丢，那句提示等于骗人。
现在它调 `POST /api/v2/settings/sync-defaults` 真存进库，提示改成「已存为默认设置，开始同步时生效」，
设置页看得见同一份。

存坏的 JSON **不静默**：`readSyncDefaults()` 回 `broken: true`，设置页明确提示
「库里的同步默认设置存坏了，已回内置默认（保存一次就会覆盖掉坏数据）」。

### 3. 外观沿用 ③ 的密度口径

不新造存储：同一个 `fp.view_density`、同一套三档（紧凑 30 / 标准 44 / 超高 64 px，行高是我们选的）。
两个入口（列表页工具条的下拉、侧栏菜单的「外观」）**必须互相同步**，否则会出现
「菜单里选了紧凑、下拉框还显示标准」。

做法是一条自定义事件 `fp:density`：`setDensity()` 写完广播，谁在显示这个值谁自己更新。
不在两边互相 `import`（会绕成环），也不在 `app.js` 里重算一遍。

## 三、五条路由

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v2/settings` | 读设置（同步默认 + `saved` / `broken` / `diff`） |
| POST | `/api/v2/settings/sync-defaults` | 改同步默认（**合并**语义），不认识的字段进 `ignored` |
| POST | `/api/v2/settings/sync-defaults/reset` | 恢复内置默认 |
| GET | `/api/v2/diagnose/network` | 网络 / 内核 / 端口快照（**只读**） |
| POST | `/api/v2/diagnose/proxy` | 探测环境绑定的代理（**只读、不落盘**） |

`DEFAULT_SETTINGS` / `normalizeSettings` 从 `src/sync/session.js` **下移到 `src/sync/settings.js`**，
`session.js` 原样再导出。理由：`src/settings/prefs.js` 要读默认值，而
`prefs.js → session.js` 会把整个运行时（CDP 客户端、内核管理器）拖进来，`session.js` 又要用 prefs
—— 一个循环。判据断言 `sessionMod.DEFAULT_SETTINGS === settingsMod.DEFAULT_SETTINGS`
（同一个对象，不是两份长得一样的常量）。

## 四、诊断页报什么

- **服务**：版本（`package.json`）、地址、pid、启动时刻、运行时长、Node 与平台、内存、
  数据目录、数据库字节数 + **WAL 字节数**（只拷 `freepower.db` 等于没备份，这句在页面上也写了）、
  API 验证开关与请求计数（总/放行/拒绝/限流）。
- **监听端口**：本地 API + 各运行中环境的 CDP 端口。**不扫全机端口** —— 那不是本产品的职责，
  也不该去探别人的端口。
- **内核**：已装几个（版本 + 来源）、运行中几个（pid / CDP 端口 / 真实版本 / 出口 IP / 启动时刻）。
- **代理**：绑了代理的环境数、去重后条数（按 `host:port:账号` 去重，因为同一批环境常共用一条）。
  **账号打码**（只留首字母），**密码连字段名都不出现** —— 诊断页会被截图发给别人。

探测结果分 `ok` / `fail` / `timeout` 三态，超时带具体秒数；一条失败不中断其它条；
按 host:port:账号 去重，所以「两个环境共用一条代理」只探一次、结果回填到两个环境上。

## 五、判据（56 条，A 层，不起内核）

```
node --no-warnings test/settings-diagnose.test.mjs → 56 PASS / 0 FAIL
```

七段：

1. **设置**：初始 `saved:false`、16 个键齐全；改一项真的改、其余保持（合并语义）；
   不认识的字段进 `ignored`；越界夹回区间（`delay_ms:999999 → 5000`、`jitter_ms:-5 → 0`）；
   打字间隔上下界反了自动换过来。
2. **真生效**：`mergeSyncSettings()` 就是存的那份；请求里显式给了覆盖在上面；
   `/sync/status` 没在跑时显示的是**存的那份**（不是写死的常量）；静态断言 start 路由用的是
   `mergeSyncSettings`，且没有回退成老写法。
3. **存坏了**：写坏 JSON → `saved:false` + `broken:true` + 回内置默认；reset 之后两处一起回默认。
4. **快照**：`readonly:true`、端口是这次请求实际落到的那个、pid 是本进程、版本来自 `package.json`、
   库文件字节数 > 0、监听端口里有本地 API 那条、没跑环境时**没有 CDP 端口条目**；
   两个环境共用一条代理 → 去重 2 条 / 绑了 3 个环境；快照里没有代理密码、账号打码；
   **连读两次逐字节不变**。
5. **代理探测**：`readonly` + `persisted:false`；活代理 `198.51.100.7` / Germany / 延迟；
   共用一条代理的两个环境都列在同一条结果上；黑洞代理 `timeout` + `timeout_seconds:1.2`；
   汇总三态分开；**探测前后代理的 `checked_at` 没变**；只挑直连环境 → `total:0` + 一句说明（不是报错）。
6. **静态**：`diagnose.js` 剥掉注释后零写操作、明写只读；设置存库不存 localStorage；
   侧栏底部有挂载点；菜单三项都在；外观走 `DENSITIES` + `setDensity`；`app.js` 没有自己写新的
   localStorage 键；两条路由注册了；菜单项用 `account-item`（不参与侧栏折叠计数）；
   设置页真的调 `saveSyncDefaults` / `resetSyncDefaults`；「没做 / 在别处」五项逐条在；
   诊断页没有任何写接口调用；同步页「没在跑」时会真存。
7. **纯函数与契约**：`session.js` 仍导出**同一个** `DEFAULT_SETTINGS` / `normalizeSettings`；
   空入参给全套 16 键；`diffSettings` 只报不同的键；密度读不到存储时回标准。

**第一版这条判据红了两条，是判据自己写错了**：`diagnose.js` 与 `prefs.js` 的头注释里
**明确写着**「不许 `rmSync`」「不是 localStorage」，全文 grep 把自家的告诫当成违规。
改成剥掉注释再扫（只去注释、不动字符串），两条转绿 —— 这不是放宽，是把「扫代码」做对。

## 六、已知限制

1. **没有主题切换**：只有一套浅色配色。深色主题要重做整套 CSS 变量并逐页核对对比度，
   这一版没做（设置页的「没做」表里写着）。
2. **没有界面多语言**：文案直接写在代码里、只有中文。
3. **没有自动更新**：升级方式是装新版本安装包（升级说明里写了怎么退回去）。
4. **诊断不扫全机端口、不查系统代理设置**：只报本产品自己的监听端口。
   系统代理是环境启动时会读的东西（`systemProxy` 那条只给测试用），诊断页不去动它。
5. **代理探测只探「绑在环境上的」**：代理列表里没绑到任何环境的代理不在诊断范围里
   （要检查那些去代理管理页，那边会记最近结果）。
6. **设置里没有「恢复全部默认」的总按钮**：只有同步默认那一组有 reset。
   现在总共就一组，等有第二组再谈总开关，免得先做一个管不到东西的按钮。
